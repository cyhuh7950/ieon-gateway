## 1. 사람과 역할

- **관리자:** 지금의 관리자(허브 비밀번호, `u_sinsan`). 허브 설정·보안·봇·메신저·엔진 칸·계정·가입 승인은 관리자만.
- **사용자:** 가입 신청 → 관리자 승인. 이메일·비밀번호로 로그인. 상태 `pending`(승인 대기)·`approved`·`rejected`·`disabled`. 승인된 사용자만 기능을 쓴다.
- 설정 `multiUser.enabled`(관리자 화면 "여러 사람 쓰기")가 꺼져 있으면 가입 신청을 받지 않는다(이미 승인된 사용자는 그대로 로그인).
- 허브에 접속 제한(IP 목록)이 켜져 있으면 다른 사람은 허브에 닿지 못한다 — 여러 사람을 받으려면 관리자가 허브 보안에서 열어야 함(관리자 비밀번호·사용자 로그인은 그대로 필요). 가입·로그인 화면은 접속 제한을 거치지 않게 하지 않는다(관리자 결정에 맡김).

## 2. 사람별 분리

| 것 | 분리 방법 |
| --- | --- |
| 대화·요청·방·예약·승인·작업·메시지·앱 기기·웹 알림 | 이미 주인(사용자) 기준(`canAccess`·`owner_user_id`·`user_id`) |
| PC 기기 | `devices.owner_user_id`를 새로 둠 — 연결(짝맺기)을 승인한 사람이 주인. 예전 기기(빈칸)는 관리자 것 |
| 기기 목록·짝맺기·기기 명령(`hosts/:id/run`)·새 세션 만들 곳 | 사용자는 **자기 기기만**(남의 기기는 404). 관리자는 기기 목록(이름·상태)만 전체 |
| 기존 세션 등록(bindings) | 주인만 보고·고치고·지움. 남의 것을 덮어쓰지 못함. 가입자는 등록 표 대신 **＋ 대화 연결**로 자기 PC의 Codex 대화를 붙임(2026-11-19 — 허브가 그 PC에 기기 명령 `codex.threads`로 목록을 묻고, `codex.connect`로 그 PC 허용 목록에 넣은 뒤 허브가 그 사람의 등록으로 저장. 업무 대화는 PC에 보내지도 않음) |
| 약관·한도(M4, 2026-11-19) | 가입은 `agree: true`여야(`terms_required`), `users.terms_at` 기록. `/terms`·`/privacy`는 접속 제한 예외(정적). 설정 `member_limits = { perDay, users{id: n} }`(관리자만 `PUT /v1/admin/settings/member-limits`), 질문 접수(`askConversation` — 웹·앱·메신저·예약 모두)에서 가입자의 오늘(KST 0시~) 질문 수가 한도 이상이면 429 `member_limit`. 관리자 목록에 오늘 질문·한도 |
| 관리 경로(`/v1/admin/*`) | 사용자에게 허용: 앱 기기·짝맺기·기기 목록·자기 기기 명령·작업 폴더 붙이기. 나머지는 관리자만(403) |

- **남은 한계(알려 둠):** 허브 DB를 서버에서 직접 열면 관리자(서버 주인)는 내용을 볼 수 있다 — 화면·API로는 못 봄. AI 직원 이름·새 세션 이름은 허브 전체에서 겹치지 않아야 함(다른 사람이 쓴 이름이면 "이미 있음").

## 3. 화면

- 로그인 화면: 이메일 칸(비우면 관리자 비밀번호 로그인), "가입 신청"(여러 사람 쓰기가 켜져 있을 때만).
- 승인 대기 화면: "관리자 승인을 기다려요".
- 관리자 설정 → 허브 보안: "여러 사람 쓰기" 켜기, 가입 신청 목록(승인·거절), 사용자 목록(끊기·다시 켜기).
- 사용자 설정: 관리자용 탭(메신저·허브 보안 등)은 숨기고 PC 연결·앱 연결만.

## 4. 결과(2026-11-18 코드, M2-a)

- **저장:** `users` 표(이메일 소문자·비밀번호 scrypt 해시·상태), `devices.owner_user_id`(연결을 승인·등록한 사람, 빈칸 = 관리자), 등록(bindings) 목록·고치기·지우기를 주인 기준으로 — 남의 것 덮어쓰기는 `id_taken`.
- **로그인:** `/v1/auth/signup`(허브 + 여러 사람 쓰기 켜짐일 때만, 주소당 잠금 공유) → 승인 대기 세션. `/v1/auth/login`에 이메일을 넣으면 사용자, 비우면 관리자. 거절·끊긴 계정은 `account_disabled`, 끊으면 그 사람 세션을 바로 지움. 관리자 비밀번호 바꾸기는 관리자 세션만 끊음(전에는 전부).
- **서버:** 제한은 **가입으로 들어온 사람(users 표)에게만** — 설정 파일의 사용자(관리자·메신저·외부 앱 키·시험)는 그대로. 사용자는 승인 전 `pending_approval`, `/v1/admin/*` 중 앱 기기·짝맺기·기기·자기 기기 명령·작업 폴더만(나머지 `admin_only`). 기기 목록·재발급·폐기·짝맺기 교체·기기 명령·새 세션 만들 곳·등록 확인을 자기 기기 기준으로. 관리자의 등록 목록도 자기 것만(남의 대화 이름이 안 보이게).
- **관리자 API:** `GET /v1/admin/users`(이메일·상태·PC 수·신청일), `POST /v1/admin/users/<id>/approve|reject|disable|enable`, `PUT /v1/admin/settings/multi-user`.
- **화면:** 로그인 화면 이메일 칸·가입 신청(켜졌을 때), 승인 대기 화면, 관리자 설정 → 허브 보안에 "여러 사람"(켜기·승인·끊기), 사용자 설정은 메신저·허브 보안·계정 탭과 세션 등록·새 세션 설정·외부 프로그램 키를 숨김.
- **시험:** m2-multi-user 2건(가입→대기→승인, 관리자 전용 경로, 남의 PC·대화 안 보임, 관리자도 남의 대화 안 보임, 남의 등록 덮어쓰기 막음, 끊기·다시 로그인 막힘, 관리자 로그인 그대로, 자기 PC 없으면 새 세션 거절).
- **실측(2026-11-19 허브, 신산님 "켜고 시험해 줘"):** 여러 사람 쓰기 켬 → 시험 계정 `ieon-test@example.com` 가입 신청(승인 대기, 대화 목록 `pending_approval`) → 관리자 승인 → 로그인: 대화 0개(관리자의 "시험 표식 확인" 안 보임), 설정·사용자·봇·보안 `admin_only`, 내 기기 0개, 관리자 PC(h_pc) 명령 `unknown_host`, 관리자 대화 기록·질문 404, 작업 0개 → 끊기 → 401·다시 로그인 `account_disabled` → 여러 사람 쓰기 끔(가입 신청 사라짐). 관리자 대화 3개 그대로. 시험 계정은 끊긴 채 남음(지우기 기능 없음). **PASS.**
- **남음(M2-b):** 사용자 PC 연결 흐름 실측(사용자가 자기 PC 연결 링크·코드 승인), 메신저는 관리자 것만(공용 봇은 M3), AI 직원·새 세션 이름이 허브 전체에서 겹치지 않아야 하는 점, 사용자 비밀번호 바꾸기·찾기.

## 5. M2-b(2026-11-19 코드, 신산님 "다음 작업 진행하자")

- **AI 직원 이름:** 허브 전체 고유 → **같은 사람 안에서만** 겹치지 않게(DB 고유 색인 `staff_name`을 지우고 코드에서 주인 기준으로 확인). 방에서 @이름은 그 사람 방의 직원 안에서만 찾으므로 그대로.
- **새 세션 ID:** 가입한 사람은 `n_<이름>_<사람 표식 6자>`(다른 사람의 같은 이름과 겹치지 않게), 관리자는 전처럼 `n_<이름>`.
- **비밀번호:** 설정 → 밖에서도 쓰기 → **내 비밀번호**(관리자·가입자 같음, 바꾸면 그 사람의 다른 로그인 끊김). 관리자는 가입자 목록에서 **임시 비밀번호**(메일 없이 "비밀번호 찾기" — 한 번만 보이고, 그 사람 로그인 끊김, `POST /v1/admin/users/<id>/reset`).
- **가입자 지우기:** `POST /v1/admin/users/<id>/delete` — 그 사람의 이어온 대화 기록(질문·답·승인·AI 직원·작업 모드·작업 폴더 표시·예약·새 세션)·방·기기·앱 연결·웹 알림·로그인과 사용자 기록을 지움(기기 기록에는 "delete_with_user" 남김). 그 사람 PC의 원래 엔진 세션 기록은 그대로. 화면은 확인 창 하나.
- **시험:** m2-multi-user 1건 추가(이름 사람별, 임시 비밀번호·옛 비밀번호 거절, 내 비밀번호 바꾸기, 지우기 범위·관리자 것 그대로).

## 6. M3 공용 메신저 봇(2026-11-19 코드, 신산님 "M3 진행" → 결정 "지금 봇 그대로 같이", "카카오는 이번엔 빼기")

- **연결:** 가입자가 설정 → 밖에서도 쓰기 → **메신저 연결**에서 연결 숫자(6자리·10분·한 번)를 받아 허브의 봇(텔레그램·디스코드·슬랙·라인)에 보내면, 그 메신저 계정(메신저·사용자 ID)이 그 가입자에 연결된다(`messenger_links` 표). 같은 화면에서 끊기. 카카오는 연결하지 않음.
- **봇이 보낸 사람을 알림:** 브리지가 한 메시지를 처리하는 동안의 모든 서버 요청에 `x-ieon-sender`(그 메신저 사용자 ID)를 실음(AsyncLocalStorage — 동시에 온 메시지가 섞이지 않음). 서버는 메신저 토큰 + 봇 + 보낸 사람이 승인된 가입자에 연결돼 있으면 그 가입자로 처리(대화·방·승인·새 세션 모두 그 사람 것, 관리 경로는 M2 규칙). 연결 안 된 사람은 지금처럼(관리자가 허용한 사람 = 관리자 대화).
- **봇이 받아 주는 사람:** 메신저 설정 응답에 `linkedUsers`(승인된 가입자에 연결된 메신저 계정) → 실행기가 허용 목록·승인할 수 있는 사람에 더함(승인은 서버가 그 사람 대화인지 다시 확인).
- **연결 숫자 안전:** 가입자 숫자를 주인 등록 숫자보다 먼저 봄, 숫자는 한 번만, 메신저 계정마다 틀린 시도 5번이면 15분 잠김, 숫자는 기록에 남기지 않음. 가입자를 지우면 연결도 지움.
- **예약 답·보관 예고(2026-11-19 보탬):** 봇이 1분마다 가져가는 알림(`/v1/schedules/notices`·`/v1/sessions/notices`)에 메신저에 연결된 가입자들의 대화 것도 함께 줌 — 봇은 그 대화에 묶인 방(그 사람이 `/use`로 고른 방)에만 보내므로 그 사람 방으로 감. 메신저를 연결하지 않은 가입자 것은 주지 않음.
- **남은 한계:** 단체방은 방 하나가 대화 하나에 묶이므로 가입자는 1:1 대화를 권함(남의 대화에는 서버가 막음).
- **시험:** m3-messenger-users 2건(연결 숫자·카카오 거절·한 번만, 연결 뒤 가입자 대화만·다른 사람 그대로·관리 경로 막힘, 끊기, 브리지가 동시 메시지마다 보낸 사람을 따로 실음).
