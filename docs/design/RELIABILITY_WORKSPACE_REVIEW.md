## 2. 신뢰성 후보 — 재현 결과와 고침

| # | 후보 | 지금 코드에서 | 고침 |
| --- | --- | --- | --- |
| R1-1 | 메신저가 같은 이벤트를 다시 보내면 매번 새 요청 → 세션 작업 중복 실행 | **재현됨.** 브리지가 질문마다 무작위 요청 열쇠(`msg-<무작위>`)를 써서 서버가 같은 메시지를 새 질문으로 받음. 텔레그램은 처리 중 프로그램이 다시 켜지면 같은 update가 다시 옴(offset 확정 전), 슬랙은 응답 확인 지연 시 재전송. 라인은 이미 막음(webhookEventId), 디스코드는 재접속 때 다시 받지 않음 | 원본 메시지 번호(`tg-<채팅>-<메시지>`, `dc-<id>`, `sl-<채널>-<client_msg_id\|ts>`, `ln-<webhookEventId>`)로 **요청 열쇠를 만듦**(`msg-` + 해시 40자 — 서버의 기존 중복 방지가 같은 요청으로 받음, 다시 켠 뒤에도). 프로그램 안에서는 같은 메시지를 10분 기억해 두 번째는 무시 |
| R1-2 | 슬랙의 서로 다른 스레드가 같은 채널로 묶여 대상이 섞임 | **재현됨.** 브리지 대화방 열쇠는 스레드를 지원하지만(텔레그램 주제는 이미 나눔), 슬랙 연결부가 스레드를 넘기지 않아 한 스레드의 `/use`가 같은 채널의 모든 스레드를 바꿈 | 슬랙 스레드 답글이면 `thread_ts`로 대화방을 나눔. **연결이 없는 스레드는 채널 연결을 따름**(지금까지의 동작 보존 — 채널에서 쓰던 사람은 그대로). 텔레그램 주제는 전처럼 채널 연결을 따르지 않음 |
| R1-3 | 메신저 전송 API가 오류를 돌려줬는데 성공으로 판단 | **재현됨.** 텔레그램·슬랙은 실패해도 HTTP 200에 `ok:false`를 돌려주는데 확인하지 않음. 답을 보내다 실패해도 브리지는 모름. 디스코드는 확인함, 라인은 기록만, 카카오는 못 보낸 답을 `/last`로 받게 되어 있음 | `messengerOk()`로 `ok:false`를 실패로 처리(한도·서버 오류는 "잠깐 실패"). **엔진 실행 완료와 답 전달 완료를 나눔**: 잠깐 실패면 전달만 두 번 더, 끝내 실패하면 `deliver_failed` 기록(답 원문 없이)·"답을 보내지 못했어요 — /last" 안내. **엔진은 다시 돌리지 않음.** `/last`는 요청을 다시 읽어 전달만. `/status`에 "답 전달 실패" 표시. 안내 글(접수·실패 안내)은 못 보내도 처리를 멈추지 않음 |

결과 불명은 지금처럼 **자동으로 다시 실행하지 않음**(확인 카드·`/review`) — 바꾸지 않음.

## 7. 작업공간(WS) — 현황과 빠진 것

> **기억·지식의 분리와 PC 파일 작업공간의 분리는 다른 문제.** 폴더를 나눴다고 다른 폴더를 못 읽는 것은 아님 — **정리상 분리 ≠ 보안상 차단.**

| 질문 | 지금 이어온 | 판단 |
| --- | --- | --- |
| 1. 직원별 작업 폴더 | **새 세션**은 세션마다 작업 폴더를 만들어 그 안에서 시작(기본 `D:/ieon-workspaces/<이름>`). **기존 세션**은 원래 세션의 폴더를 그대로 씀(작업 모드는 PC 허용 목록의 작업 폴더). AI 직원 이름·역할·역할 안내는 있음 | 개인 폴더는 새 세션만 자동. 직원마다 **지침 파일·메모 폴더**를 두는 구조는 없음(기억은 원래 세션 대화 자체) |
| 2. 공유 공간 | 없음(방은 대화를 나누는 곳이지 파일 공유가 아님) | **빠짐** |
| 3. 접근 통제 | Codex: 작업 모드·새 세션 `workspace-write` 샌드박스 — **쓰기는 작업 폴더 안만, 인터넷 막음**. 그러나 **읽기는 막지 않음**. Claude 새 세션: 도구 허용 목록 + `--restricted` — 공식 문서 기준 **파일 도구 읽기·쓰기가 작업 폴더 안**(명령 도구 없음, `full` 제외 — 2026-11-14 [WORKSPACES](WORKSPACES.md) 3절에서 바로잡음, 실측 필요). Claude 채널(기존 세션): 그 세션 자체 권한 설정 | Codex는 쓰기만 차단·읽기는 막지 못함, Claude 새 세션은 파일 도구 읽기·쓰기 모두 작업 폴더 안(문서 기준), 다른 직원 폴더를 실제로 못 읽게 하는 것은 엔진마다 다름 → [WORKSPACES](WORKSPACES.md) |

**방향(WS1 설계 — 승인 뒤):**
1. **사람이 지정·승인:** 직원마다 "개인 폴더", 프로젝트마다 "공유 폴더"를 웹 화면에서 **사람이 골라 지정**(PC의 실제 폴더, 허용 목록과 같은 방식). AI가 스스로 폴더를 만들거나 넓히지 않음.
2. **구조(보존 우선):** 기존 세션·새 세션 작업 폴더는 그대로 두고, 필요한 직원에게만 `개인 폴더 + 읽기 허용 공유 폴더(+쓰기 허용 공유 폴더)`를 더함. 지침 파일(예: 개인 폴더의 AGENTS.md)은 사람이 쓰고 이어온은 읽기만.
3. **차단 수준을 정직하게 표시:** 화면에 "쓰기 차단(샌드박스)" / "정리만(차단 아님)"을 엔진별로 보여 줌.
4. **실제 차단:** Codex는 샌드박스 쓰기 허용 폴더를 개인+공유(쓰기)로. 읽기까지 막으려면 **OS 수준 격리**(직원별 Windows/Linux 사용자·컨테이너) 필요 — 무겁고 승인 필요한 선택지로 따로 설계. Claude는 권한 설정(허용 경로·샌드박스 기능)의 실제 차단 여부를 **먼저 실측**(W0처럼)한 뒤 결정.
5. **이건 이어온 연결 기능의 확장이지, 세션을 전문 봇으로 키우는 일(학습·전문 MCP)과는 다름** — 그것은 사용자 몫·다음 프로젝트.
