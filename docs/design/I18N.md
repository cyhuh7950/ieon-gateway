## 1. 원칙

1. **한국어가 원본.** 사람이 읽는 문구는 모두 **키**로 부르고, 언어마다 **사전 파일**에 둔다. 코드에 문구를 직접 쓰지 않는다.
2. **언어 더하기 = 사전 파일(+문서 번역) 더하기.** 코드는 바꾸지 않는다. 사전에 없는 키는 **영어 → 한국어** 순으로 대신 보여 준다(빈칸·키 이름이 화면에 나오지 않게).
3. **번역하지 않는 것:** 사용자가 쓴 질문, AI 답, 세션·대화 이름, AI 직원 이름·역할 이름, 방 이름, 메신저 사용자 이름.
4. **서버는 되도록 코드를 보내고 화면이 번역한다.** 이미 오류는 코드(`hub_mode`, `desktop_holds_thread` …)로 오간다. 서버가 직접 만들어 사람에게 보내는 글(메신저 답, 카카오 중계 안내, 계정 이름표, 승인 요약 등)만 서버가 받는 사람 언어로 만든다.
5. **날짜·시간·숫자는 `Intl`**로 그 언어 형식에 맞춘다(지금 `toLocaleTimeString()` 등은 그대로 언어만 넘기면 됨).
6. **새 부품 최소.** 사전 읽기·`{이름}` 채우기·영어 단수/복수 정도만 필요해 작은 자체 함수로 만든다(필요가 커지면 그때 `i18next` 등을 별도 승인으로).

## 2. 언어 정하기

| 어디 | 정하는 법 | 바꾸는 곳 |
| --- | --- | --- |
| 웹 화면(PC형·허브형) | 브라우저 언어(`Accept-Language`/`navigator.language`) → 지원 안 하면 영어 | 설정 화면 맨 위 **언어** 고르기(이 브라우저에 기억), 로그인 화면에도 작은 고르기 |
| 이어온 앱 | 기기 언어(앱: `navigator.language`, PC 앱: Electron `app.getLocale()`) → 지원 안 하면 영어 | 앱 첫 화면 아래 **언어**(기기에 기억) |
| 메신저 봇 답 | **서버 기본 언어**(설치 때 PC 언어로 정해지고 설정에서 바꿈) → 봇마다 덮어쓰기(설정 → 메신저 → 봇 → 언어) | 웹 설정 |
| 카카오·라인 중계 안내 | 그 봇의 언어 | 웹 설정 |
| AI에게 붙이는 머리말(`[방 안내]`·`[역할 안내]`·`[질문]`) | 서버 기본 언어(AI는 어느 언어든 이해하지만 사람이 기록을 볼 때 읽기 쉽게) | 웹 설정 |
| 음성(받아쓰기·읽어 주기) | 화면 언어를 따름(`ko-KR` → `en-US`) | 화면 언어와 같이 |

- 메신저 **사용자마다** 다른 언어는 나중(필요하면 `/lang en` 명령) — 처음엔 봇 단위.

## 3. 층별 설계

### 3-1. 사전(공통)

- 위치: 저장소 맨 위 `locales/<언어>/<묶음>.json` — 예: `locales/ko/web.json`, `locales/en/web.json`.
- 묶음(namespace):

| 묶음 | 쓰는 곳 |
| --- | --- |
| `common` | 공통 낱말(보내기·취소·저장·끄기…) |
| `errors` | **오류 코드 → 문구 한 곳**(지금은 웹 `app.html` ERR, 앱 `texts.ts` ERR, 메신저 `bridge.mjs` 세 곳에 따로 있음 → 하나로 합쳐 뜻도 맞춤) |
| `web` · `settings` | 웹 화면·설정 화면 |
| `app` | 이어온 앱(연결·목록·대화·방·음성·알림) |
| `messenger` | 봇 답·도움말·승인 요청 안내·카카오/라인 중계 안내 |
| `server` | 서버가 만드는 글(계정 이름표, 기본 봇 이름, AI 머리말, 승인 요약) |
| `privacy` | 처리방침 화면 |

- 키 이름: `화면.자리.뜻` — 예: `app.pair.title`, `errors.hub_mode`.
- 채우기: `"{name}이 답했어요"` / 영어 `"{name} replied"`. 한국어 조사는 `{name|이가}`처럼 조사 처리(이미 앱 `iga()`가 있음) — 영어 사전에서는 쓰지 않음.
- 영어 단수·복수: `"{count} AI staff"` 같은 꼴로 피하고, 꼭 필요할 때만 `{count|one:…|other:…}`.
- 사전 한 벌을 세 곳이 같이 씀: **서버**(웹 화면용으로 내줌, 메신저·서버 글), **앱**(빌드 때 `app/src/locales`로 복사해 묶음), **동영상 도구**(장면 글).

### 3-2. 웹 화면(`app.html`·`settings.html`, 약 660줄)

- 서버가 페이지를 줄 때 고른 언어의 사전을 `<script type="application/json" id="i18n">`으로 함께 넣는다(따로 불러오지 않아 깜빡임 없음), `<html lang>`도 맞춘다.
- 고정 글은 `data-i18n="키"`(필요하면 `data-i18n-attr="placeholder:키"`), 코드에서 만드는 글은 `t('키', {값})`.
- 서버 응답의 오류 코드는 지금처럼 화면에서 `errors.*`로 바꾼다.
- 설정 화면 맨 위 언어 고르기 → 다시 불러오기(쿠키 `ieon_lang`, 개인 정보 아님).

### 3-3. 이어온 앱(`app/`, 약 170줄 + 안드로이드·PC 앱 바깥 글)

- `useT()` 작은 훅 + 사전. 지금 `texts.ts`·`rooms.ts`·`voice.ts`·`notify.ts`의 문구 표를 사전으로 옮김.
- **안드로이드:** 앱 이름(`strings.xml` → `values-en/strings.xml`), 받아쓰기 창 안내(`VoicePlugin`의 "말하면 글자로 바꿔요" → 화면에서 넘김), 읽어 주기 언어(`Locale` 고정 → 화면 언어로).
- **PC 앱:** 메뉴(새로 고침·끝내기), 창 제목, 설치 파일 언어(electron-builder NSIS 언어 묶음), 바로 가기 이름(`이어온 앱` / `Ieon App`).
- 알림 글(`noteFor`)은 앱이 만들므로 앱 사전으로.

### 3-4. 서버·메신저(약 150줄)

- `bridge.mjs` 답·도움말·승인 요청(`/허용 n`) → `messenger` 묶음. **명령 이름은 영어가 기준**(지금도 `/new`·`/restore`·`/use` …), 언어별 별칭을 사전에서 더 받음(지금 `/허용`=`/allow`, `/거부`=`/deny`처럼).
- 카카오 중계(`src/relay/relay.mjs`의 "접수되었습니다…" 등) → 봇 언어.
- 계정 이름표(`accountOf`의 "그 PC의 Claude Code 창에 로그인된 계정" 등)·승인 요약(`codex-thread.mjs`의 "파일 수정"·"권한 요청")·기본 봇 이름 → **코드 + 값**으로 보내고 화면·봇이 번역.
- AI 머리말(`[방 안내 — 이름]`·`[역할 안내]`·`[질문]`) → 서버 기본 언어 사전. 이미 저장된 질문 원문은 그대로(머리말은 넘길 때만 붙음 — 지금 구조 그대로).
- 로그는 번역하지 않는다(코드·영문 그대로).

### 3-5. 음성

- 앱·웹의 `lang`(지금 `ko-KR` 고정) → 화면 언어의 음성 언어로. PC 앱은 그 언어 Windows 목소리를 고름(영어는 기본으로 있음, 다른 언어는 Windows 음성 팩 — 설명서에 안내).
- 처음 안내·오류 글 → `app`·`web` 사전.

### 3-6. 설명서·처리방침

- 사람이 읽는 설명서만 번역: `BEGINNER_GUIDE`, `APP_GUIDE`, `MANUAL`, `MESSENGER_MANUAL`, `API_GUIDE` → `docs/en/…`(같은 파일 이름). 설계·작업현황 등 내부 문서는 한국어로 둔다.
- 번역본 맨 위에 **"원본 기준 커밋"**을 적고, 원본이 바뀌면 시험이 번역본이 오래됐다고 알림.
- 처리방침: `/privacy`가 언어를 고름(`/privacy?lang=en`, 브라우저 언어 기본). **법적 문서라 영어판은 원어민·전문가 검토 권장.**
- 웹 화면의 "설명서" 링크는 화면 언어의 설명서로.

### 3-7. 동영상(영어만 — I3)

- 지금 장면 글이 `intro-scenes.mjs`(말)와 `intro.html`(화면 글·이름표·말풍선)에 나뉘어 있음 → **화면 글도 장면 목록으로 옮겨** 언어별 파일(`intro-scenes.ko.mjs`·`intro-scenes.en.mjs`)로.
- 영어 목소리: Windows 기본(Zira·Mark·David), 실제 화면 캡처는 화면 언어를 영어로 바꿔 다시 찍음(가짜 서버 예시 답도 영어판).
- 결과 `Ieon_intro_en.mp4` + `.srt`.

### 3-8. 스토어

- 플레이 소개 글·데이터 보안 답·스크린샷을 영어판으로(`docs/store/PLAY_LISTING.en.md`), 스크린샷은 가짜 서버 + 영어 화면으로 찍음.

## 4. 시험(언어를 쉽게 더해도 안 깨지게)

| 시험 | 무엇을 막나 |
| --- | --- |
| **키 맞춤** | 모든 언어 사전이 한국어 사전의 키를 다 갖는지 — 영어는 하나라도 빠지면 실패, 다른 언어는 빠진 수를 보고(대신 영어로 보임) |
| **채우기 맞춤** | `{name}` 같은 자리 표시가 언어마다 같은지 |
| **안 쓰는 키** | 코드에서 부르지 않는 키 경고 |
| **직접 쓴 문구 금지** | 웹 화면·앱·메신저 코드의 문자열 안 한국어 0(주석·시험·사전·허용 목록 제외) — 앞으로 기능을 더해도 문구가 사전으로 가게 |
| **가짜 언어 `xx`** | 모든 문구를 `[!! … !!]`로 1.4배 늘린 가짜 사전으로 화면을 찍어, 넘침·빠진 키·잘린 버튼을 찾음 |
| **언어 바꾸기** | 웹·앱에서 언어를 바꾸면 화면·음성 언어·날짜 형식이 바뀌는지 |
| **영어 봇** | 대역 시험으로 영어 봇의 답·도움말·승인 안내·카카오 안내 |
| **설명서 오래됨** | 번역본의 원본 기준 커밋 뒤에 원본이 바뀌면 알림 |

## 5. 단계(구현은 0절 I4 시기에)

| 단계 | 내용 | 보이는 변화 |
| --- | --- | --- |
| **I18N-0** | 이 설계 | 없음 |
| **I18N-a 바탕** | `locales/ko` 사전, 웹·앱·서버의 `t()`, 문구를 한국어 사전으로 옮기기, 오류 문구 세 곳 합치기, 언어 고르기 자리(한국어만), 시험 4종(키·채우기·안 쓰는 키·직접 쓴 문구 금지) | 없음(한국어 그대로) |
| **I18N-b 영어** | `locales/en` 전체, 언어 고르기, 메신저·중계·머리말 영어, 음성 언어, 안드로이드·PC 앱 이름·메뉴·설치 파일, 설명서 `docs/en`, 처리방침 영어, 스토어 영어, 소개 영상 영어, 가짜 언어·언어 바꾸기·영어 봇 시험 | 영어 |
| **I18N-c 언어 더하기 절차** | 문서 한 장: ① `locales/en`을 복사해 `locales/<새 언어>` ② 번역 ③ 시험 통과 ④ (선택) 설명서 번역 — **코드 변경 없음** | 새 언어 |

- 그 사이에 기능을 더할 때도 **오류는 코드로, 문구는 한곳(표)에** 두는 지금 방식을 지키면 I18N-a가 쉬워진다.
