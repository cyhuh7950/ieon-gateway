## 1. 원칙

00. **최소 규칙(2026-11-12 신산님): 사용자가 어떤 계정인지 모르는 상태에서 "토큰(한도)이 없다"로 실패하면 안 된다.** 이어온은 질문마다 **어느 엔진·어느 계정(접속)으로 보내는지**를 화면·카드·메신저 답에 보이고, 한도에 걸리면 **"○○ 계정(Codex · 개인 Plus)이 한도에 걸렸어요 — ○시 이후, 또는 다른 계정·API 키·호환 주소로"**처럼 계정 이름과 고를 수 있는 길을 함께 알린다. 계정이 정해지지 않았으면(처음) 보내기 전에 고르게 한다.
0. **AI 사용량(토큰)은 언제나 이어온에서 로그인(또는 등록)한 계정·접속의 것을 쓴다 — 어떤 세션을 읽어 오든 상관없이(2026-11-12 신산님 결정).** 세션은 Codex Desktop·Claude 앱·다른 계정 어디에서 만들어졌든 이 PC 기록에서 읽어 오고, 질문은 이어온에서 고른 계정 접속(구독 로그인)·API 키·호환 주소로 보낸다. 이어온은 PC의 다른 앱(Desktop 등)에 로그인된 계정을 암묵적으로 쓰지 않는다(기본값 "PC 기본 로그인"도 신산님이 이어온 화면에서 그것을 고른 경우에만).

1. **세션은 계정과 무관하다(신산님 결정) — 세션은 계정과 상관없이 이 PC(로컬)에 있는 기록을 읽어 오고, 계정은 AI를 부를 때만 쓴다.** 세션(대화 기록)은 이 PC에 저장된 것이고, 계정은 AI를 부를 때 "누구 이름·누구 한도로" 부르느냐다. 계정을 바꿔도 **같은 세션을 그대로 이어 쓴다**(새 세션·복사·갈라 쓰기로 대체하지 않음).
2. **엔진마다 이어온 전용 계정을 고른다 — Desktop·웹 계정과 독립.** 한 PC에서 Codex Desktop과 Codex 웹(chatgpt.com)이, Claude 앱·웹과 Claude Code가 서로 다른 계정을 쓸 수 있듯, 이어온도 엔진마다 자기 계정을 쓴다. Desktop 계정을 바꾸지 않는다.
3. **로그인은 신산님이 직접, 공식 방법으로.** 이어온은 각 엔진의 공식 로그인(기기 코드 로그인 등)을 띄워 주소·코드만 보여 준다. 로그인 정보 파일을 읽거나 복사·이동·주입하지 않는다.
4. **어떤 계정의 사용량으로 부를지(또는 API 키로 부를지)를 이어온에서 엔진마다 고르고, 그 계정 접속도 이어온 화면에서 한다**(3-1절). 유료 API 키는 신산님이 명시적으로 고를 때만(MORE_ENGINES ME7과 같음).

## 2. 지금 상태(확인한 사실)

| 엔진 | 세션이 저장되는 곳 | 로그인 정보가 있는 곳 | 계정을 바꾸면 |
| --- | --- | --- | --- |
| Codex | \`%USERPROFILE%\\.codex\\sessions\`(대화 기록), 같은 폴더의 잠금·상태 DB | 같은 \`.codex\` 폴더(로그인 하나) | Codex 앱에서 로그아웃·다른 계정 로그인 → 이어온도 다음 질문부터 새 계정(질문마다 로그인을 새로 읽음). **계정을 바꿔도 이 PC의 내 세션이 모두 그대로 보인다 — 신산님 확인(2026-11-12)**. 바꾼 계정으로 그 세션을 실제로 이어 쓸 때 문제가 없는지(이전 답의 암호화 조각)는 A0에서 확인 |
| Claude Code | \`%USERPROFILE%\\.claude\` 아래 프로젝트별 기록 | 같은 곳(로그인 하나) | 계정을 바꾸면 **화면 목록에는** 그 계정에서 만든 세션만 보이지만, **다른 계정의 세션을 가져오면 이어서 작업 가능**(신산님 확인 2026-11-12). 같은 폴더에서 `claude-solar`(Upstage API 키)로 열면 기존 세션을 이어 썼다(신산님 실사용) |
| Grok·Gemini | 각 프로그램 폴더(\`~/.grok\`·\`~/.gemini\`) | 같은 곳 | 아직 연결 전(E 단계) |

**제약:** 네 엔진 모두 **로그인과 세션 기록이 같은 폴더**에 있다. 그래서 "계정마다 따로 폴더(예: \`CODEX_HOME\`)를 두는" 방법은 그 계정 폴더에 기존 세션이 없어 **원칙 1(같은 세션)과 어긋난다.** 세션 폴더만 연결(링크)해 나누는 방법은 잠금 파일·상태 DB가 함께 있어 **두 프로그램이 같은 DB를 다른 경로로 쓰다 깨질 위험**이 있다.

## 3. 방식

핵심: **"세션 기록은 Desktop과 같은 곳에서 읽고, 로그인은 이어온 전용 계정으로."** 웹이 Desktop과 다른 계정을 쓸 수 있는 것은 웹이 이 PC의 엔진 폴더를 쓰지 않기 때문이고, 이어온은 이 PC에 저장된 기존 세션을 이어 써야 하므로 둘을 나눠 읽게 해야 한다.

| 방식 | 모양 | 원칙 1(같은 세션) | Desktop 계정 | 위험 |
| --- | --- | --- | --- | --- |
| **B. 이어온 전용 로그인 + 세션 기록은 공유(목표)** | 엔진마다 이어온 전용 로그인 위치(Codex `CODEX_HOME`, Claude Code `CLAUDE_CONFIG_DIR` 등)에 신산님이 공식 로그인, 세션 기록·잠금은 Desktop과 같은 것을 쓰게 연결 | A0 실측으로 확인 | **그대로** | 잠금·상태 DB를 두 경로로 쓰면 "Desktop에서 열려 있으면 거부" 판별이 틀어지거나 기록이 손상될 수 있음 → **A0에서 안전이 확인돼야만** |
| A. 엔진 폴더의 로그인 자체를 바꾸기(대체안) | 공식 로그아웃 → 다른 계정 로그인 | 지킴(기록 폴더 그대로) | **같이 바뀜** | Desktop에서 쓰던 계정이 바뀜 |
| 새 세션 | 이어온 전용 로그인 위치 안에서 만들고 이어 씀 | 지킴(처음부터 그곳) | 그대로 | 없음 — **바로 가능** |

**엔진별:**
- **Codex:** 기존 대화는 `%USERPROFILE%\.codex`(Desktop과 같은 곳)에서 읽어야 한다. B의 공식 방법(로그인 위치만 따로 지정)이 있는지, 없으면 연결 방식이 안전한지 A0에서.
- **Claude 계정과 세션(신산님 확인, 2026-11-12):** Claude는 계정을 바꾸면 **화면 목록(Claude 데스크톱 앱의 사이드 창 — 신산님 캡처, 계정 표시 "신산 · Max")에는** 그 계정에서 만든 세션만 보이지만, **다른 계정에서 만든 세션을 가져오면 이어서 작업이 가능하다 — 화면에서만 안 보일 뿐.** 즉 Claude도 세션은 계정과 무관하다. 이어온은 화면 목록이 아니라 **이 PC의 세션 기록(세션 ID)으로 직접 열기** 때문에 목록 필터와 상관없이 고른 계정·접속으로 이어 쓴다. 이어온의 대화 연결 목록은 계정과 관계없이 이 PC의 Claude 세션을 모두 보여 준다(업무 대화 제외 규칙은 그대로).
- **Claude Code 채널:** 이어온은 사람이 띄운 Claude Code 창에 질문을 넣으므로 **그 창의 로그인 계정**이 쓰인다 → `ieon.ps1 claude`가 이어온 전용 계정(`CLAUDE_CONFIG_DIR`)으로 창을 열 수 있게 한다. 그 창에서 기존 세션을 이어 쓸 때는 Codex와 같은 실측.
- **Claude 새 세션(`claude -p`):** 이어온 전용 `CLAUDE_CONFIG_DIR`로 바로 가능.
- **Grok·Gemini:** E 단계에서 같은 원칙(전용 로그인 + 세션 기록 공유 가능 여부 실측).

### 3-1. 엔진마다 "사용 방식" — 어떤 계정의 사용량으로, 또는 API로(2026-11-12 신산님)

신산님: "토큰을 위해 어떤 계정에 접속할 건지를 이어온에서 계정 접속을 해야 해. 즉 어떤 계정의 토큰을 사용할 건지, 아니면 API를 사용할 건지."

설정 → 계정 탭에서 엔진(Codex·Claude·Grok·Gemini)마다 하나를 고른다.

| 사용 방식 | 누구 사용량 | 이어온에서 하는 일 | 비용 |
| --- | --- | --- | --- |
| **구독 계정(이어온에서 로그인)** | 이어온에서 로그인한 그 계정의 구독 한도 | **이어온 화면에서 계정 접속**: "로그인" → 공식 기기 코드 로그인(주소·코드) → 신산님이 브라우저에서 원하는 계정으로 승인. 여러 계정을 이름표로 두고 하나를 고름. 로그인 정보는 이어온 전용 위치에 엔진이 저장(이어온은 읽지 않음) | 구독에 포함(한도 있음) |
| **API 키** | 그 API 키의 계정(종량제) | 키를 웹에서 한 칸에 붙여 넣기(봇 토큰과 같은 비밀 파일, 다시 보이지 않음). 실행할 때만 그 엔진에 넘김 | **쓴 만큼 요금** — 고를 때 확인 창으로 한 번 더 묻는다(AGENTS "유료 API 자동 전환 금지" — 신산님이 명시적으로 고른 경우만) |
| PC 기본 로그인(지금) | 이 PC의 Codex Desktop·Claude Code에 로그인된 계정 | 없음 | 구독(Desktop과 같은 한도를 나눠 씀) |

**계정 접속과 API 접속은 다른 것이다(2026-11-12 신산님) — 이것은 Codex·Claude·Grok·Gemini뿐 아니라 앞으로 붙일 모든 LLM 엔진의 공통 규칙이다.** 새 엔진을 붙일 때마다 "계정 접속 방법·API 접속 방법·세션 기록 위치·한도 오류 모양"을 같은 표로 정리하고, 화면도 같은 모양(로그인 버튼 / API 키 칸 / 사용 방식 고르기)으로 둔다.

| | 계정 접속(구독 로그인) | API 접속(API 키) |
| --- | --- | --- |
| 무엇 | 그 서비스 계정으로 로그인해 받는 접속 정보(로그인 토큰) | 개발자 콘솔에서 발급하는 키 |
| 얻는 곳 | 엔진의 공식 로그인(기기 코드 등) — ChatGPT·Claude·grok.com·Google 계정 | OpenAI Platform·Anthropic Console·xAI Console·Google AI Studio 등의 API 키 화면 |
| 저장 | 엔진이 자기 폴더(이어온 전용 위치)에 저장하고 스스로 갱신 — 이어온은 읽지 않음 | 이어온 비밀 파일(웹에서 한 칸 입력, 다시 보이지 않음) — 실행할 때만 엔진에 넘김 |
| 요금 | 구독료에 포함 | **쓴 만큼 따로 요금** |
| 한도 | 구독 요금제의 사용 한도(오늘처럼 "○시에 다시") | API 계정의 결제·사용 한도 |
| 끝나는 때 | 로그아웃·만료되면 다시 로그인 | 폐기하거나 결제가 막히면 |
| 이어온 화면 | **로그인** 버튼(주소·코드) | **API 키** 칸 |

그래서 엔진마다 두 가지를 **따로 등록해 둘 수 있고**, 어느 쪽으로 부를지만 고른다(예: 평소에는 계정 접속, 한도에 걸리면 API 접속으로 바꾸기 — 바꾸는 것은 사용자가 고를 때만).

- **구독 계정과 API 키가 섞이지 않게:** 구독 방식일 때는 실행 환경에서 API 키 환경 변수(\`OPENAI_API_KEY\`·\`CODEX_API_KEY\`·\`ANTHROPIC_API_KEY\`·\`XAI_API_KEY\`·\`GEMINI_API_KEY\` 등)를 지워 조용히 종량제로 바뀌지 않게 하고, API 방식일 때만 그 엔진에 키를 넘긴다(시험으로 고정).
- **어느 방식이 쓰였는지 보이게:** 대화 상단·카드에 "Codex · 개인 Plus 계정" / "Codex · API 키"처럼 표시, 한도 카드에서 바로 사용 방식을 바꿀 수 있다.
- **Claude 채널**은 사람이 띄운 창의 로그인을 쓰므로, \`ieon.ps1 claude\`가 고른 구독 계정(이어온 전용 위치)으로 창을 연다. 채널 방식은 구독 계정만(API 키는 새 세션 \`claude -p\`에서만).

### 3-2. 세 번째 접속: CLI는 그대로, AI 모델만 다른 곳으로(호환 주소 접속, 2026-11-12)

예: Upstage의 [Claude Code 연동](https://console.upstage.ai/ko/docs/integrations/claude-code) — \`claude-solar\` 명령이 **Claude Code 프로그램은 그대로 두고 그 아래 AI를 Upstage Solar(기본 \`solar-pro4\`)로** 돌린다(Upstage API 키, 그 Claude Code 세션에만 적용, 기존 \`~/.claude\` 설정 유지). OmniRoute 같은 라우터·회사 게이트웨이·로컬 모델도 같은 모양(그 CLI가 알아듣는 방식의 다른 주소 + 키).

| 경우 | 가능 여부 | 이어온의 처리 |
| --- | --- | --- |
| **새 세션을 처음부터 다른 모델로**(예: Claude Code + Solar로 만든 세션) | **가능**(Upstage 공식 안내, **신산님이 새 세션으로 실제로 써 봄** — 2026-11-12) | 엔진 사용 방식에 "호환 주소"(주소·키·모델 이름)를 두고, 그 방식으로 만든 세션은 계속 그 방식으로 이어 씀 |
| **같은 회사의 다른 계정으로 기존 세션 이어 쓰기**(Claude 세션 → 다른 Claude 계정) | 될 수도 있음(생각 과정 서명·암호화 조각 때문에 **불확실**) | A0 실측에서 확인된 경우만 |
| **같은 CLI에서 다른 모델로 기존 세션 이어 쓰기**(Claude 모델로 쌓은 Claude Code 세션 → 같은 폴더에서 Claude Code + Solar) | **대화가 이어진다 — 신산님 실사용 확인(2026-11-12, 작업 폴더 \`D:\\Project\\ieon-gateway\`에서 Claude Code로 쓰던 세션을 \`claude-solar\`로 이어 씀)**. 내부에서 생각 과정·도구 기록을 어떻게 처리하는지는 미확인 | 허용. 다만 A0에서 도구 호출·작업 모드·결과 품질을 시험 세션으로 확인 |

즉 **세션의 경계는 모델 회사가 아니라 CLI(작업 도구)다(신산님 실사용으로 확인).** Claude Code 세션은 Claude Code가(모델은 Claude·Solar 등 Claude Code가 받는 것), Codex 세션은 Codex CLI가 이어 쓴다. 세션마다 "어느 CLI·어떤 접속(계정·API·호환 주소)·어떤 모델"로 쓰였는지 기록해 화면에 보이고, **다른 CLI로 보내려 하면 거부**하고 이유를 카드로 알린다. 같은 CLI 안에서 접속·모델을 바꾸는 것도 **모든 조합에서 문제없다고 확인된 것은 아니다**(2026-11-12 신산님) — 그래서 **"확인된 조합" 목록에 있는 것만 허용**한다. 목록은 `CLI × 접속 방식 × 모델` 단위로, 시험 세션에서 ① 기존 세션 이어 쓰기 ② 질문·답 ③ 도구 호출·작업 모드 ④ 다시 원래 모델로 돌아와도 이어지는지를 확인한 것만 올린다. 목록에 없는 조합은 **새 세션에서만** 쓸 수 있고, 기존 세션에서 고르면 "이 조합은 아직 확인되지 않았어요"로 막는다. 바꿀 때는 "이 세션은 지금까지 ○○ 모델로 쓰였어요"를 한 번 보여 준다.

## 6-1. OpenMausBot은 어떻게 하나(2026-11-12, WSL-server `~/github/OpenMausBot` 0.1.153 소스 확인)

- **엔진마다 자기 로그인 폴더**로 실행한다(`CODEX_HOME`·`CLAUDE_CONFIG_DIR`·`GROK_HOME` 등, `server/engine-homes/layout.ts`). Codex는 "ChatGPT 요금제 엔진은 자기 CODEX_HOME에서 로그인"(`imported-skills.ts`), Claude는 **이름 붙인 계정 = 계정마다 `CLAUDE_CONFIG_DIR`**(`claude-accounts.ts`, 로그인은 Claude가, 지워도 폴더·로그아웃 안 건드림) → Desktop 계정과 무관(원칙 0과 같음).
- **세션은 사람·방·팀마다 따로 폴더, 로그인 파일만 공유** — 공유는 폴더끼리 **복사해 최신 것으로 맞추는** 방식(`sign-ins.ts`)이라 이어온 규칙(인증 파일 복사 금지)과 맞지 않음. OpenMausBot은 **자기가 만든 세션만** 이어 쓰므로 세션이 자기 폴더에 있어도 되지만, 이어온은 Desktop의 기존 대화를 이어 써야 해 반대 구조("세션은 Desktop 폴더, 로그인은 이어온 것")가 필요 → A0.
- **한도(`limit-failover.ts`):** 한도·로그아웃 때 미리 정한 예비 엔진으로 대화를 넘기고 풀리면 돌아옴. **같은 구독 엔진의 다른 계정으로 자동 전환은 막음**(주석: 한도를 피하려고 계정을 돌려 쓰면 약관 위반·계정 정지 위험), 다른 엔진·같은 엔진의 API 키(종량제)는 허용. 다른 엔진으로 넘길 때 대화를 어떻게 잇는지는 확인 못 함.
- **약관 확인(웹 검색, 2026-11-12):** OpenAI 이용약관에 "사용 한도·제한 우회 금지"와 계정 공유 금지(내 계정을 여러 기기에서 쓰는 것은 허용). 한 기사(2026-11-02)는 OpenAI가 같은 기기·결제 카드로 유료 구독을 겹쳐 쓰는 것을 막는다고 보도(공식 문서로 미확인). Anthropic 소비자 약관은 계정 공유 금지·보호 장치 우회 금지, 여러 계정을 직접 다룬 조항은 못 찾음. **신산님 결정:** 본인의 정상 계정 여러 개(개인·회사)를 본인이 쓰는 것은 공유가 아니고 계정 선택은 사용자 몫 → EA9. 이어온은 스스로 자동으로 계정을 바꿔 가며 쓰지 않는다(EA4).
