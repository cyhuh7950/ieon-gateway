## 1. 지금 화면이 어려운 이유 (2026-11-11, main `ae7d3ae`)

1. **화면이 둘로 갈려 있다.** "세션"(질문하는 곳)과 "봇 관리"(설정, 탭 9개: 이 PC·봇·메신저·카카오·세션 등록·새 세션·역할·기기·허브 보안·Codex·외부 프로그램). `src/pilot/web/index.html` 996줄 한 파일. 무엇을 어느 탭에서 하는지 사용자가 기억해야 한다.
2. **필수 단계가 많다.** 첫 질문까지 반드시 해야 하는 일:

   | 단계 | 지금 | 성격 |
   | --- | --- | --- |
   | 1 | Node.js 24 설치 | 필수 |
   | 2 | PowerShell에서 `install.ps1` | 필수(명령) |
   | 3 | 파일 탐색기에서 Codex 대화 ID 찾기(`rollout-…-<ID>.jsonl`) | 필수, 가장 어려움 |
   | 4 | 이 PC 탭 → 허용 목록에 ID·연결 방식·작업 폴더 | 필수 |
   | 5 | 세션 등록 탭에 같은 ID를 한 번 더(세션 ID `c_…`·이름·엔진) | 필수, 중복 입력 |
   | 6 | 이 PC 탭 → 실제 실행 켜기 | 필수 |
   | 7 | (메신저) 봇 토큰 → 메신저에서 아무 말 → 허용 요청에서 허용 → 1분 기다렸다 다시 | 필수 4동작 |
   | 8 | (Claude) 명령 창에서 `ieon.ps1 claude` | 필수(명령) |
3. **문제가 생겼을 때 이유가 대화에 없다.** "사용 중", "실제 실행 꺼짐", "PC 연결 끊김", "확인 필요"가 상태 문구로만 나오고, 해결할 곳은 다른 탭에 있다.

## 2. 원칙

1. **대화 화면이 홈이다.** 왼쪽은 연결한 대화 목록, 가운데는 대화. 설정은 그것이 필요한 자리(그 대화 옆 패널)에서 연다.
2. **기본값으로 바로 동작한다.** 사용자가 반드시 할 일을 화면마다 센다. 목표는 **설치 1번 + 대화 하나 고르기**. 메신저를 쓸 때만 **토큰 1칸 + 숫자 보내기**.
3. **고급 설정은 접어 둔다.** 연결 방식·대화 ID·권한·봇 이름·역할·허브·API 키·새 세션은 "고급"이나 설정(톱니)에 둔다.
4. **문제는 대화 안의 카드로 알린다.** 이유 + 해결 버튼이 그 대화에 나오고, 누른 결과가 카드에 기록으로 남는다(4절).
5. **구조와 안전 규칙은 그대로다.** 기존 세션 이어 쓰기(Codex `alternate`·`shared_server`, Claude 채널), 사용 중이면 거부, 결과 불명이면 자동 재전송 없음, 업무 대화 제외, 소유권 서버 검증, 로그에 원문 없음. **나오는 자리만 바뀐다.**
6. **기존 원칙 유지.** 명령·내부 토큰 입력 없음(W), 새 의존성 없음(바닐라 HTML·JS), 모바일 폭 동작, 탭·스크롤 최소화.

## 3. 화면 구성

| 영역 | 내용 | 지금 화면에서 옮겨 오는 것 |
| --- | --- | --- |
| 왼쪽 목록 | 위 `＋ 대화 연결`. 연결한 대화마다 엔진 표시·마지막 메시지 한 줄·주의 상태(사용 중·꺼짐·확인 필요) 배지 | 세션 화면의 목록, 세션 등록 탭 |
| 왼쪽 아래 | `메신저`(연결된 메신저 요약), 톱니 = 설정 | 봇·메신저·카카오 탭 입구 |
| 대화 상단 | 대화 이름, 엔진·PC 표시, **AI 응답 켜짐/꺼짐** 스위치, `연결 설정` | 이 PC 탭의 실제 실행 |
| 대화 본문 | 내 말(어디서 왔는지: 웹·텔레그램…)·진행 표시(접수 → 실행 → 완료)·답·카드 | 세션 화면 |
| 연결 설정 패널(오른쪽) | 기본: 엔진·PC·작업 폴더(자동)·상태·이 대화를 부를 수 있는 메신저. 고급: 연결 방식·권한·대화 ID·마지막 확인·연결 끊기 | 이 PC 탭 허용 목록, 세션 등록 |
| 설정(톱니) | 일반(PC 이름·버전·이어온 끄기), 밖에서도 쓰기(허브), 메신저 고급(봇·역할·허용 사용자·카카오), 내 프로그램 연결(API 키), 새 대화 만들기(새 세션), 허브 전용(보안·Codex 로그인) | 나머지 탭 전부 |

허브 화면도 같은 구성을 쓴다. 허브에서는 왼쪽 목록에 PC별로 묶어 보이고, PC 전용 항목(AI 응답 스위치·허용 목록)은 지금처럼 PC 화면에서만 바꾼다.

## 4. 카드

| 카드 | 언제 나오나 | 버튼 | 서버(기존·추가) |
| --- | --- | --- | --- |
| 첫 질문 확인 | 처음 질문을 보낼 때 한 번(결정 UD1) | 보내기 / 취소 | 기존 실제 실행 설정 |
| AI 응답 꺼짐 | 실제 실행이 꺼진 상태에서 보냄 | (PC 화면) 켜기 | `/v1/admin/local/device/live` |
| 사용 중 | `thread_busy`(Codex 앱에서 열려 있음) | 앱에서 닫았어요 → **다시 보내기**(사용자가 누를 때만) | 기존 |
| 확인 필요 | 결과 불명 | 원래 앱에서 확인하는 방법 + 기존 정리 버튼 | 기존(자동 재전송 없음) |
| PC 연결 끊김 | 허브에서 PC 오프라인 | 확인할 것(PC 켜짐·이 PC 화면 "연결됨") | 기존 기기 상태 |
| Claude 채널 꺼짐 | Claude 세션이 실행 중이 아님 | Claude 채널 열기(결정 UD6) | 추가 가능성 |
| 잠듦·보관 | 새 세션이 잠듦·보관 | 깨우기 / 꺼내기 | 기존 `/v1/sessions/…` |
| 메신저 새 사람 | 허용 목록에 없는 사람이 말을 검 | 허용 / 무시 | 기존 `/v1/admin/denied/allow` |
| 허브 Codex 로그인 필요 | 허브 새 세션인데 로그인 안 됨 | 로그인(기기 코드) | 기존 `/v1/admin/codex/login` |

카드를 누른 결과는 "✓ 다시 보냄 · 신산님 · 시각"처럼 카드 안에 남는다. 같은 동작은 연결 설정 패널·설정에서도 할 수 있다(카드는 입구일 뿐 별도 권한이 아니다).

**엔진 승인 카드(Codex·Claude가 명령 실행 승인을 묻는 것)는 이번 범위가 아니다.** 지금 이어온은 읽기 전용·작업 폴더 범위로만 실행해 승인 요청이 거의 없다. OpenMausBot식 승인 카드는 후속 검토.

**서버 추가(작게):**

1. `GET /v1/admin/local/threads` — 이 PC의 최근 Codex 대화(제목·마지막 사용·작업 폴더). **업무 대화는 서버가 처음부터 빼고 돌려준다**(조회 방법은 결정 UD2).
2. `POST /v1/admin/connections` — "대화 연결" 한 번으로 허용 목록 추가 + 세션 등록(지금의 4·5단계를 하나로). 세션 ID·이름은 자동(대화 제목).
3. 메신저 주인 등록 코드 — 토큰 저장 뒤 6자리 숫자(10분, 1회용, 틀린 시도 제한) 발급, 봇이 그 숫자를 받으면 보낸 사람을 그 봇의 허용 사용자로 넣고 답한다(결정 UD3).
4. 허브 "PC 연결 링크" — 허브가 1회용 링크를 만들고, PC에서 열면 지금의 짝맺기(코드 확인·승인)를 자동으로 끝낸다.
5. 대화별 카드 목록 `GET /v1/conversations/:id/cards`와 목록 배지 개수(ieun-agent와 같은 방식, 소유권 검증은 기존과 같음).

## 5. 처음 설정 — 3단계 안내

ieun-agent는 "안내 도우미 대화"로 했지만, 이어온의 대화는 사용자의 엔진 세션이라 도우미 대화를 끼우지 않고 **화면 가운데 3단계 카드**로 한다(시안 ①).

1. **확인:** Codex·Claude Code 로그인 상태를 자동 확인해 "준비됨"으로 보여 준다. PC 이름은 자동(고급에서 변경).
2. **대화 고르기(유일한 필수 선택):** 최근 Codex 대화 목록에서 하나를 누른다. 고급: 새 대화로 시작·대화 ID 직접 넣기.
3. **준비됨:** "메신저로도 쓰기", "밖에서도 쓰기(허브)"는 선택. `대화 열기`로 바로 메인 화면.

## 7. 세 가지 형태 — 웹·PC 창·모바일

화면 코드는 하나다. 형태마다 다른 것은 어떻게 열리는가뿐이다.

| 형태 | 지금 | U 이후 |
| --- | --- | --- |
| 웹(브라우저) | 있음(데스크톱 폭 위주) | 대화 중심 화면 |
| **PC 창** | 바로 가기가 브라우저 탭으로 열림 | 결정 UD5 — 추천: **Edge 앱 창**(`msedge --app=http://127.0.0.1:28760`). Windows 11에 Edge가 기본이라 새 의존성이 없고, 자기 창·작업 표시줄 아이콘이 생긴다. 없으면 지금처럼 브라우저 탭 |
| **모바일** | 허브 주소를 휴대폰 브라우저로 열 수 있음, 배치는 데스크톱용 | 같은 화면이 휴대폰 폭에서 목록 ↔ 대화 전환, 버튼 44px 이상. 홈 화면 추가(PWA)는 U7에서 |

설치 파일(.exe, Node 포함)은 화면과 따로 판단한다(결정 UD7). 그때까지 설치는 지금의 `install.ps1` 한 번이다.

## 10. 위험

- **기능 누락:** 예전 화면 항목이 새 화면에 없을 수 있다 → U6 점검표, U8까지 `/classic` 유지.
- **업무 대화 노출:** 대화 목록이 생기면 업무 대화가 섞일 위험 → 서버가 목록을 만들 때 먼저 빼고, 응답·로그에 없음을 시험으로 고정(UD2 승인 전에는 목록 기능을 켜지 않음).
- **기본 켜짐과 비용:** 실제 실행이 기본 켜짐이면 메신저 질문이 바로 모델을 호출 → 첫 질문 확인·상단 스위치·메신저는 주인만 허용.
- **카드 남발:** 카드가 많으면 다시 복잡 → 처리할 카드는 위로 모으고, 처리한 카드는 한 줄로 접음.
- **index.html 크기:** 996줄 한 파일 → U1에서 화면별 작은 파일로 나눌지 착수 때 결정(같은 서버가 정적 제공, 의존성 없음).
- **허브·PC 화면 어긋남:** 화면 코드는 하나로, 차이는 PC 전용 항목의 표시 여부만.
