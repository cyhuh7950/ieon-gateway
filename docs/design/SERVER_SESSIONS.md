# 서버 세션 — 서버에서 CLI 엔진을 돌리고, 허브에서 서버·PC 대화를 고르기(SV)

기준: 2026-11-14 · 상태: **설계(코드·서버 변경 없음).** 구현은 단계마다 신산님 승인 후.
관련: [INSTALL_MODES](INSTALL_MODES.md)(설치 모드 3가지), [ENGINE_ACCOUNTS](ENGINE_ACCOUNTS.md)(엔진 계정 분리), [WORKSPACES](WORKSPACES.md)(작업공간·차단 수준), [HUB_AND_PC_PROFILES](HUB_AND_PC_PROFILES.md).

## 0. 요청(2026-11-14 신산님)

- 설치형(①)을 **서버에** 설치하면, 서버에 **CLI 엔진(Codex CLI·Claude Code CLI)** 을 두고 그 **CLI 대화 이력을 서버에 저장**해 이어 쓰고 싶다.
- 허브형(②)은 **서버의 CLI 대화**와 **로컬 PC의 대화** 가운데 **골라서** 쓰고 싶다.
- 이유: **로컬 PC를 늘 켜 두지 않아도** 법률봇 같은 서비스가 돌아가게.

**신산님 결정(같은 날):**
1. 다른 사람(고객)이 쓰는 서비스는 **당연히 API형**으로 한다(개인 구독 로그인으로 남에게 서비스하지 않음).
2. 개발 중에는 서버 자원을 이유로 막지 않는다. **운영할 때 권장 사양을 제시**한다.
3. 보안(로그인 정보가 서버에 남음 → 허브 접속 제한·직원별 폴더 분리 함께) — 동의.

## 2. 설계

### 2-1. 한 이미지, 두 쓰임

허브 이미지(서버·연결부·메신저를 한 컨테이너에서)는 이미 "서버에서 엔진을 돌리는 이어온"이다. 그래서 **서버 설치형(①)과 허브형(②)을 같은 리눅스 이미지**로 만들고 설정으로만 나눈다.

| | 서버 설치형(① 서버) | 허브형(②) |
| --- | --- | --- |
| 엔진 실행 위치 | 서버만 | 서버 + 연결된 PC들 |
| PC 연결 | 끔(PC 연결 링크·기기 화면 숨김) | 켬 |
| 카카오 | **중계 없이 바로**(서버 자체가 공개 주소) | 지금처럼 허브가 받음 |
| 고르는 대화 | 서버 대화 | 서버 대화 + PC 대화 |

- 나중에 ①→②로 바꾸려면 설정에서 "PC 연결 켜기"만(데이터 그대로). 섞어 쓰기 금지 원칙(INSTALL_MODES)은 그대로: 한 메신저 봇은 한 곳에만 연결.

### 2-2. 서버 대화(CLI 이력) 저장·고르기

- **저장:** 엔진 저장 폴더를 모두 데이터 폴더 아래에 둔다 — Codex `/data/codex`(이미), Claude `/data/home/.claude`(`HOME=/data/home`, 이미 설정). 컨테이너를 지우고 다시 만들어도 대화가 남는다. 백업은 `hub/data` 한 폴더.
- **서버에서 사람이 CLI로 직접 이어 쓰기:** 같은 저장 폴더를 쓰는 CLI를 서버에서 연다 — 도우미 명령 `deploy/hub/ieun.sh tui codex|claude [대화 ID]`(안에서 `docker exec -it ieun-relay …`). 이렇게 만든 대화도, 이어온이 만든 대화도 같은 목록에 나온다(같은 저장 폴더). 명령 창이 필요한 사람만 쓰는 고급 기능이고, 기본은 웹에서 고르기.
- **고르기(웹):** 허브·서버 설정 → "서버 대화" 칸 — PC의 "대화 연결"(U3)과 같은 화면. 서버 Codex 공식 `thread/list`로 목록(제목·폴더·최근 시간만, 본문 안 읽음), 골라서 **서버 허용 목록**에 넣음. 업무 대화 ID는 서버에서도 똑같이 3중 제외(AGENTS UD2).
- **이어 쓰기 방식:** 서버도 PC와 같은 `alternate`(질문마다 같은 대화를 재개하고 반납). 사람이 서버 CLI로 그 대화를 열어 두었으면 **사용 중으로 거절**(자동 대기·재전송 없음). 리눅스에서의 사용 중 판별은 SV0에서 실측.
- **Claude 서버 기존 대화:** 서버에서는 이어온이 Claude 프로세스를 직접 관리하므로 `claude -p --resume <ID>`로 이어 쓴다. 조건: 그 세션을 사람이 서버 CLI로 열어 두지 않았을 때만 보냄, 답의 세션 ID가 다르면(복사본이 생김) **결과 불명**으로 잠그고 알림(지금 Claude 새 세션 어댑터와 같은 규칙) — "같은 세션, 복사본 대체 금지" 원칙 유지. PC 쪽 Claude는 지금처럼 채널(바꾸지 않음).

### 2-3. 허브에서 서버·PC 고르기

- 대화 목록 묶음에 **"서버"** 를 더한다: `서버(허브)` · `신산 PC` · `다른 PC` … (지금의 PC별 묶음에 한 줄 추가).
- **AI 직원(예: 법률봇)마다 어느 세션인지 고른다** — 서버 세션이든 PC 세션이든 한 세션. 직원 카드에 "서버 · 늘 켜짐" / "신산 PC · PC가 켜져 있을 때만" 표시.
- **자동 전환은 하지 않는다.** PC가 꺼졌다고 서버 세션으로 몰래 넘기면 다른 대화에 답하는 것이므로(같은 세션 원칙 위반) "PC 연결 끊김"을 알리고 끝. 늘 답해야 하는 직원은 처음부터 서버 세션에 붙인다.
- 메신저 `/sessions`·`/status`에도 "서버"/"PC 이름"이 이미 나오는 자리(R1의 PC 이름 표시)에 그대로.

### 2-4. 개인용(구독)과 서비스용(API) — 신산님 결정 1

| | 개인용 | 서비스용 |
| --- | --- | --- |
| 누가 쓰나 | 주인(신산님)만 | 주인 밖의 사람(고객·직원·공개 채널) |
| 엔진 계정 | 구독 로그인(Codex 기기 코드, Claude 로그인) | **API 키 계정**(Codex `--with-api-key` 방식, Claude `ANTHROPIC_API_KEY` 방식) |
| 요금 | 구독 한도 | 사용량 과금(공급자 청구) |

- **계정 종류를 둔다:** 지금의 계정(ENGINE_ACCOUNTS)에 `종류: 구독 | API`. API 계정은 웹에서 **신산님이 공급자 화면에서 발급한 키를 한 번 붙여 넣기**(가려진 칸, 다시 보여 주지 않음, 서버 데이터 폴더에 주인만 읽는 파일로, 로그·응답에 원문 없음). 키를 만들거나 옮기는 일은 이어온이 하지 않는다.
- **서버가 지킨다(사람 실수 방지):** AI 직원이나 봇이 주인 밖의 사람을 받도록 설정되면(허용 사용자에 다른 사람, 공개 카카오 채널, 여러 사람 방) 그 직원의 세션은 **API 계정만** 쓸 수 있다. 구독 계정 세션이면 질문을 보내지 않고 "서비스용 직원은 API 계정이 필요해요"로 거절(설정 화면에도 같은 경고).
- **사용량 한도:** API 계정마다 하루·한 달 한도(질문 수·토큰) — 넘으면 거절하고 주인에게 알림. 사용량은 이미 있는 토큰 기록(usage)에 계정별 합계.
- 공용 서비스(③, M2~M4)도 이 규칙을 그대로 쓴다.

### 2-5. 보안 — 신산님 결정 3

- 서버에 남는 것: 엔진 로그인·API 키·대화 이력. 모두 `hub/data` 아래, 컨테이너 사용자(1001)만 읽음. 로그에 원문·키 없음(지금 원칙).
- 허브 웹 접속 제한(허브 보안 탭)은 서버 대화를 켜기 전 **필수**(꺼져 있으면 서버 대화 켜기 거부).
- **직원별 폴더 분리(WORKSPACES)** 를 서버에도: 직원마다 개인 폴더·공유 폴더, Codex `writableRoots`, Claude `--restricted`+`--add-dir`.
- 리눅스라서 좋아지는 점: Claude OS 샌드박스(명령의 읽기·쓰기까지)를 쓸 수 있음 — **단 Docker 안에서 Codex·Claude 샌드박스가 실제로 켜지는지는 SV0에서 실측**(컨테이너 안에서는 커널 기능 제한으로 샌드박스가 꺼질 수 있음. 안 되면 컨테이너 자체가 경계이고 화면에 "정리만"으로 정직하게 표시, 직원별 격리가 꼭 필요하면 직원별 컨테이너를 선택지로).
- 법률봇처럼 민감한 서비스의 고객 질문은 지금처럼 보관 설정을 따르고, 처리방침에 서버 보관을 적는다(M4).

### 2-6. 권장 사양 — 신산님 결정 2

개발 중에는 자원으로 막지 않는다(지금 서버에서 그대로 개발·시험). 운영용으로 설명서에 아래를 **권장 사양**으로 싣고, SV 구현 뒤 실제 측정값으로 고친다.

| 쓰임 | 동시 질문 | CPU | 메모리 | 디스크 |
| --- | --- | --- | --- | --- |
| 개인(서버 설치형, 엔진 1~2개) | 1~2 | 2코어 | 4GB | 20GB |
| 소규모 서비스(법률봇 등 직원 몇 명) | 3~5 | 4코어 | 8GB | 40GB |
| 그 이상 | 5+ | 동시 질문 1개당 약 1코어·1~1.5GB 추가 | | 대화 보관량에 맞춰 |

- 근거(추정, 측정 전): Codex CLI·Claude Code CLI는 질문 하나에 프로세스 하나(Node 기반, 수백 MB)씩 뜬다.
- 컨테이너 `mem_limit`·`pids_limit`은 고정값 대신 설정(`.env`)으로 바꿀 수 있게 하고, 동시 질문 수 제한(초과는 줄 세우지 않고 "바빠요" 거절 — 자동 재전송 없음 원칙)을 둔다.

### 2-7. SV0 실측 결과(2026-11-14, sinsan-server Ubuntu 22.04·arm64·Docker 29.1.3, codex-cli 0.165.0 · Claude Code 2.1.325)

허브 컨테이너(`ieun-relay`, 허브 자신의 Codex 로그인) 안의 시험 폴더 `/data/sv0-test`(끝나고 지움)와 일회용 시험 컨테이너(`--rm`)만 씀. 모델 호출 **Codex 2회**(허브 계정)·Claude 0회. 근거 [`docs/validation/sv0-server-20261114.json`](../validation/sv0-server-20261114.json).

| 시험 | 결과 | 설계에 주는 뜻 |
| --- | --- | --- |
| 서버 대화 목록 `thread/list`(출처 조건 없음) | 이어온이 만든 허브 새 세션(출처 `exec`)은 **안 나옴**, 서버 CLI 화면으로 연 대화(출처 `cli`)는 나옴 | 목록에 `sourceKinds`(cli·vscode·exec·appServer)를 정해 줘야 함. **PC의 U3 대화 목록도 같은 이유로 SDK·exec로 만든 대화가 빠져 있을 수 있음** — SV1에서 함께 고침 |
| 서버 CLI 화면(TUI)으로 대화를 열어 둔 동안 이어온 잠금 검사(`lock-probe` Linux `/proc/locks`) | **WRITER_LOCK_CONFLICT**(사용 중) → 화면이 닫힌 뒤 **NO_WRITER_LOCK** | 지금까지 미검증이던 리눅스 사용 중 판별이 실제로 동작 → 서버도 `alternate` 그대로 |
| Docker 안 Codex 샌드박스(`workspace-write`) | **모든 명령이 실패**(`bwrap: No permissions to create a new namespace`) — 밖 쓰기·읽기뿐 아니라 작업 폴더 안 쓰기도 안 됨(막히는 쪽으로 실패) | ⚠ **지금 허브 새 세션도 명령을 하나도 못 돌린다**(글 답만 됨). 원인은 호스트가 아니라 Docker 기본 보안(seccomp·AppArmor·/proc 가림) — 호스트는 사용자 이름공간 허용(`unprivileged_userns_clone=1`, AppArmor 제한 0) |
| 일회용 컨테이너에서 Codex 내장 bwrap만 시험 | 기본: 실패 / seccomp만 풂: 실패 / seccomp+AppArmor 풂: `/proc` 마운트 실패 / **seccomp+AppArmor+systempaths 풂: 성공** | Docker 안에서 엔진 샌드박스를 켜려면 컨테이너 보안 세 가지를 풀어야 함 → 아래 결정 필요 |
| Claude Code CLI 설치(일회용 컨테이너, npm) | 됨(2.1.325) | 이미지에 넣을 수 있음 |
| Claude 헤드리스 로그인 `claude auth login` | 주소를 보여 주고 "Paste code here" — **주소 열기 → 로그인 → 코드 붙여 넣기**. `--console`은 API(사용량 과금) 로그인 | 웹에서 Codex 기기 코드처럼 처리 가능(주소 보여 주기 + 코드 칸) |
| Codex API 키 | `codex login --with-api-key`(키를 표준 입력으로) 있음 | SV3에서 웹 붙여 넣기 → 표준 입력으로만 넘김 |

**미측정:** Claude 실제 호출·`--resume` 복사본 조건(신산님 서버 Claude 로그인 필요), API 키 호출(신산님 키 필요), Docker 안 Claude 샌드박스(같은 bwrap 방식이라 같은 제약일 것으로 봄 — 추정), seccomp를 통째로 풀지 않고 필요한 것만 여는 좁은 설정.

### 2-8. 결정 A — 컨테이너가 경계(2026-11-14 신산님 "A 컨테이너 경계")

**핵심: 서버의 "엔진 칸"을 PC 한 대처럼 만든다.** 지금 PC는 `server.mjs`(허브 연결 모드) + 연결부(`connector.mjs`)이고 허브와 짝지어(pairing) 붙는다. 이걸 리눅스 컨테이너 하나에 그대로 넣으면, 허브 입장에서는 **PC가 하나 더 붙은 것**과 같다.

| 항목 | 엔진 칸(컨테이너) |
| --- | --- |
| 무엇 | 허브 이미지와 같은 코드로 `server.mjs`(허브 연결 모드)+연결부만 돌리는 컨테이너. 메신저·공개 포트 없음 |
| 하나에 무엇이 | 직원 하나(예: 법률봇) 또는 서비스 하나 — 자기 `/data`(엔진 로그인·API 키·대화 이력·작업 폴더) |
| 허브와 연결 | 지금의 PC 짝짓기·허브 연결을 그대로 씀. 처음 띄울 때 허브가 1회용 초대를 넣어 자동으로 짝지음(사람이 토큰을 다루지 않음) |
| 허브 화면 | 목록에 PC처럼 보임: `서버 · 법률봇`. 허용 목록·AI 응답·작업 폴더·계정은 지금 "허브 화면에서 PC를 골라 바꾸기"(A2-d)로 같은 화면에서 |
| 엔진 샌드박스 | 칸 안에서는 끔(Codex `danger-full-access`, Claude는 `--restricted`를 유지하되 Bash 허용 가능) — **칸 자체가 경계**. 화면 차단 수준: "다른 직원: 차단(컨테이너)" |
| 컨테이너 보안 | 허브와 같이 `cap_drop: ALL`·`no-new-privileges`·읽기 전용 이미지·자기 `/data`만 연결. Docker 보안을 풀지 않음 |
| 네트워크 | 칸 전용 네트워크(`ieun-engines`)에 허브와 칸만. 같은 서버의 다른 서비스(DB 등)와 안 붙음. 바깥(OpenAI·Anthropic)만 나감 |
| 대화 이력 | 칸의 `/data`(서버 폴더 `engines/<이름>/data`)에 남음. 사람이 서버에서 그 칸의 CLI를 열 수도 있음(`ieun.sh tui <이름> codex|claude`) |
| 크기 | 칸마다 `mem_limit`·`pids_limit`(설정으로), 쉬고 있을 때는 Node 프로세스 둘(수십 MB) |

**칸 만들기·지우기:** 허브 컨테이너에 Docker 제어권(소켓)을 주지 않는다(주면 서버 전체 권한과 같음). 그래서 칸은 **서버 쪽 한 번 명령**으로 만든다: `deploy/hub/ieun.sh engine add 법률봇` → 폴더 만들기·compose에 칸 추가·띄우기·허브와 자동 짝짓기. 개발·운영 중에는 Claude Code가 배포 때 함께 처리하고(신산님이 명령 창을 쓰지 않음), 설명서에는 운영자용으로 적는다. 웹 버튼으로 칸 만들기는 나중에 별도 판단(제어권을 좁게 주는 방법이 있을 때).

**좋은 점:** ① 새 연결 방식을 만들지 않음 — 허브·PC 사이 검증된 길(소유권 확인·결과 불명 처리·자동 재전송 없음)을 그대로 씀 ② PC형·허브형 같은 기능 원칙이 저절로 지켜짐 ③ 직원끼리 읽기까지 나뉨(WS0에서 Codex·Bash로는 못 막던 것).

**지금 허브 새 세션:** 허브 컨테이너 안이라 명령은 실패(SV0)·글 답만. 그대로 두되 화면에 "글 답만"을 표시하고, 명령이 필요한 일은 엔진 칸으로 안내. 나중에 기본 엔진 칸("서버 기본")으로 옮길지 SV1 뒤에 판단.

### 2-14. SV4 구현 기록 (2026-11-17, 신산님 "SV4 진행해", 모델 0, 미배포)
