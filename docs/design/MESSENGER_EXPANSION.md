# 메신저 넓히기 — 라인 추가, 이어온 앱(회사 전용)

기준: 2026-11-12. 상태: **승인 2026-11-12(신산님 "추천안 승인"). AP0은 신산님 답.** C절 추천안이 결정이다. 구현은 단계마다 신산님 승인 후. 코드·서버 변경 없음. 승인된 결정만 구현한다.
관련: [INSTALL_MODES](INSTALL_MODES.md)(설치 모드 3가지·여러 사용자), [MULTI_BOTS](MULTI_BOTS.md)(여러 봇), [UI_CHAT_FIRST](UI_CHAT_FIRST.md)(새 화면·메신저 창·주인 등록 숫자).

## A. 라인(LINE) 추가

### A1. 라인은 카카오와 같은 종류다

| | 텔레그램·디스코드·슬랙 | 카카오톡·**라인** |
| --- | --- | --- |
| 메시지를 받는 방식 | 이어온이 메신저 서버로 먼저 접속해 가져옴 | **메신저가 우리 공개 주소로 보내 줌(webhook)** |
| 공개 서버 | 필요 없음 | **필요**(설치 모드 ①은 중계, ②③은 허브가 받음) |

그래서 라인은 지금의 카카오 길(공개 중계 `src/relay/`·허브 내장 중계 → 메신저 실행기)을 그대로 따른다.

### A2. 구성

- **받기:** 공개 서버에 `/line/webhook/<비밀 경로>`. 라인이 붙여 보내는 서명(`X-Line-Signature`, 채널 비밀 값으로 만든 HMAC-SHA256)을 확인하고 맞지 않으면 버린다. 질문 원문은 기록하지 않는다(카카오와 같음).
- **답하기:** 라인은 받은 메시지마다 한 번 쓸 수 있는 "답장 표"(reply token)를 주는데 **쓸 수 있는 시간이 짧다.** AI 답은 길게 걸리므로 ① 바로 "받았어요"(또는 1:1 대화의 "입력 중" 표시)로 답하고 ② 실제 답은 "보내기"(push message)로 보낸다. **보내기는 라인 공식 계정 요금제의 월 무료 건수에 들어간다** — 건수·시간 한도는 구현 전에 공식 문서로 다시 확인(지금 기억으로 단정하지 않음).
- **필요한 값:** 채널 액세스 토큰, 채널 비밀 값(Line Developers 콘솔). 새 화면 메신저 창에 "라인"을 추가하고 **2칸**(슬랙과 같은 모양), webhook 주소는 카카오 스킬 URL처럼 "복사"로 준다.
- **허용:** U5의 6자리 숫자로 주인 등록(그대로). 명령어(`/sessions`·`/use`·`/status`·`/help`…)도 같은 메신저 연결부(bridge)를 쓴다.
- **그룹:** 처음에는 1:1 대화만. 그룹·여러 사람 대화방은 라인이 그룹 안에서 부를 때 규칙이 달라 다음 단계.

### A3. 단계(안)

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| L1 | 라인 받기(서명 확인)·답하기(받았어요 → 보내기)·메신저 창 라인 2칸·webhook 주소 복사 | 서명 틀림 거절·원문 기록 없음·답 흐름 대역 시험 |
| L2 | 실제 라인 공식 계정으로 확인(신산님이 계정 만들기·토큰은 메신저 창에 붙여 넣기) | 실제 1:1 대화로 질문·답·숫자 등록 |

## B. 이어온 앱 — 신산님과 직원이 쓰는 회사 전용 메신저 앱

### B1. 무엇인가(2026-11-12 신산님 답)

- **대화 상대는 내 Codex·Claude 세션뿐**이다. 사람끼리 대화하는 메신저가 아니다. 회사(신산님과 직원)의 각 사람이 자기에게 허용된 AI 세션과 대화한다.
- **휴대폰·PC·웹 브라우저 모두**에서 쓴다. 휴대폰은 **구글 플레이·앱스토어에서 받는 진짜 앱**.
- **텔레그램·라인 가입이나 봇 토큰 없이 바로** 쓴다. 이어온 앱이 이어온 서버에 직접 붙는다.
- **붙는 서버는 설치 모드를 따른다**: ① 내 PC, ② 내 허브, ③ 공용 서비스(INSTALL_MODES).

즉 바깥 메신저(텔레그램·디스코드·슬랙·카카오·라인)를 거치는 대신 **이어온 전용 앱**이 하나 더 생기는 것이다. 화면은 지금의 새 화면(대화 목록 → 대화, 카드, AI 응답 상태)을 그대로 앱으로 옮긴 모양이다.

### B2. 사람과 권한

- **사람:** 신산님(관리자) + 직원. 직원 계정은 가입 신청 → 신산님 승인(INSTALL_MODES IM6과 같은 바탕).
- **세션별 허용:** 직원이 신산님의 Codex·Claude 세션에 질문하면 **신산님 계정의 사용량**이 쓰이고 신산님 작업 세션에 글이 남는다 → 세션마다 "누가 쓸 수 있나"를 정한다(기본: 신산님만). 직원별 하루 질문 수 한도.
- **그대로인 안전 규칙:** 업무 대화 제외, 사용 중이면 거부, 결과 불명이면 자동 재전송 없음, 이 PC 안전 설정은 PC 화면에서만, 로그에 원문 없음. 한 세션을 여러 사람이 쓰면 "처리 중"(한 번에 한 질문) 규칙이 그대로 적용된다.

### B3. 설치 모드별로 앱이 붙는 곳

| 모드 | 앱이 붙는 곳 | 직원 사용 | 주의 |
| --- | --- | --- | --- |
| ① 내 PC만 | 이 PC 서버 | **어려움** | 휴대폰이 집 밖에서 PC에 닿으려면 길이 필요 — Tailscale(지금 있는 고급 기능) 또는 공개 중계를 앱용으로 넓힘(결정 AP4). 직원은 사실상 ②③ |
| ② 내 허브 | 내 허브 주소 | 됨 | 허브에 사람 여러 명 바탕 필요 |
| ③ 공용 서비스 | 공용 서비스(내 회사 공간) | 됨 | 공용 서비스가 회사 단위로 공간을 나눠야 함 |

### B4. 앱을 처음 연결하기(토큰 없이)

- **② ③:** 앱에서 서버 주소를 고르거나(③은 고정) 로그인. 계정이 없으면 앱에서 가입 신청 → 승인 대기.
- **① 또는 빠른 연결:** PC·허브 화면에 **QR 코드(또는 6자리 숫자)**를 띄우고 앱으로 찍으면 그 기기가 연결된다(U5 주인 등록 숫자·U6 PC 연결 링크와 같은 1회용·10분 방식). 기기마다 따로 끊을 수 있다(설정 → 내 기기).
- 앱이 받는 기기 열쇠는 앱 안의 안전한 저장소(휴대폰 보안 저장소)에만 두고 화면·로그에 내지 않는다.

### B5. 알림

- 답이 오면 앱을 닫아 둬도 알림. 휴대폰 알림은 구글·애플 알림 서버를 반드시 거친다 → **알림 내용에 질문·답 원문을 넣지 않고 "○○ 세션에 답이 왔어요"만**(결정 AP3). 앱을 열면 서버에서 직접 받는다.
- 웹 브라우저·PC는 웹 푸시(서비스 워커는 알림 전용, 화면 캐시 없음 유지).

### B6. 프로그램을 만드는 방법

| 방법 | 장점 | 비용·제약 |
| --- | --- | --- |
| **Expo(React Native) 한 코드로 안드로이드·아이폰·웹** | 한 번 만들어 세 곳, 스토어 빌드·심사 제출·알림을 Expo 도구가 돕는다 | 새 의존성(지금 서버는 의존성 최소) → **앱은 별도 폴더(`app/`)로 두고 서버와 분리** |
| 안드로이드·아이폰 따로(Kotlin·Swift) | 각 OS 기능을 가장 잘 씀 | 두 번 만들기, 유지 비용 큼 |
| 웹 앱(PWA)만 | 지금 화면 그대로 | 스토어 앱이 아님(요청과 다름) |

추천: **Expo로 휴대폰 앱(스토어)과 웹을 함께**(AP1). PC는 처음엔 **지금의 Edge 앱 창(U7)**, 스토어형 PC 앱(Microsoft Store·설치 파일)은 UD7(설치 파일)과 함께 나중에 판단.

**스토어 배포에 필요한 것(신산님이 직접):** 구글 플레이 개발자 계정(한 번 결제), 애플 개발자 프로그램(해마다 결제), 앱 이름·아이콘·개인정보 처리방침 주소(스토어 심사 필수), 심사용 시험 계정. 계정 만들기·결제·서명 열쇠 보관은 신산님이 한다(우리 원칙: 로그인·결제는 직접).

### B7. 서버에서 새로 필요한 것

1. **사람 여러 명 바탕:** 계정·가입 신청·승인·로그인·사람별 분리 — INSTALL_MODES M2와 **같은 것**(한 번만 만든다).
2. **앱 기기 연결:** QR·숫자 1회용 연결, 기기 목록·끊기, 기기 열쇠는 해시만 저장(지금 PC 기기와 같은 방식).
3. **앱용 API:** 지금 웹이 쓰는 API(대화 목록·카드·질문·결과)를 그대로 쓰되, 새 답을 바로 받는 길(SSE)과 알림 등록을 더한다.
4. **세션별 허용·직원별 한도.**
5. **알림 보내기:** 답이 끝나면 그 세션을 쓰는 사람의 기기로 "답이 왔어요"(원문 없음).

### B8. 단계(안)

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| AP-1 | 사람 여러 명 바탕(= INSTALL_MODES M2), 세션별 허용·직원별 한도 | 사람별 소유권·허용 시험(허용 안 된 직원은 질문 거부, 남의 대화가 어디에도 안 나옴) |
| AP-2 | 앱 기기 연결(QR·숫자), 기기 목록, SSE로 새 답 바로 받기 | 대역 시험 |
| AP-3 | Expo 앱: 로그인·QR 연결, 대화 목록·대화·카드, 질문 보내기(웹 화면과 같은 규칙) | 안드로이드 에뮬레이터·웹에서 시험, 실제 휴대폰(신산님) |
| AP-4 | 알림(원문 없음), 아이폰 빌드 | 실제 알림(신산님) |
| AP-5 | 스토어 제출(신산님 계정), 개인정보 처리방침 | 심사 통과 |

## D. 위험

- **범위:** 스토어 앱은 서버와 별개의 제품 하나를 더 만드는 일이다(빌드·심사·업데이트·OS 버전 대응). 사람 여러 명 바탕을 먼저 단단히, 단계마다 승인.
- **보안:** 직원 계정·앱 기기가 생기면 분리 실수가 곧 신산님 작업 세션 노출 → 모든 API 소유자·허용 검사 시험, AI 세션 기본 신산님만, 기기 열쇠는 해시만·기기별 끊기.
- **비용:** 직원의 AI 질문은 신산님 Codex·Claude 사용량, 스토어 개발자 계정 비용, 라인 보내기는 라인 요금제 건수.
- **의존성:** 앱(Expo)은 의존성이 많다 → 서버 코드와 폴더를 나누고, 설치·업데이트는 승인 범위에서만.
- **스토어 심사:** 개인정보 처리방침·계정 삭제 기능·시험 계정 요구 → AP-5 전에 준비.
