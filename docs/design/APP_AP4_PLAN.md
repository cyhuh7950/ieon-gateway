## 1. 알림 원칙(모든 곳 같음)

- 알림 글은 **"○○(AI 직원 이름)가 답했어요" / "○○가 허락을 기다려요" / "○○에게 보내지 못했어요"**만. 질문·답·명령 원문은 넣지 않는다(휴대폰 알림은 구글 서버를 거침).
- 그 화면을 보고 있으면 알림을 띄우지 않는다(이미 보임). 알림을 누르면 그 대화가 열린다.
- 알림 켜기·끄기는 기기마다(기본: PC 앱 켜짐, 웹 화면은 사용자가 켤 때 브라우저가 허용을 물음).

## 2. 단계

| **AP-4b** | **안드로이드 푸시(Firebase)** · **웹 푸시**(탭을 닫아도 오는 브라우저 알림, 서비스 워커는 알림 전용) | 아래 3절 | 실제 휴대폰·실제 서버(신산님 확인) |

## 3. AP-4b에 필요한 것(승인 대상)

**신산님 몫(한 번):**
1. [Firebase 콘솔](https://console.firebase.google.com)에 구글 계정으로 로그인 → 프로젝트 만들기(이름 예: ieon).
2. 안드로이드 앱 추가 — 패키지 이름 `kr.sinsan.ieon` → `google-services.json` 받기 → 이 PC의 `D:\Project\ieon-gateway\.local\firebase\` 폴더에 넣기(앱을 만들 때만 씀, 저장소에 올리지 않음).
3. 프로젝트 설정 → 서비스 계정 → "새 비공개 키 생성"으로 키 파일 받기 → **허브 웹 화면 설정에 올리기**(새 칸 "휴대폰 알림 키", 값은 다시 보여 주지 않음). 파일을 열거나 복사해 붙일 필요 없음.

**제 몫:**
- 설치(`app/` 안): `@capacitor/push-notifications`(Capacitor 공식) — 앱을 만들 때 구글 빌드 부품(google-services gradle 플러그인·Firebase 메시징)을 내려받음.
- 서버: 앱 기기마다 알림 주소(FCM 토큰) 저장, 답·허락 대기·실패 때 FCM으로 "○○가 답했어요" 보내기(서버 키로 구글에 로그인 — 키 원문은 로그·화면에 없음, 새 부품 없이 node 기본 기능).
- 웹 푸시: 서버가 웹 푸시 키를 스스로 만들어 보관(사용자 입력 없음), 브라우저 알림 서버(구글·모질라·MS)로 원문 없는 알림.
- 배포: 서버 수정은 허브·이 PC 적용 승인.

## 3-1. AP-4a 결과(2026-11-14, 새 설치 0·계정 0·모델 0)

- **PC 앱 알림:** 새 소식(SSE)으로 창을 보고 있지 않을 때 Windows 알림. 문구는 이름 + 정해진 말만(이/가 맞춤), 같은 일은 한 번만, 누르면 창을 앞으로 + 그 대화. PC 앱 권한은 알림만 허용(나머지 거절). 첫 화면 아래 🔔 켜기·끄기(기본 켜짐).
- **웹 화면 알림:** `EventSource('/v1/events')`(로그인 쿠키), 왼쪽 아래 🔕 알림 → 브라우저 허용, 탭을 보고 있지 않을 때만. PC형·허브형 같은 화면.
- **서버:** 새 소식 응답에 `x-accel-buffering: no`(허브 앞단이 모아 두지 않게). 그 밖 변경 없음.
- **PC 설치 파일:** `npm run package:desktop` → `app/dist/desktop/ieon-setup-0.1.0.exe`(약 100MB, NSIS, 서명 없음, 사용자 폴더 설치·설치 폴더 고르기, 바로 가기 "이어온 앱"). 아이콘은 이어온 512 그림으로 256 아이콘을 만들어 씀. 앱 묶음에서 개발 부품을 빼 188MB→0.7MB. NSIS 도구는 이 PC에 있던 것, Electron 실행 부분 묶음은 빌드 때 받음.
- **시험:** 앱 21건, 서버 334건 중 실패 0(건너뜀 1). 설치 파일을 조용히 설치 → 설치된 앱을 가짜 서버에 연결 → 다른 곳에서 보낸 질문의 답·허락 대기 알림이 원문 없이 나옴 → 제거 뒤 프로그램·바로 가기·제거 목록 모두 지워짐 확인. 웹 화면은 가짜 서버 화면에서 새 소식 연결(OPEN)과 알림 흐름 확인(내장 브라우저는 알림 허용을 줄 수 없어 알림 부분만 바꿔 끼움).
- **시험 중 발견해 고침:** 프로그램 이름(이어온)과 바로 가기 이름(이어온 앱)이 달라 Windows 알림용 바로 가기가 하나 더 생기고 제거 뒤에도 남음 → 프로그램 이름을 "이어온 앱"으로 맞춤(남은 시험 바로 가기는 지움). 알림 문구 "문서담당가" → 이/가 맞춤. 화면이 부르는 API 목록 시험에 `/v1/events` 추가.
- **미확인:** Windows 알림이 실제 화면 오른쪽 아래에 뜨는 모습(코드상 알림 생성까지 확인), 실제 브라우저 알림 허용 뒤 동작.

## 3-2. AP-4b 안드로이드 알림 — 코드(2026-11-18, 신산님 "휴대폰 알림 진행")

- **바꾼 점(신산님 몫 줄임):** 앱 설정 파일(google-services.json)도 이 PC 폴더가 아니라 **허브 설정 화면에 올림** — 앱을 만들 때 허브에서 받아 씀. 신산님은 Firebase 콘솔에서 파일 두 개를 받아 **설정 → 내 프로그램 연결 → 휴대폰 알림**에 올리기만.
- **서버(`src/pilot/push.mjs`):** 서비스 계정 키 검사·보관(설정 `push.fcm`, 화면에는 있다/없다·프로젝트 이름만), 구글 로그인(JWT RS256, node 기본 crypto, 50분 재사용), FCM HTTP v1로 "○○가 답했어요 / 허락을 기다려요 / 보내지 못했어요 / 확인이 필요해요"(원문 없음, 알림 갈래 `ieon`, 누르면 그 대화 — data.conversationId). 새 소식(SSE와 같은 사건)에서 그 대화 주인의 앱 기기로만. 더는 안 쓰는 주소(UNREGISTERED·404)는 지움.
- **API:** `PUT /v1/app/push-token`(앱 열쇠만, 빈 값 = 끄기), `PUT/DELETE /v1/admin/settings/push-key`·`push-app`, `GET /v1/admin/settings/push-app/file`(앱 만들 때). 앱 기기 목록에 `push`(알림 받는지).
- **앱:** `@capacitor/push-notifications` 8.1.3(공식) 설치, `src/lib/push.ts` — 연결되면 알림 갈래 만들고 허용 묻고 등록 → 주소를 서버에 알림, 알림 누르면 그 대화. 안드로이드만(PC 앱·웹은 AP-4a 그대로).
- **실측(2026-11-18 신산님 휴대폰):** 0.1.2에서 허용 창이 안 뜸 → 원인을 보려고 앱이 알림 준비 단계(시작·권한·허용·등록·주소 전송·오류 이름)를 허브 기록에 남기게 함(`POST /v1/app/push-state`, 0.1.3) → 0.1.3도 기록 없음(알림 부품을 처음 부르는 단계가 오류 처리 밖이라 조용히 끝난 것으로 봄) → 0.1.4에서 모든 단계를 오류 처리·15초 시간 제한 안으로 → 허용 창 뜸·허용·등록·주소 전송 확인. 허브에서 직접 보낸 시험 알림(구글 200) 도착, 앱을 내려 둔 채 보낸 시험 질문의 "시험이 답했어요" 도착(신산님 확인). 첫 시험은 앱이 화면에 열려 있어 설계대로 띄우지 않음. **PASS.**
- **시험:** 서버 ap4b-push 4건(글·검사·JWT 서명 검증·서버 흐름, 가짜 구글), 앱 push 3건. **남음:** 신산님 파일 올리기 → 앱 0.1.2 빌드(google-services.json 넣고, 구글 빌드 부품 내려받음) → 실제 휴대폰 알림. 웹 푸시(탭을 닫아도)는 다음.

## 3-3. 웹 알림(탭을 닫아도) — 코드(2026-11-18, 신산님 "웹 알림 진행")

- **서버(`push.mjs` 아래쪽):** VAPID 키를 허브가 처음 쓸 때 스스로 만들어 보관(설정 `push.vapid`, 사용자 입력 없음), RFC 8291 aes128gcm 암호화·RFC 8292 VAPID(ES256) — node 기본 crypto만. 휴대폰 알림과 같은 새 소식에서 그 대화 주인의 브라우저 구독마다 같은 글(원문 없음). 404·410이면 구독을 지움.
- **API(웹 로그인만):** `GET /v1/webpush/key`, `PUT/DELETE /v1/webpush/subscription`. 서비스 워커 `GET /sw.js`(알림만 — 요청 가로채기·화면 저장 없음, 이어온 화면을 앞에서 보고 있으면 안 띄움, 누르면 열린 탭으로 그 대화 또는 `/#conv=<ID>`).
- **화면:** 🔕 알림을 누르면 브라우저 허용 → 서비스 워커 등록·구독·서버에 알림. 안 되는 브라우저(https 아님 등)는 지금처럼 탭이 열려 있을 때만. 웹 알림이 켜지면 탭 알림은 띄우지 않음(겹치지 않게). PC형(127.0.0.1)·허브(https) 같음.
- **시험:** webpush 6건(받는 쪽처럼 풀어 확인·VAPID 서명 검증·구독 검사·보내기·서버 흐름·화면). **남음:** 배포, 실제 브라우저 확인.

## 4. 알려진 제한

- PC 앱 알림은 이어온 PC 앱이 켜져 있을 때만(창을 닫으면 끝남). 알림 영역(트레이)에 남기는 것은 필요하면 다음에.
- 서명 없는 설치 파일: 처음 실행 때 Windows SmartScreen 경고, 자동 업데이트 없음(새 판은 새 설치 파일).
- 앱 아이콘·시작 화면은 지금 기본 그림 — 스토어 제출(AP-5) 전에 이어온 그림으로.
