**가져오지 않을 것(이어온 안전 규칙과 정면으로 부딪힘):** 다시 열기가 실패하면 대화 내용을 새로 넣어 "재구성"하는 것(이어온은 새 대화로 대체 금지), 봇이 자기 설정·예약·폴더를 승인 없이 바꾸는 것, Full 권한에서 묻지 않고 실행·전송하는 것, 음성 "예/아니오"로 승인하는 것.

## 1. 지금 이어온

- 질문은 엔진에 **읽기 전용·승인 없음·네트워크 차단**으로 넣는다(MANUAL 6절). 그래서 "질문 → 답"에서 끝나고, 파일 수정·명령 실행은 원래 세션에서 사람이 한다.
- 새 세션은 작업 폴더 안 쓰기까지(`workspace`), 명령 실행·인터넷은 막는다. `full`은 설정 파일에서만.
- 승인 대기(`approval_required`)는 지금 "확인 필요"로 멈추고 자동 승인하지 않는다.

## 2. A. 일 시키기 — 대화마다 "작업 모드"와 승인 카드

### A1. 모양

- 대화(세션)마다 **"질문만"(기본, 지금과 같음)** / **"작업"** 중 하나. 작업 모드는 연결 설정에서 켜고, 켜 있는 동안 대화 위쪽에 표시.
- 작업 모드에서는 엔진이 **파일 수정·명령 실행을 하려 할 때마다** 대화 안에 **승인 카드**가 뜬다: 무엇을 하려는지(명령 한 줄·바꿀 파일과 변경 요약), 작업 폴더, [허용] [거부]. 누른 결과는 카드에 "✓ 허용 · 사용자 · 시각"으로 남는다(U2 카드 기록과 같음).
- 웹·이어온 앱·메신저(텔레그램·디스코드·슬랙의 버튼, 카카오·라인은 "허용/거부" 답글) 어디서든 같은 카드.
- **15분 응답이 없으면 거부**, 질문(엔진의 되묻기)은 시간 제한 없음, 그 차례(turn)가 끝나면 남은 요청은 거부. 거부는 "결과 불명"과 다르다(엔진이 다른 길을 찾거나 멈춤).
- **항상 허용·전체 허용은 없다.** `full`(제한 없음)·엔진의 자동 승인 모드(Codex `never`, Claude `bypassPermissions`·`auto`)는 쓰지 않는다(AGENTS: auto mode·권한 자동 처리 금지 그대로).

### A2. 엔진별로 되는 것

| 엔진·연결 | 승인 받는 길 | 가능 여부 |
| --- | --- | --- |
| Codex 동시 사용(`shared_server`, app-server) | app-server의 `requestApproval` 요청에 허용/거부로 답함(OpenMausBot과 같음) | 가능성 높음(구현 전 0.165.0에서 실측) |
| Codex 번갈아 쓰기(`alternate`, SDK `resumeThread`) | SDK가 승인 요청을 넘겨주는지 확인 필요 | **확인 필요** — 안 되면 작업 모드는 app-server 경로로만 |
| Claude 새 세션(`claude -p`) | `--permission-prompt-tool`(이어온 전용 MCP 승인 도구) → 이어온 서버 → 카드 | 가능성 높음(실측 필요) |
| Claude 채널(실행 중 터미널 세션) | 그 터미널의 사람이 직접 승인(manual mode) | 이어온 카드 대상 아님(지금처럼 터미널에서) |

### A3. 안전 장치

- 작업 모드를 켜는 것과 승인하는 것은 **그 세션의 주인(사용자 본인)만**. 이어온 앱에는 사람이 사용자 한 명뿐이라 다른 사람이 승인할 일은 없다(2026-11-12 MESSENGER_EXPANSION 수정과 맞춤).
- 작업 폴더 밖 쓰기·네트워크는 작업 모드에서도 기본 막음(엔진 샌드박스 `workspace-write` 범위).
- **업무 대화 `01a0dadd-…`는 작업 모드 대상도 아니다**(지금 규칙 그대로).
- 승인 기록: 허용/거부·시각·누가·종류(명령/파일)는 DB에 남기고 기본 180일 보관. **로그 파일에는 명령·파일 내용 원문을 남기지 않는다**(지금 원칙).
- 메신저 버튼 승인은 그 봇의 주인(사용자 본인)만 누를 수 있음(다른 사람이 누르면 무시).

### A4. 예약 작업(나중)

"매일 9시에 ○○ 세션에 '어제 변경 요약해줘'"처럼 정해진 때 질문을 보내는 기능. 이어온의 "자동 재전송 금지"는 결과 불명 질문을 다시 보내지 않는다는 것이라 예약과는 다르지만, 사람이 없을 때 모델이 호출되므로: **예약마다 사용자 승인, 횟수 한도, 질문만(작업 모드 예약 금지), 결과 불명이면 다음 예약까지 멈춤.**

## 3. B. 음성 — 말로 묻고 소리로 듣기

### B1. 모양(이어온 앱·웹)

- **음성으로 묻기:** 마이크를 누르고 말하면 받아쓰기 → 글자 질문으로 보낸다(보내기 전에 고칠 수 있음). 대화에는 "🎤 음성" 표시가 붙은 일반 메시지로 남음(OpenMausBot의 "via call"과 같은 생각).
- **답 듣기:** 답 옆 "읽어 주기", 설정에서 "답을 자동으로 읽기"(기본 꺼짐).
- **처음엔 기기 내장 기능만:** 휴대폰·브라우저의 내장 받아쓰기·읽기(키·비용 없음). 다만 기기에 따라 음성이 OS 회사(구글·애플·마이크로소프트) 서버로 갈 수 있음 → 처음 쓸 때 한 번 안내.
- **실시간 대화(Live, OpenAI 실시간 음성 등)는 나중:** 사용자 본인 키·분당 요금이 들고 음성·대화 일부가 외부로 감 → 따로 결정.
- 음성은 서버에 저장하지 않고, 로그에 받아쓴 글도 남기지 않는다(질문 원문을 로그에 남기지 않는 원칙).
- **음성으로 승인하지 않는다.** 승인은 카드 버튼으로만.

### B2. 실제 전화(전화번호로 걸고 받기)

OpenMausBot에도 없다. 원한다면 **새 기능**이며 전화 연결 서비스(유료 외부 서비스, 전화번호 임대), 통화 중 음성 인식·합성, 통화·녹음 고지와 동의, 요금이 필요하다 → **이번 설계 범위 밖**, 원하시면 따로 설계(WV7).

## 4-2. W2 구현 기록(2026-11-13, 신산님 "W2 진행")

- **작업 모드(`work_modes` 표):** 대화별 켜기(기본 꺼짐), Codex 기존 대화만(새 세션·Claude는 대상 아님), 주인 웹 화면만, 처리 중엔 못 바꿈. 켠 대화의 질문에 `workMode: true`.
- **엔진 연결(W0에서 된 것만):** 작업 모드 질문은 Codex **app-server 차례**로(`appServerTurn`) — `approvalPolicy: untrusted`·`approvalsReviewer: user`·`sandbox: workspace-write`·`sandboxPolicy: workspaceWrite(writableRoots: 작업 폴더, networkAccess: false)`. 번갈아 쓰기는 Desktop 잠금 판별 뒤 질문할 때만 stdio app-server를 띄움(SDK는 승인을 못 넘기므로), 동시 사용은 공유 서버에서 idle일 때만. 작업 폴더가 없거나 없는 폴더면 `work_dir_required`/`work_dir_missing`(보내지 않음). 엔진의 승인 요청은 W1 카드로, 답은 accept/decline만.
- **메신저(W2-b):** 승인 요청을 그 대화방에 "승인 요청 n"으로 알리고 `/허용 n`·`/거부 n`. 주인(공통 허용 사용자)만, 알린 번호만, 같은 요청은 한 번만 알림. 서버는 웹·메신저 봇만 결정 가능(외부 프로그램 키 403). 설계의 "버튼" 대신 모든 메신저 공통의 답글 명령.
- **실측(모델 3회):** 이어온 전용 계정·임시 폴더 새 시험 대화로 실제 서버·연결부·어댑터 전체 — ① 명령 승인 카드 → 거부 → 실행 안 됨·차례 정상(31초) ② 파일 수정 승인 카드 → 허용 → 파일 생성("hi")·차례 정상(124초). 파일 수정 승인 요청에는 작업 폴더(cwd)가 오지 않음(카드에 폴더 표시 없음).
- **시험:** `w2-work-mode` 8건, 민감도 12종, 전체 318건 중 실패 0(건너뜀 1).

## 4-1. W1 구현 기록(2026-11-13, 신산님 "W1 Codex부터")

W0 결과(Codex app-server만 가능, SDK 불가, Claude 보류)에 따라 **승인 카드 바탕**을 만들었다. 작업 모드 켜기(엔진 연결)는 W2.

- **저장(`approvals` 표):** 요청·대화·종류(명령/파일/권한)·요약(명령 한 줄·파일 사유, 500자)·작업 폴더·상태(pending → allowed/denied/expired/turn_ended)·누가·언제. **180일 지나면 서버 켤 때 정리.** 로그 파일에는 "승인 요청됨/결정됨"과 결과만(내용 원문 없음).
- **연결부 → 서버:** `POST /v1/device/approvals`(그 PC가 처리 중인 질문만) → `GET /v1/device/approvals/<id>`로 2초마다 결정 확인(`connector.mjs approver`). 허용이면 `accept`, 그 밖의 모든 경우(거부·시간 초과·차례 끝·서버 거절·닿지 못함)는 `decline`.
- **15분 규칙:** 답이 없으면 서버가 읽을 때 `expired`(거부)로 바꿈. **차례가 끝나면**(결과 보고) 남은 요청은 `turn_ended`(거부).
- **웹 카드:** 대화 카드 맨 앞에 "명령을 실행해도 될까요?/파일을 고쳐도 될까요?" — 요약·작업 폴더·남은 분, [허용] [거부]만(이번 한 번만, 항상 허용 없음). 누르는 것은 그 대화 **주인의 웹 화면만**(`POST /v1/approvals/<id>`, 메신저·외부 키 403). 처리 중에도 2초마다 카드를 불러옴. 기록 `GET /v1/conversations/<id>/approvals`.
- **공유 서버 경로(W0 F5 고침):** app-server가 보내는 승인 요청에 이제 답한다 — 작업 모드가 아니면(지금은 늘) **바로 거부**해 차례가 3분 멈추지 않음. 이 thread의 요청만 사람에게 묻고, 엔진 쪽 답은 `accept`/`decline` 둘로만 보냄(`acceptForSession` 같은 것은 거부로). 모르는 서버 요청은 "지원 안 함".
- **시험:** `w1-approvals` 7건, 민감도 9종 모두 잡힘, 전체 310건 중 실패 0(건너뜀 1). **미확인:** 실제 엔진으로 카드 왕복(W2에서 작업 모드와 함께, 모델 호출 승인 필요).

## 6. 위험

- **안전 기본값이 바뀐다:** 지금 "질문만"이라 사고 범위가 작다. 작업 모드는 파일·명령을 건드리므로 승인 카드가 유일한 방어선 → 카드에 무엇을 하는지 정확히(명령 원문·바꿀 파일) 보여 주고, 승인자는 사용자 본인만, 폴더 밖·네트워크는 막음.
- **메신저 승인 오조작:** 휴대폰에서 잘못 누를 수 있음 → 명령이 위험해 보이면(삭제·폴더 밖 경로 등) 카드에 경고 표시, 실행 취소가 안 되는 일임을 문구로.
- **엔진 버전 의존:** app-server·SDK·Claude 옵션은 실험 기능이거나 바뀔 수 있음 → W0 실측과 버전 기록, 승인 경로가 안 되면 작업 모드를 켜지 못하게(조용히 자동 허용으로 넘어가지 않음).
- **음성 개인정보:** 기기 내장 받아쓰기도 OS 회사 서버를 거칠 수 있음 → 처음 안내, 서버·로그에 음성·받아쓴 글 저장 안 함.
