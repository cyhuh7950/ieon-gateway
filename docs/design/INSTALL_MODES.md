# 설치 모드 3가지 — 처음에 하나를 고르고, 섞어 쓰지 않는다

기준: 2026-11-12. 상태: **승인 2026-11-12(신산님 "추천안 승인"). IM6은 신산님 수정안(초대 코드 없이 가입 신청 → 관리자 승인).** 7절 추천안이 결정이다. 구현은 단계마다 신산님 승인 후. 코드·서버 변경 없음. 승인된 결정만 구현한다.
관련: [HUB_AND_PC_PROFILES](HUB_AND_PC_PROFILES.md)(ieon·ieun 두 형태, 2026-11-06), [UI_CHAT_FIRST](UI_CHAT_FIRST.md)(새 화면·처음 설정 3단계).

## 1. 왜 필요한가

- 카카오톡은 메신저 쪽에서 우리에게 요청을 보내는 방식이라 **공개 주소(URL)가 있는 공개 서버**가 꼭 필요하다. 텔레그램·디스코드·슬랙은 PC가 먼저 접속하므로 필요 없다.
- 지금 공개 서버 모듈은 두 가지다. `ieon-gateway.sinsan.kr`은 PC 완결형용 **카카오 중계**, `ieun-gateway.sinsan.kr`은 **허브**다(둘 다 같은 Oracle 서버 168.107.4.6).
- **지금 이 PC는 둘을 섞어 쓰고 있다.** PC 서버·웹·메신저를 켜 둔 채 허브에도 연결돼 있고, 카카오는 PC가 ieon 중계로, 허브가 자기 중계로 따로 받는다. 텔레그램·디스코드·슬랙은 사람이 PC에서 꺼서 겹치지 않게 맞췄다. 이런 상태는 질문이 두 곳으로 갈라지거나(같은 봇 충돌), 어디서 설정해야 하는지 헷갈리게 한다.
- 공개 서버를 직접 둘 수 없는 사람도 카카오톡과 밖에서 쓰기를 원한다 → **우리가 운영하는 공용 서비스**가 세 번째 모드.

## 2. 세 가지 모드

| | ① 내 PC만(ieon) | ② 내 허브(ieun) | ③ 공용 서비스(ieun-server) |
| --- | --- | --- | --- |
| 누구에게 | PC 한 대로 쓰는 사람 | 자기 공개 서버가 있는 사람 | 공개 서버가 없는 사람 |
| PC에 설치 | 서버·웹·메신저·연결부 전부 | 연결부 + 이 PC 안전 설정용 화면 | ②와 같음 |
| 공개 서버 | **카카오 중계만**(카카오를 쓸 때만, 자기 서버 또는 `ieon-gateway.sinsan.kr`) | **허브 전체**를 자기 서버에(`ieun-gateway.sinsan.kr`은 신산님의 허브) | **우리가 운영**(예: `ieun-server.sinsan.kr`), 사용자는 가입만 |
| 설정·대화하는 곳 | 이 PC 화면 | 내 허브 화면 | 공용 서비스 화면(내 계정) |
| 메신저 봇 | PC가 연결 | 허브가 연결 | 공용 서비스가 연결(7절 결정) |
| PC가 꺼지면 | 아무것도 답하지 않음 | 허브 새 세션은 답함, PC 대화는 "PC 연결 끊김" | PC 대화는 "PC 연결 끊김"(서버 새 세션 없음, 7절) |
| 공개 주소 필요 | 카카오 쓸 때만 | 예(내 것) | 아니요(우리 것) |

**공통으로 그대로인 것:** 기존 세션 이어 쓰기 방식(Codex `alternate`·`shared_server`, Claude 채널), 사용 중이면 거부, 결과 불명이면 자동 재전송 없음, 업무 대화 제외, **이 PC의 안전 설정(허용 목록·AI 응답·작업 폴더)은 이 PC 화면에서만**, 로그에 원문 없음.

## 3. 처음에 고르기

원칙(WEB_FIRST·UI_CHAT_FIRST): 명령 창에서 묻지 않고 **화면에서** 고른다. 설치(`install.ps1`)는 지금처럼 한 번 실행으로 끝나고, 처음 설정 3단계 앞에 0단계를 하나 둔다.

> **0. 어떻게 쓰실 건가요?**
> - **이 PC에서만** — 가장 간단해요. 카카오톡을 쓰려면 나중에 중계 주소만 넣어요.
> - **내 허브에 연결** — 허브 주소(또는 허브에서 만든 PC 연결 링크)가 있어요.
> - **이어온 공용 서비스** — 계정을 만들거나 로그인해서 써요. 공개 서버가 필요 없어요.

- ①이면 지금의 처음 설정(준비 확인 → 대화 고르기 → 준비됨) 그대로.
- ②면 허브 주소 → 연결(PC 연결 링크로 열었으면 이 단계는 자동으로 골라진 상태) → 이 PC에서 이어 쓸 대화 고르기(허용 목록) → 완료. 대화·메신저는 허브 화면에서.
- ③이면 공용 서비스 로그인/가입(브라우저로 공용 서비스 페이지를 열어 승인 — PC 연결 링크와 같은 방식, 사용자가 토큰을 다루지 않음) → 이 PC 대화 고르기 → 완료.
- 기본값은 ①(아무것도 고르지 않고 넘어가면 ①).

## 4. 섞어 쓰지 못하게 하는 장치

모드는 이 PC의 설정 파일 한 곳(`.local/mode.json`, git 제외)에만 둔다. 서버가 켜질 때 읽고, 모드에 맞지 않는 부분은 **켜지 않는다**(화면에서 숨기는 것만이 아니라 서버가 거부).

| 기능 | ① 내 PC만 | ②·③ 허브 연결 |
| --- | --- | --- |
| 이 PC의 메신저 봇(텔레그램·디스코드·슬랙) | 켬 | **켜지 않음**(허브·공용 서비스가 받음) |
| 이 PC의 카카오 중계 연결 | 켬(주소를 넣었을 때) | **켜지 않음** |
| 허브 연결(PC 연결 링크·허브 주소) | **거부**(모드를 바꿔야 함) | 켬(②는 내 허브 1곳, ③은 공용 서비스 1곳) |
| 이 PC 화면에서 질문 보내기 | 됨 | 안 됨(지금의 `409 hub_mode`와 같음, 허브 화면으로 안내) |
| 이 PC 화면 | 전체 | 이 PC 안전 설정·연결 상태만 |

- 허브는 한 번에 **한 곳**만. ②와 ③을 동시에 붙이지 않는다.
- 공개 서버 쪽도 같은 원칙: 한 서버에 같은 메신저 봇을 둘 이상의 모드에서 켜지 않게, 봇 연결 충돌(지금의 "충돌" 표시)을 그대로 쓴다.

### 모드 바꾸기

설정 → 일반 → "사용 방식"에서 바꾼다. 바꿀 때 무엇이 꺼지고 켜지는지 먼저 보여 주고 확인을 받는다(예: ①→②면 "이 PC의 텔레그램·디스코드·슬랙·카카오 연결을 끕니다. 봇은 허브에서 다시 연결하세요"). 처리 중이거나 확인 필요 질문이 있으면 바꾸지 않는다. 대화 기록·허용 목록은 지우지 않는다.

### 지금 이 PC 옮기기

이 PC는 지금 사실상 ②에 가깝다(허브 연결 중, PC 봇 대부분 꺼 둠). 구현 뒤 처음 켤 때 "허브에 연결돼 있으니 ②(내 허브)로 정할게요"로 자동 판단하고, 남아 있는 PC의 카카오 중계 연결은 끄는 것을 확인받는다.

## 5. ③ 공용 서비스가 지금 코드와 다른 점

지금 이어온은 **사용자가 한 사람**이라고 가정하고 만들어져 있다(관리자 비밀번호 하나, 사용자 `u_sinsan` 하나, 봇·설정·기기가 서버 전체에 하나씩). 공용 서비스는 여러 사람이 한 서버를 쓰므로 아래가 새로 필요하다.

1. **가입·로그인:** 가입 신청 → 관리자 승인 뒤 사용(IM6), 잠금·비밀번호 재설정.
2. **사람마다 분리:** 대화·요청·기기(PC)·봇 설정·허용 사용자·API 키를 사용자별로 나누고, 서버가 모든 요청에서 소유자를 검사(지금의 소유권 검사를 사용자 여러 명으로 확장).
3. **메신저:** 봇을 어떻게 둘지(7절 결정). 사용자 각자의 봇 토큰을 우리 서버가 보관하면 위험·책임이 커진다.
4. **카카오:** 사용자마다 다른 스킬 URL(비밀 경로) 또는 공용 채널 하나(7절).
4-1. **중계·연결 분리(2026-11-12 보완, 외부 검토 지적 확인):** 지금 공개 중계(`src/relay/relay.mjs`)는 PC 연결 열쇠(`pcToken`) 하나, 카카오 비밀 경로(`kakaoSecret`) 하나, **대기열 하나**를 쓰고 PC가 가져갈 때 통째로 비운다 — 한 사람용이다. 가입 화면만 붙이면 다른 사람의 카카오 질문이 내 PC로 넘어갈 수 있다. ③에서는 **회사 공간(사용자)별·봇별·PC별로** 열쇠·비밀 경로·대기열을 나누고, PC는 자기 공간의 자기 몫만 가져가며, 서버가 모든 요청에서 어느 공간인지 확인한다. 허브 쪽(기기·대화·요청 저장)도 같은 기준으로 나눈다. ①의 `ieon-gateway` 중계는 지금처럼 한 사람(신산님) 전용(IM8).
5. **서버에서 AI 실행 안 함:** 남의 코드를 우리 서버에서 실행하는 새 세션은 공용 서비스에서 끈다. 실제 실행은 각자의 PC에서만(요금도 각자의 Codex·Claude 계정).
6. **한도·남용 방지:** 사용자별 요청 수·기기 수·저장 기간, 가입 남용 방지.
7. **운영·법:** 다른 사람의 질문·답이 우리 서버를 지나간다 → 개인정보 처리방침·이용약관, 저장하지 않는 원칙(지금처럼 원문 로그 없음), 장애·백업, 비용. 실제로 열기 전에 신산님 결정이 필요한 영역.

## 7-1. M1 구현 기록(2026-11-12, 신산님 "다음 작업 진행하자")

- **모드 파일(`src/pilot/mode.mjs`):** `.local/mode.json` `{ mode: 'pc'|'hub', setAt }`. 없으면 null(예전 설치 — 지금처럼 동작). ③은 M2·M3.
- **서버가 거부:** ① 'pc' — 허브 연결·다시 연결 `409 mode_pc`, 켤 때 짝맺은 허브가 있어도 다시 연결하지 않음. ② 'hub' — 메신저의 봇 목록을 빈 목록으로(텔레그램·디스코드·슬랙·라인·카카오 중계가 1분 안에 꺼짐, 봇 설정은 그대로), 이 PC 화면 질문 `409 hub_mode`, 이 PC 서버는 작업을 내주지 않음, 카드 `hub_mode`(허브 연결이 잠깐 끊겨 있어도 모드 기준).
- **바꾸기 `PUT /v1/admin/local/mode`:** 이 PC에서 연 화면만, 처리 중·확인 필요 질문이 있으면 `409 requests_pending`. ①로 바꾸면 허브 연결부를 끔(짝맺은 정보는 남김), ②로 바꾸면 짝맺어 있으면 다시 연결. 바꾸기 전 화면이 꺼지는 것·켜지는 것을 보여 주고 확인.
- **화면:** 처음 설정 0단계("어떻게 쓰실 건가요?" — 이 PC에서만 / 내 허브에 연결 / 공용 서비스 준비 중, 넘어가면 ①), 설정 → 이 PC → 사용 방식, 고르지 않은 예전 설치는 왼쪽 위 안내 줄(짝맺어 있으면 ② 추천). 허브 화면의 PC 설정에서도 그 PC의 사용 방식을 보고 바꾼다(**처음엔 보기만 두었다가 신산님 지적으로 IM10대로 고침, 2026-11-12**) — 공통 명령 `mode.get`·`mode.set`. 허브에서 "이 PC에서만"으로 바꾸면 결과를 보낸 뒤 허브 연결이 끊기므로(다시 ②로는 그 PC 화면에서) 확인 창에서 미리 경고.
- **이 PC 자동 판단:** 파일이 없고 허브에 짝맺어 있으면 ② 추천을 보이고, 신산님이 확인해 정함(카카오 중계 연결이 꺼지는 것을 확인받는 설계대로 자동으로 바꾸지 않음).
- **시험:** `m1-modes` 7건, 민감도 6종 모두 잡힘, 전체 294건 중 실패 0(건너뜀 1).

## 8. 위험

- **범위:** ③은 이어온을 "한 사람용"에서 "여러 사람용"으로 바꾸는 일이라 가장 크다 → M1을 먼저 끝내고, M2 이후는 단계마다 승인.
- **보안:** 여러 사람이 한 서버를 쓰면 분리 실수가 곧 다른 사람의 대화 노출 → 모든 API에 소유자 검사 시험을 붙이고(지금 `ownership` 시험 확장), 공용 서비스에서는 서버 쪽 AI 실행을 하지 않는다.
- **책임·비용:** 공용 봇·공용 카카오 채널은 우리 이름으로 운영된다(차단·스팸·약관 위반 대응 필요).
- **지금 쓰던 상태와의 호환:** 이 PC처럼 섞여 있던 설치는 M1에서 자동 판단 후 확인받아 정리한다(아무것도 지우지 않음).
