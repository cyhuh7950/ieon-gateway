## 1. 만드는 것

- **정식 서명 키:** 이어온 전용 키를 이 PC `.local/app-signing/`에 만든다(비밀번호는 무작위, 화면·로그·git에 없음). 이 키로 정식(release) APK를 만든다 — 다른 PC로 옮겨도 같은 키면 덮어 설치(업데이트)가 된다. 키를 잃으면 같은 앱으로 업데이트할 수 없으므로 신산님이 한 부 따로 보관.
  - 시험용 서명(0.1.5까지)에서 정식 서명으로 바꾸는 첫 설치만은 앱을 지우고 새로 깔아야 한다(안드로이드 규칙) — 연결도 다시(연결 코드).
- **허브 내려받기:** `GET /app`(안드로이드 APK로 바로), `GET /download/<파일>`, `GET /v1/app/version`(판 정보 — 판 번호·파일 이름·크기·SHA-256). 접속 제한(IP 목록)을 거치지 않음 — 앱 파일에는 비밀값이 없고 허브 없이는 못 씀. 허브는 데이터 폴더 `apps/`, PC형은 이 PC의 `.local/apps/`.
- **설정 화면 "앱 받기":** 내 프로그램 연결 → 이어온 앱 연결 바로 위에 안드로이드·PC 받기 버튼과 휴대폰에서 칠 짧은 주소(`<허브>/app`).
- **새 판 알림(앱):** 앱이 켜질 때 연결한 서버의 `/v1/app/version`을 보고 더 새 판이면 "새 판이 있어요 — 받기"(누르면 휴대폰 브라우저가 내려받음, 자동 설치는 안드로이드가 막음).
- **올리기:** `node scripts/publish-apps.mjs`가 최신 APK·PC 설치 파일과 판 정보를 `.local/apps/`에 모으고, 배포 때 허브 데이터 폴더로 복사.

## 2. 결과(2026-11-18 코드)

- 정식 서명 키 `.local/app-signing/`(RSA 4096, 50년, `scripts/make-signing-key.mjs`), 빌드 설정은 그 파일을 읽기만 함(비밀번호를 빌드 파일에 적지 않음). `npm run package:android:release` → `app/dist/release/ieon-android-0.1.6.apk`(4.4MB, 서명 CN=ieon 확인). PC 설치 파일 0.1.6.
- 서버 `/v1/app/version`·`/app`·`/download/<파일>`(판 정보에 있는 파일만, 접속 제한 예외), 설정 화면 "앱 받기", 앱 `src/lib/update.ts` 새 판 알림 띠(앱 판 번호는 빌드 때 package.json에서).
- 시험: 서버 ap5-apps 3건, 앱 update 2건. **남음:** 배포(허브 데이터 폴더 apps/에 파일 올리기 포함), 휴대폰에서 받아 설치 확인. 시험용 서명 0.1.5 이하에서 넘어올 때는 한 번 지우고 설치.
