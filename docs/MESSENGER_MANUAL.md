# 이어온 메신저 설정 설명서 (텔레그램·디스코드·슬랙)

> **봇 토큰·주인 등록·허용 사용자·봇 등록은 모두 웹 화면에서** 한다. 기본 봇은 화면 왼쪽 아래 **메신저** 창, 여러 봇·고급 설정은 **설정 → 메신저**. 설정 파일을 고치거나 메신저를 명령으로 다시 켤 필요가 없다(메신저는 이어온 서버가 띄우고, 1분마다 웹 설정을 다시 읽는다).

- 기준: 2026-11-12(새 화면 U1~U7 반영) · 대상: 신산님
- 함께 보기: [사용 설명서](MANUAL.md)(서버·연결부·웹), [작업 기록](WORK_STATUS.md)

## 1. 구조 한눈에

```
신산님(메신저 대화방) ⇄ 메신저 봇 ⇄ 이어온 메신저 모듈(이 PC) ⇄ 이어온 서버 → 연결부 → Codex/Claude 세션
```

- 기본은 **메신저마다 봇 1개**(`default` 봇)이고, 대화방(채널·그룹·1:1)마다 세션 하나를 `/use`로 연결한다.
- 필요하면 **같은 메신저에 봇을 여러 개** 둘 수 있다(6.2). 봇마다 허용 사용자·볼 수 있는 세션·대화방 연결이 따로다. 어떤 용도로 나눌지는 신산님이 정한다.
- 세 메신저 모두 **봇이 이 PC에서 메신저 서버로 먼저 접속**한다(텔레그램 long polling, 디스코드 Gateway, 슬랙 Socket Mode). 그래서 공유기 포트·공개 주소·Tailscale이 필요 없다. 카카오톡은 이 방식을 지원하지 않아 공개 HTTPS 서버(Oracle 등)가 필요하고 지금은 제외한다.
- 로그인은 토큰 대신 **메신저 사용자 ID 허용 목록**이다. 목록 밖 사용자에게는 `/whoami` 외에 아무 응답도 하지 않는다.
- 질문 규칙은 웹과 같다: 사용 중이면 거절, 결과 불명이면 다시 보내지 않음, Codex 질문은 읽기 전용.

## 2. 어디서 설정하나

| 하는 일 | 화면 |
| --- | --- |
| 기본 봇 토큰 넣기·바꾸기 | 왼쪽 아래 **메신저** → 메신저 고르기 → 토큰 칸(저장한 값은 다시 보이지 않음) |
| 내 계정을 봇 주인으로 등록 | **메신저** 창이 보여 주는 6자리 숫자를 봇에게 보내기(5절) |
| 여러 봇의 토큰 넣기·바꾸기·지우기 | **설정 → 메신저** → 봇 목록에서 봇 고르기 → 편집 칸 **토큰** |
| 봇 추가·이름·역할·부르는 이름·추가 허용 사용자·볼 수 있는 세션·켜기·삭제 | **설정 → 메신저**의 봇 목록·편집 칸(메신저 창의 "고급" 링크도 여기로) |
| 허용 요청·공통 허용 사용자 | 대화 화면의 "허용 대기" 띠에서 "허용", 또는 **설정 → 메신저 → 허용 요청**·**메신저 공통 허용 사용자** |
| 카카오 스킬 URL | **메신저 → 카카오톡**의 복사, 또는 **설정 → 메신저 → 카카오 스킬 URL** |
| 역할 | **설정 → 메신저**의 역할 |

토큰은 채팅·문서·스크린샷에 남기지 않는다. 기록(`.local\run\server.log`)에는 토큰·질문·답 원문이 없다.

## 3. 켜고 끄기·상태

메신저는 이어온 서버가 함께 띄운다(설치 후 자동). 따로 켜고 끌 필요가 없다. 기본 봇 상태는 **메신저** 창의 메신저 고르기 화면에, 모든 봇 상태는 **설정 → 메신저**의 봇 목록 상태 칸에 나온다. 꺼 둔 봇은 메신저 창에서 "꺼져 있음 · 다른 곳(허브 등)에서 쓰는 중일 수 있어요"로 보이고 고를 수 없다(허브로 옮긴 봇에 토큰을 다시 넣어 겹치지 않게).

| 상태 | 뜻 | 할 일 |
| --- | --- | --- |
| 연결됨 | 정상 | — |
| 토큰 없음 · 빠진 토큰 이름 | 그 봇의 토큰을 아직 안 넣음 | 메신저 창 또는 편집 칸 **토큰**에 넣기(1분 안에 연결) |
| 토큰 중복 | 같은 토큰이 두 봇에 들어 있음(둘 다 안 켬) | 봇마다 다른 토큰으로 |
| 충돌 · 다른 곳에서 같은 봇을 켜 둠 | PC와 허브 등 두 곳에서 같은 봇을 받는 중(텔레그램·슬랙만 알 수 있음. 디스코드는 알려 주지 않아 "연결됨"으로 보임) | 한쪽에서 봇을 끄기(1분 안에 풀림) |
| 텔레그램 그룹 일반 글 수신 꺼짐 | 그룹 일반 글을 못 받음 | 4.1의 `/setprivacy` → Disable |

- 실제 답을 받으려면 이 PC의 AI 응답(실제 실행)이 켜져 있어야 한다(이 PC 화면 위쪽 **AI 응답** 스위치, 또는 웹에서 첫 질문을 보낼 때 **켜고 보내기**). 웹에서 한 번 켜기 전에는 메신저 질문에 답하지 않는다. 꺼져 있으면 봇이 "연결부에서 실제 실행이 꺼져 있음"으로 답한다.
- 같은 봇 토큰을 PC와 허브에 동시에 넣지 않는다(두 곳이 같은 봇을 동시에 받으면 메시지가 나뉜다).

## 4. 메신저별 봇 만들기

### 4.1 텔레그램 (가장 쉬움)

1. 텔레그램에서 `@BotFather`를 열고 `/newbot`을 보낸다.
2. 표시 이름과 사용자 이름(끝이 `bot`, 예: `Test_cyhuh_01_bot`)을 정하면 토큰이 나온다.
3. 이어온 **메신저 → 텔레그램**의 토큰 칸에 넣고 **연결**(추가 봇은 **설정 → 메신저 → 그 봇 → 토큰**).
4. 봇 찾기: 텔레그램 검색에서 `@사용자이름`을 찾거나 기동 로그의 `open` 링크를 연다. **시작(Start)**을 누른다. 대화 목록에 봇이 일반 대화처럼 보인다.
5. 그룹에서 쓰려면: BotFather에서 `/setprivacy` → 봇 선택 → **Disable**(그래야 그룹의 일반 글을 봇이 읽는다). 성공하면 "Success! The new status is: DISABLED."가 나온다. 그룹에 봇을 초대한다. 그룹의 **주제(Topic)**마다 다른 세션을 연결할 수 있다.
   - **이미 그룹에 들어가 있던 봇은 내보냈다가 다시 넣어야** 바뀐 설정이 그 그룹에 적용된다.
   - 적용 여부는 메신저 로그의 `"canReadAll":true`로 확인한다(메신저를 다시 켜면 다시 읽음).

### 4.2 디스코드

1. https://discord.com/developers/applications → **New Application** → 이름 입력.
2. 왼쪽 **Bot** → **Reset Token**으로 토큰 발급 → 이어온 **메신저 → 디스코드**의 토큰 칸(추가 봇은 **설정 → 메신저 → 그 봇 → 토큰**).
3. 같은 **Bot** 화면에서 **Message Content Intent**를 켠다(꺼져 있으면 메시지 내용을 못 읽는다). 한국어 화면에서는 "메시지 콘텐츠 인텐트".
4. 봇을 내 서버에 초대: 기동 로그의 `invite` 링크를 열거나, **OAuth2 → URL Generator**(한국어 "OAuth2 URL 생성기")에서 고른다.
   - 스코프: `bot` 하나
   - 봇 권한: `View Channels`(채널 보기)·`Send Messages`(메시지 보내기)·`Read Message History`(메시지 기록 보기) 세 개
   - 연동 유형: `Guild Install`(길드 설치)
   - 아래 **생성된 URL**을 복사해 브라우저에서 열고 서버를 골라 승인한다. 로그의 `guilds`가 1 이상이면 들어간 것이다.
5. 봇 찾기: 봇은 채널 목록이 아니라 **멤버 목록**(채널 화면 오른쪽 위 사람 모양 아이콘)에 보인다.
   - 채널에서 쓰기: 그 채널에 바로 글을 쓴다.
   - 1:1로 쓰기: 멤버 목록에서 봇을 누르고 메시지를 보내면 왼쪽 위 **다이렉트 메시지**에 봇 대화방이 생긴다.
6. 연결이 가끔 끊기면(`closed`, code 1006) 2초 뒤 자동으로 다시 붙는다. 4004는 토큰 오류, 4014는 Message Content Intent 꺼짐이며 자동 재접속하지 않는다.

### 4.3 슬랙

1. https://api.slack.com/apps → **Create New App** → **From an app manifest**를 고른다. Claude/OpenAI 같은 AI 에이전트 템플릿이나 Slack CLI(`slack create`) 예제는 쓰지 않는다(아래 주의 참고).
2. 워크스페이스 선택 → 형식 **YAML** → 아래를 붙여넣고 Create.

```yaml
display_information:
  name: ieon
  description: 이어온 — 이 PC의 작업 세션에 질문을 전달합니다
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: ieon
    always_online: true
oauth_config:
  scopes:
    bot:
      - chat:write
      - channels:history
      - groups:history
      - im:history
settings:
  event_subscriptions:
    bot_events:
      - message.channels
      - message.groups
      - message.im
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

3. **Basic Information → App-Level Tokens → Generate Token and Scopes**: 이름 `socket`, scope `connections:write` → `xapp-…` → 이어온 **메신저 → 슬랙**의 앱 토큰 칸(추가 봇은 **설정 → 메신저 → 그 봇 → 토큰**).
4. **Install App → Install to <워크스페이스>** → **Bot User OAuth Token**(`xoxb-…`) → 같은 곳의 봇 토큰 칸. 두 칸을 채우고 **연결**.
5. 봇 쓰기:
   - 1:1: 왼쪽 사이드바 **Apps**에서 앱을 열고 **Messages** 탭에 쓴다(안 보이면 **+ Add apps**에서 검색).
   - 채널: 채널 화면 맨 위의 채널 이름(`# bot` 등) → 채널 정보 창의 **Agents & apps** 탭(이전 Slack 화면은 Integrations) → **Add agents and apps**로 추가. 또는 채널 입력창에 `/invite @앱이름` — 표시 이름이 정확해야 하므로 자동 완성 목록에서 고른다.
6. 슬랙에서는 `/`로 시작하는 글을 슬랙이 가로채므로 이어온 명령은 **`!`로 시작**한다(`!whoami`, `!sessions`, `!use 1` …).

**Socket Mode란**: 슬랙이 우리 공개 주소로 이벤트를 보내는 대신, 봇이 슬랙으로 먼저 접속해 연결을 유지하며 메시지를 받는 방식이다. 이 PC에 공개 주소가 있어도 포트를 열 필요가 없어 더 안전하다. App-Level Token(`xapp`)은 이 접속용, Bot Token(`xoxb`)은 답장용이다.

**주의 — 같은 앱에 다른 프로그램이 붙으면 메시지가 나뉜다**: Socket Mode는 같은 앱에 연결이 여러 개면 메시지를 그중 하나에만 보낸다. 2026-10-31에는 Slack CLI 예제(`D:\slack\my-app`에서 `slack run`, 앱 이름 `my-app (local)`)가 같은 앱에 붙어 있어 1:1 대화를 그 예제가 가져가 엉뚱하게 답했다. 이어온 봇이 쓰는 슬랙 앱에서는 `slack run` 같은 다른 프로그램을 실행하지 않는다. 가장 확실한 방법은 위 manifest로 이어온 전용 앱을 만드는 것이다.

### 4.5 라인(LINE) — 2026-11-12 L1

라인은 카카오처럼 **라인이 우리 공개 주소로 webhook을 보내는** 방식이라 공개 서버(지금은 허브)가 받아 두고, 메신저가 먼저 접속해 가져갑니다(중계의 메신저별 대기열 `?channel=line`). 서명(`X-Line-Signature`, 채널 시크릿으로 만든 HMAC-SHA256)은 채널 시크릿을 가진 메신저 쪽이 확인하고, 틀리면 버립니다. 1:1 대화만 받습니다.

1. **라인 공식 계정 만들기:** LINE 계정으로 [LINE Official Account Manager](https://manager.line.biz)에서 공식 계정을 만듭니다.
2. **Messaging API 켜기:** 공식 계정 관리 화면의 설정에서 **Messaging API 사용**을 켭니다(처음이면 프로바이더 이름을 정합니다). 그러면 [LINE Developers](https://developers.line.biz) 콘솔에 그 계정의 **Messaging API 채널**이 생깁니다.
3. **값 두 개 받기:** LINE Developers → 그 채널 → **Basic settings(기본 설정)**의 **Channel secret(채널 시크릿)**, **Messaging API** 탭의 **Channel access token(long-lived)** → Issue(발급).
4. **이어온에 넣기:** 이어온 **허브 화면** 왼쪽 아래 **메신저 → 라인** → 두 칸(채널 액세스 토큰·채널 시크릿)에 붙여 넣고, 그 아래 **Webhook URL**을 **복사**합니다.
5. **라인에 주소 넣기:** LINE Developers **Messaging API** 탭의 **Webhook URL**에 붙여 넣고 **Verify(확인)** → **Use webhook(웹훅 사용)**을 켭니다.
6. **자동 응답 끄기:** 공식 계정 관리 화면의 **응답 설정**에서 **자동 응답 메시지**를 끕니다(켜 두면 라인이 미리 정한 답을 같이 보냅니다).
7. **연결:** 이어온 메신저 창에서 **연결**을 누르면 봇이 연결된 뒤 **6자리 숫자**가 나옵니다. 휴대폰 라인에서 그 공식 계정을 **친구 추가**(Messaging API 탭의 QR 코드)하고 **1:1 대화**에서 숫자를 보내 주인으로 등록합니다.
8. **질문:** `/sessions` → `/use 1` → 질문. 4절의 AI 응답이 켜져 있어야 답합니다.

- 토큰 이름: 기본 봇 `LINE_CHANNEL_ACCESS_TOKEN`·`LINE_CHANNEL_SECRET`, 추가 봇 `LINE_BOT_<ID>_ACCESS_TOKEN`·`LINE_BOT_<ID>_CHANNEL_SECRET`(웹에서만 입력).
- Webhook URL: 허브 `https://<허브>/line/webhook/<비밀 경로>`(카카오 스킬 URL과 같은 비밀 경로 값). **설정 → 메신저**가 아니라 메신저 창에서 복사합니다.
- 답장(reply)은 무료, 보내기(push)는 공식 계정 요금제의 월 무료 건수에 들어갑니다. 이어온은 답이 20초 안에 오면 답장으로, 늦으면 "받았어요"를 답장으로 보내고 실제 답을 보내기로 보냅니다.

## 5. 처음 연결하기(공통 순서)

1. 웹 화면 왼쪽 아래 **메신저**를 누르고 메신저를 고른다. 꺼 둔 봇은 고를 수 없다.
2. 짧은 안내를 따라 봇 토큰을 넣고 **연결**(텔레그램·디스코드 1칸, 슬랙 2칸, 이미 저장돼 있으면 바꿀 때만). 카카오톡은 스킬 URL을 복사해 오픈빌더에 붙이고 **붙여 넣었어요**.
3. 봇이 연결되면 화면에 **6자리 숫자**가 크게 나온다. 메신저에서 그 봇에게 **숫자만** 보낸다. 화면에 "○○님이 주인으로 등록됐어요"가 나오면 끝이다(다시 켤 필요 없음, 사용자 ID를 옮겨 적지 않는다).
   - 숫자는 10분 동안 한 번만 쓸 수 있다. 5번 틀리면 잠기니 **숫자 새로 받기**를 누른다.
   - 이미 허용된 사람이 보내면 봇이 "이미 허용된 분이라 따로 등록하지 않았어요"라고 답하고 화면은 완료로 바뀐다(질문으로 가지 않는다).
   - 다른 방법: 봇에게 아무 말이나(또는 `/whoami`, 슬랙 `!whoami`) 보낸 뒤 대화 화면의 "허용 대기" 띠나 **설정 → 메신저 → 허용 요청**에서 **허용**.
4. `/sessions`로 목록을 보고 `/use <번호>`로 이 대화방을 세션에 연결한다. 이후 일반 글은 그 세션에 질문으로 간다.

| 명령(슬랙은 `!`) | 동작 |
| --- | --- |
| `/whoami` | 내 사용자 ID·대화방·허용 여부(허용 전에도 동작) |
| `/sessions` | 연결 가능한 세션과 상태(보낼 수 있음·처리 중·엔진 꺼짐·확인 필요·PC 연결 끊김) |
| `/use <번호>` | 이 대화방을 그 세션에 연결(대화방마다 따로 저장) |
| `/status` | 연결된 세션 상태(확인 필요 질문이 막고 있으면 그때 보낸 세션과 지금 세션이 같은지 한 줄) |
| `/review done` · `/review not` | 결과 불명 질문을 원래 세션 확인 결과로 정리(다시 보내지 않음) |
| (접수 안내) | 웹을 공개 https 주소로 연 적이 있으면 "작업 보기: https://…/#task=…" 링크가 붙음 — 누르면 로그인 뒤 그 작업(질문·승인·결과) |
| `/stop` · `/중지` | 이 대화방의 마지막 질문만 멈추기(보낸 사람·주인만). 시작 전이면 바로 중지됨, 실행 중이면 멈춘 것을 확인한 뒤 "중지됨"을 알림. Claude 창(채널)은 실행 중에는 원래 창에서 |
| `/new codex|claude <이름>` | 새 세션을 만들고 이 대화방에 연결(새 세션 기능을 켠 경우, 6.4) |
| `/sleep`·`/archived`·`/restore`·`/close`·`/limits` | 새 세션 잠재우기·보관 목록·꺼내기·삭제·한도(6.4) |
| `/help` | 명령어 목록 |

## 6. 추가하기

### 6.1 대화방을 더 만들어 다른 세션에 연결

봇을 늘리지 않는다. 새 대화방을 만들고 같은 봇을 넣은 뒤 `/use <번호>`만 하면 된다.

- 텔레그램: 새 그룹(또는 그룹의 새 주제)에 봇 초대 → `/use`.
- 디스코드: 서버에 새 채널(예: `#claude-개발`) → 봇이 서버에 있으므로 바로 `/use`.
- 슬랙: 새 채널 → **Integrations → Add an App** → `!use`.

### 6.2 같은 메신저에 봇 추가(여러 봇)

> 이 절은 **여러 봇 M3까지 완료** 상태 기준이다. 봇 등록·이름·부르는 이름·역할·볼 수 있는 세션은 웹 **설정 → 메신저**에서 한다(④). 역할에서 정한 **엔진·권한 제한**은 그 봇의 `/new`에 적용되고, **AI 역할 안내**는 그 봇에서 `/new`로 만든 새 세션의 첫 질문 앞에 붙는다(기존 세션 연결에는 붙지 않는다). 봇에서 만든 새 세션은 **만든 봇과 웹**에서만 보인다(다른 봇의 `/sessions`에는 나오지 않는다).

같은 봇을 다른 디스코드 서버·슬랙 워크스페이스에 넣는 것은 봇을 늘리는 것이 아니다(그 서버·워크스페이스에 초대·설치만 하면 된다). 아래는 **봇을 하나 더 만드는** 방법이다.

**① 봇 ID 정하기**

봇 ID는 이어온이 봇을 구분하는 이름표다. 영문 소문자·숫자·`-` 2~32자이고 **한 번 정하면 바꾸지 않는다**(토큰 변수 이름·대화방 연결이 여기에 묶임). 사람이 보는 이름·부르는 이름은 웹 **설정 → 메신저**에서 따로 정한다. 지금 쓰는 봇의 봇 ID는 `default`다. 아래 예는 봇 ID `ieun01`.

| 이름 | 예 | 정하는 곳 |
| --- | --- | --- |
| 메신저 쪽 이름 | 텔레그램 `@ieun_cyhuh_bot`, 디스코드 `코드리뷰`, 슬랙 `ieon-review` | 각 메신저(신산님) |
| 봇 ID | `ieun01` | 이어온(신산님이 정해 등록) |
| 표시 이름·역할·부르는 이름 | `코드 리뷰 봇`, `리뷰` | 웹 설정 → 메신저 |

**② 메신저에서 봇(앱) 만들기**

봇(앱)마다 토큰이 따로다. 같은 토큰을 두 봇이나 두 프로그램에 쓰지 않는다.

- 텔레그램: 4.1처럼 `@BotFather` → `/newbot`(이미 만든 봇은 `/mybots` → 봇 → API Token). 그룹에서 쓰면 `/setprivacy` → Disable.
- 디스코드: 4.2처럼 **New Application**을 하나 더 만든다(앱 하나에 봇 하나). Message Content Intent 켜기, OAuth2 URL로 서버에 초대.
- 슬랙: 4.3처럼 **From an app manifest**로 앱을 하나 더 만든다. manifest는 **처음부터 끝까지 전체**를 붙이고 `name`과 `display_name` 두 곳만 바꾼다(일부만 붙이면 오류가 나고 Socket Mode가 꺼진다).

  ```yaml
  display_information:
    name: ieon-review
    description: 이어온 — 이 PC의 작업 세션에 질문을 전달합니다
  features:
    app_home:
      home_tab_enabled: false
      messages_tab_enabled: true
      messages_tab_read_only_enabled: false
    bot_user:
      display_name: ieon-review
      always_online: true
  oauth_config:
    scopes:
      bot:
        - chat:write
        - channels:history
        - groups:history
        - im:history
  settings:
    event_subscriptions:
      bot_events:
        - message.channels
        - message.groups
        - message.im
    interactivity:
      is_enabled: false
    org_deploy_enabled: false
    socket_mode_enabled: true
    token_rotation_enabled: false
  ```

  App-Level Token은 이름 `socket`, scope `connections:write` 하나(`xapp-…`). Install App 후 Bot User OAuth Token(`xoxb-…`).

**③ 토큰은 ④에서 봇을 추가한 뒤 그 봇의 토큰 칸에 넣는다**(채팅에 붙이지 않는다). 토큰 이름 규칙은 이어온이 알아서 정한다.

**④ 이어온에 봇 등록(웹 설정 → 메신저)**

1. 웹 화면(바탕화면 **이어온**)에서 왼쪽 아래 **설정**(⚙) → **메신저** 탭을 누른다(메신저 창의 "고급" 링크로도 온다).
2. 봇 목록 아래에서 메신저를 고르고 **새 봇 ID**를 넣고 **봇 추가**.
3. 목록에서 그 봇을 누르면 편집 칸이 열린다.
   - **이름**: 이어온에서 쓰는 이름(한글 가능)
   - **역할**: 역할 목록에서 고름(없어도 됨)
   - **부르는 이름**: 쉼표로 구분(예: `리뷰, 리뷰봇`). 같은 메신저의 다른 봇과 겹치면 저장되지 않는다. 비워 두면 봇 ID로 부른다.
   - **추가 허용 사용자**: 이 봇에만 더 허용할 메신저 사용자 ID(쉼표 구분)
   - **볼 수 있는 기존 세션**: 이 봇의 `/sessions`에 보일 세션을 체크
   - **켜기**: 끄면 메신저가 이 봇을 띄우지 않는다
   - **토큰**: 메신저에서 받은 토큰을 넣고 저장(다시 보이지 않음, 바꾸려면 새로 넣기·지우기)
   - **상태**: 연결됨·토큰 없음·토큰 중복·실제 봇 이름·텔레그램 그룹 일반 글 수신 꺼짐
4. **저장** → 메신저에 1분 안에 반영된다(토큰도 1분 안에 반영, 다시 켤 필요 없음).
5. 추가 봇의 허용: 그 봇의 **추가 허용 사용자**에 넣거나, 봇에게 말을 건 뒤 **허용 요청**에서 **허용**한다(메신저 창의 숫자 등록은 기본 봇 `default`용이다).
6. **역할**(같은 메신저 탭 아래): 역할 ID·이름·설명·만들 수 있는 엔진·허용 권한(읽기 전용·작업 폴더 안 읽기·쓰기)·AI 역할 안내·기본 세션을 정해 **역할 저장**. 쓰는 봇이 있는 역할은 지울 수 없다.

**⑤ 확인**

- 봇 목록의 상태가 봇마다 "연결됨"인지 본다.
- 그 봇에게 `/whoami`(슬랙 `!whoami`) → **봇 ID**와 **대화방** 키(`<메신저>:<봇 ID>:<대화방>`)가 봇마다 다르게 나오면 정상이다.
- 봇마다 `/sessions`가 다르게 나온다: 기존 세션은 서버 등록의 `appIds`에 그 봇(`app_bot_<메신저>_<봇 ID>`)이 있어야 보인다. 기본 봇은 지금처럼 `app_messenger`.

**⑥ 같은 방에 봇이 여러 개일 때(M2)**

| 상황 | 누가 답하나 |
| --- | --- |
| 1:1 대화 | 그 봇 |
| 그룹·채널에서 **부른** 글 | 부른 봇만. 부르기: 부르는 이름으로 시작(`리뷰, …`·`리뷰: …`·`리뷰야 …`·`@리뷰 …`), 메신저 멘션(`@ieun_cyhuh_bot`·`@코드리뷰`·슬랙 `@ieon-review`), 그 봇 메시지에 답장, 텔레그램 `/명령@봇username` |
| 그룹·채널에서 **부르지 않은** 글 | 그 방에서 세션에 연결된 우리 봇이 하나뿐이면 그 봇. 둘 이상 연결돼 있으면 **아무도 답하지 않음** |
| 아무 봇도 연결 안 된 방 | 부르지 않으면 두 봇이 함께 답할 수 있다 → 처음에는 부르는 이름·멘션으로 `/use`한다 |

- 부르는 이름은 떼고 나머지만 질문·명령으로 보낸다(`리뷰, /use 1` → `/use 1`).
- 역할에 기본 세션이 있으면 연결이 없는 방에서 첫 글을 받을 때 그 세션에 자동 연결하고 알린다.
- `/whoami`·`/help`에 봇 이름·역할·부르는 이름이 나온다.

### 6.3 다른 사람(또는 내 다른 계정) 허용

그 사람이 봇에게 말을 걸면 대화 화면의 "허용 대기" 띠와 웹 **설정 → 메신저 → 허용 요청**에 뜬다. **허용**을 누르면 그 봇의 추가 허용 사용자가 된다. 허용된 사람은 연결된 세션에 질문할 수 있으므로 신산님 본인 계정만 넣는 것을 원칙으로 한다.

### 6.4 메신저에서 새 세션 만들기

이어온이 새 Codex·Claude 세션을 만들어 주는 기능이다. 먼저 웹 **설정 → 대화 → 새 세션**에서 "새 세션 만들기를 켭니다"를 저장한다.

| 명령(슬랙은 `!`) | 하는 일 |
| --- | --- |
| `/new codex <이름>`, `/new claude <이름>` (끝에 `read_only` 가능) | 새 세션을 만들고 이 대화방에 연결 |
| `/sleep <이름>` | 바로 잠재우기(질문하면 다시 깨어남) |
| `/archived`, `/restore <이름>` | 보관 목록, 보관에서 꺼내기 |
| `/close <이름>` → `/close <이름> 확인` | 삭제(이어온 기록만, 되돌릴 수 없음) |
| `/limits` | 새 세션 수와 한도 |

- `full`(명령 실행·인터넷) 권한은 메신저에서 고를 수 없다.
- `/sessions`에는 새 세션 상태(첫 질문 전·깨어 있음·잠듦)가 함께 나오고, 보관된 세션은 빠진다.
- 보관 3일 전부터 하루 한 번, 그 세션에 연결된 대화방에 예고를 보낸다. 메신저 봇을 다시 켠 뒤 그 대화방에서 아직 아무 말도 없었으면 예고를 보내지 못한다.

### 6.5 기존 세션(Codex 대화·Claude 세션)을 봇 목록에 추가

봇 목록(`/sessions`)은 이어온 서버에 등록된 세션이다. 모두 웹에서 한다.

1. Codex 대화는 이 PC 화면에서 **＋ 대화 연결**로 고른다. 허용 목록 추가와 세션 등록이 한 번에 되고, 웹과 기본 봇에 보인다. 목록에 없으면 **＋ 대화 연결 → 고급: 대화 ID 직접 넣기**.
   - Claude 채널 세션이나 허브 화면에서 등록할 때는 **설정 → 대화**의 세션 등록에 이름·엔진·PC·세션 ID를 넣고 저장한다(Codex 대화는 그 PC의 **설정 → 이 PC** 허용 목록에도 있어야 실행된다).
2. 추가 봇에도 보이게 하려면 **설정 → 메신저 → 그 봇 → 볼 수 있는 기존 세션**에서 체크하고 저장한다.

## 7. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 메신저 앱에서 봇이 안 보임 | 봇을 대화 목록에 불러오지 않음 | 텔레그램: `@이름` 검색·Start / 디스코드: 서버 멤버 목록 / 슬랙: Apps 또는 채널 Integrations |
| 봇이 아무 답도 안 함 | 허용 목록에 없음, 봇 미기동, 디스코드 Message Content Intent 꺼짐, 텔레그램 그룹 privacy 켜짐 | `/whoami`로 허용 여부 확인, `messenger.log` 확인 |
| 슬랙 1:1에서 엉뚱한 답 | 같은 앱에 다른 프로그램(`slack run` 등)이 접속 | 그 프로그램 종료 또는 이어온 전용 앱 생성 |
| `/invite @이름` → "A valid member name is required" | 표시 이름과 다름 | 자동 완성에서 고르거나 Integrations → Add an App |
| "연결부에서 실제 실행이 꺼져 있음" | AI 응답(실제 실행) 꺼짐 | 이 PC 화면 위쪽 **AI 응답** 스위치 켜기(허브 새 세션은 허브 **설정 → 허브 보안·Codex**의 허브 새 세션 실제 실행) |
| "이 PC는 허브에 연결돼 있어…" 같은 답 | 이 PC가 허브에 연결돼 있어 PC 봇의 질문을 받지 않음 | 허브에 연결된 봇에서 보내기 |
| "Desktop에서 이 대화를 열고 있어 보내지 않았음" | 번갈아 쓰기 대화를 Codex 앱이 열고 있음 | 앱에서 그 대화를 닫고 다시 질문 |
| "엔진 꺼짐"(Claude) | Claude 채널 세션 미실행 | Claude 채널 세션 시작([MANUAL](MANUAL.md) "Claude 채널 세션") |
| "결과를 확인할 수 없음" | 결과 불명 | 원래 세션 확인 후 `/review done` 또는 `/review not` |
| 같은 세션에 여러 메신저에서 동시에 질문 → 하나만 처리 | 세션당 한 번에 하나 | 답을 받은 뒤 다음 질문 |
| 추가 봇이 안 켜짐(상태 "토큰 없음") | 그 봇의 토큰을 아직 안 넣음 | **설정 → 메신저**의 봇 편집 칸 **토큰**에 넣기 |
| 추가 봇이 아예 로그에 없음 | 이어온 서버에 그 봇을 등록하지 않았거나 꺼져 있음 | **설정 → 메신저**에서 추가·켜기(6.2 ④) |
| 메신저 창에서 메신저를 고를 수 없음 | 그 봇이 꺼져 있음(허브로 옮긴 봇 등) | 이 화면에서 쓸 봇이면 **설정 → 메신저**에서 "이 봇을 켭니다"(같은 봇을 두 곳에서 켜지 않기) |

| 같은 채널에서 두 봇이 함께 답함 | 그 방에 아직 어느 봇도 세션에 연결되지 않음 | 부르는 이름·멘션으로 각 봇을 `/use` |
| 그룹에서 아무 봇도 답하지 않음 | 두 봇이 모두 연결돼 있는데 부르지 않음 | 부르는 이름·멘션으로 부르기 |
| 텔레그램 그룹에서 봇이 일반 글에 반응 안 함 | privacy 켜짐, 또는 설정을 바꾼 뒤 그룹에 다시 넣지 않음 | `/setprivacy` → Disable 후 그룹에서 봇을 내보냈다가 다시 추가 |
| 디스코드 추가 봇이 채널에 없음(로그 `guilds`:0) | 서버에 초대하지 않음 | 4.2의 OAuth2 URL로 초대 |

| 보관 예고가 안 옴 | 봇을 다시 켠 뒤 그 대화방에서 아직 아무 말도 없음 | 그 방에 아무 메시지나 한 번 보내 두기 |
