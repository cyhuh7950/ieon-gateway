# 이어온 허브 운영 설명서 — 여러 사람에게 허브를 열 때

이 문서는 **허브 주인(관리자)**이 이어온 허브를 가족·동료·다른 사람과 같이 쓰도록 열고 운영할 때 볼 설명서입니다. 가입하는 사람용은 [가입자 따라 하기](MEMBER_GUIDE.md), 기능 설명은 [사용 설명서](MANUAL.md)의 "여러 사람이 같이 쓰기", 설계는 [MULTI_USER](design/MULTI_USER.md)에 있습니다.

- 작성 2026-11-19(M4 공용 서비스 운영 준비, 신산님 "9번까지 차례로").
- 기준 허브: `ieun-gateway.sinsan.kr`(신산님 Oracle 서버 Docker), 빈 서버 설치 예: `ieon-daon.sinsan.kr`(daon-server, [SERVER_SESSIONS](design/SERVER_SESSIONS.md) SV4).

---

## 0. 열기 전에 알아 둘 것

| 항목 | 내용 |
| --- | --- |
| AI 사용량·요금 | 가입자는 **자기 PC의 자기 AI 계정**으로 씁니다. 허브 주인의 Codex·Claude 계정을 나눠 쓰지 않습니다(허브 엔진 칸·허브 새 세션은 관리자만). |
| 대화 내용 | 관리자도 가입자의 대화를 **화면·API로는 볼 수 없습니다**. 다만 서버의 DB 파일(`hub/data/s2/pilot.db`)을 직접 열면 볼 수 있으니, 서버 접근 권한은 허브 주인만 갖습니다. |
| 메일 | 이어온은 메일을 보내지 않습니다. 비밀번호를 잊으면 관리자가 **임시 비밀번호**를 만들어 직접 전합니다. |
| 약관·처리방침 | `<허브 주소>/terms`(이용 약관), `<허브 주소>/privacy`(개인정보 처리방침)는 접속 제한과 상관없이 누구나 열 수 있고, 가입할 때 동의를 받습니다. **이어온이 넣어 둔 초안**이니 허브 주인이 읽고 자기 운영에 맞는지 확인하세요(고치려면 서버의 `src/pilot/web/terms.html`·`privacy.html`). |
| 메신저 | 가입자는 허브의 텔레그램·디스코드·슬랙·라인·카카오 봇을 같이 씁니다(6자리 연결). 카카오는 먼저 보내기가 없어 예약 답은 카카오 방으로 가지 않습니다. |

## 1. 여는 순서

1. **https 주소 확인:** 다른 사람이 쓰려면 허브가 https 도메인으로 열려 있어야 합니다(앞단 Nginx Proxy Manager 등). 빈 서버라면 [처음 쓰는 사람용 따라 하기](BEGINNER_GUIDE.md) 8-1.
2. **접속 제한 열기:** 허브 화면 **설정 → 허브 보안·Codex → 보안(허브 접속 제한)**. 지금 IP 목록이면 다른 사람은 닿지 못합니다. 같이 쓸 범위로 바꿉니다(열어도 로그인은 그대로 필요).
3. **약관·처리방침 읽기:** `/terms`, `/privacy`를 열어 내용을 확인합니다.
4. **여러 사람 켜기:** 같은 화면 **여러 사람 → 여러 사람 쓰기(가입 신청 받기)**. 로그인 화면에 **가입 신청**과 **약관 동의 칸**이 생깁니다.
5. **한도 정하기(선택):** 같은 칸의 **가입자 하루 질문 한도**. 비우면 한도 없음. 사람마다 다르게 하려면 목록의 **한도** 칸.
6. **알리기:** 같이 쓸 사람에게 허브 주소와 [가입자 따라 하기](MEMBER_GUIDE.md)를 보냅니다.

## 2. 날마다 하는 일

| 일 | 어디서 | 메모 |
| --- | --- | --- |
| 가입 승인·거절 | 설정 → 허브 보안·Codex → 여러 사람 목록 | 승인 전에는 아무 기능도 못 씀. 약관 동의한 때가 기록됨 |
| 끊기·다시 켜기 | 같은 목록 | 끊으면 바로 로그아웃, 다시 로그인 불가 |
| 임시 비밀번호 | 같은 목록 | 한 번만 보임. 그 사람 로그인은 끊김. 로그인한 뒤 본인이 바꾸게 안내 |
| 지우기 | 같은 목록 | 그 사람의 이어온 기록·방·예약·연결한 PC·앱·메신저 연결 모두 지움(되돌릴 수 없음). 그 사람 PC의 원래 세션 기록은 남음 |
| 사용량 보기 | 같은 목록의 **오늘 질문** | 한국 시간 0시부터 센 질문 수 / 한도 |
| 한도 바꾸기 | 같은 칸 | 기본(모든 가입자)과 사람별. 0 = 그 사람만 한도 없음 |

**한도에 걸리면:** 가입자 화면·메신저에 "오늘 보낼 수 있는 질문 수를 다 썼어요"가 뜨고 보내지 않습니다(자동으로 다시 보내지 않음). 관리자는 한도가 없습니다.

## 3. 업데이트·백업·복원

- **업데이트(신산님 허브):** 개발 쪽에서 `deploy_w3.sh`처럼 저장소 최신본을 서버 `~/deploy/ieon-gateway`에 풀고 `docker compose -f deploy/hub/compose.yaml build` → `stop` → **백업** → `up -d`. 배포 전에 데이터 폴더 `hub/data/s2`를 `backups/<이름>-<시각>`으로 복사합니다.
- **새 서버 설치·업데이트(빈 서버 설치형):** 허브 화면 **설정 → 허브 보안·Codex → 새 서버에 설치**에서 만든 명령(1시간, 관리자만)을 그 서버에 붙여 넣으면 이 허브의 판으로 설치·업데이트(적은 값·데이터는 그대로). 묶음은 허브 이미지 안 `/app/ieon-gateway.tar.gz`(소스만, 비밀값 없음)라 열쇠 없이는 내주지 않는다(저장소가 비공개라서). 다시 설치하면 이미 있는 엔진 칸도 새 판으로 다시 만든다(데이터·로그인 그대로). 칸 하나만은 `sh deploy/hub/ieun.sh engine update <칸 이름>`.
- **백업 대상:** `hub/data/s2`(DB·설정·기기 열쇠 해시), `hub/data/messenger`(봇 토큰 파일 — 비밀), `hub/data/apps`(내려받는 앱 파일), `hub/data/shared-auth`(서버 Claude·Codex 로그인 — 비밀). 비밀 파일이 든 백업은 서버 밖으로 옮기지 않습니다.
- **복원:** 컨테이너를 멈추고 `hub/data/s2`를 백업본으로 바꾼 뒤 다시 켭니다.
- 화면(첫 화면·설정)은 매번 서버에 새로 물어보므로 배포 뒤 새로 고침이 필요 없습니다.

## 4. 문제가 생겼을 때

| 증상 | 확인 |
| --- | --- |
| 가입자가 허브에 닿지 못함 | 접속 제한(1-2), 앞단 도메인·인증서 |
| "가입 신청" 단추가 없음 | 여러 사람 쓰기가 꺼져 있음(1-4) |
| 가입자 질문이 "기기 없음"·"꺼짐" | 그 사람 PC의 이어온이 꺼졌거나 PC 연결 링크로 연결하지 않음 |
| 가입자가 쓰던 Codex 대화가 목록에 안 나옴 | 그 PC가 꺼짐, Codex 앱 로그인, 업무 대화는 일부러 뺌 |
| 서버가 느림 | `docker stats`로 `ieun-relay` 메모리(기본 한도 2g)·엔진 칸 확인, 한도 낮추기 |
| 이상한 접속이 많음 | 접속 제한을 다시 좁히고, 끊기로 그 사람을 막음. 로그에는 질문·답·비밀값이 남지 않음 |

## 5. 아직 하지 않은 것(2026-11-19)

- 카카오 가입자 연결의 실제 계정 확인.
- 공용 봇·다른 사람 PC 연결의 실제 계정 확인(대역 시험만).
- 가입자 수가 많을 때의 사양 실측.
