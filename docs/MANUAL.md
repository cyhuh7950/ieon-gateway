# 이어온 사용 설명서 (요약판)

- 기준: 2026-11-12(새 화면 U1~U7 반영) · 대상: 신산님
- 원칙: **모든 설정은 웹 화면에서, 토큰은 이어온이 내부에서 처리한다.** 사용자가 설정 파일을 고치거나 토큰을 옮기지 않는다([WEB_FIRST](design/WEB_FIRST.md)).
- 형태: PC 완결형(내 PC의 `http://127.0.0.1:28760`)과 허브형(`https://ieun-gateway.sinsan.kr` + PC 연결).
- 기능 두 가지: **기존 세션 연결**(이 PC에 이미 있는 Codex 대화·Claude Code 세션에 질문)과 **새 세션 만들기**(이어온이 새 Codex·Claude 세션과 작업 폴더를 만듦, 기본 꺼짐).
- 처음이라면 [따라 하기 설명서](BEGINNER_GUIDE.md)(설치·설정 포함), 내 프로그램 연결은 [개발 프로그램 연동 설명서](API_GUIDE.md)를 본다.
- 판정 근거: [첫 실증 결과서](validation/FIRST_CONTINUITY_RESULT.md), 설계: [DESIGN](design/DESIGN.md)

## 1. 이어온이 하는 일

이어온은 웹 화면에서 보낸 질문을 **이미 쓰고 있는 작업 세션**에 넣고 그 세션의 답을 돌려준다. 새 대화를 만들거나 대화를 복사하지 않는다.

| 엔진 | 연결 방식 | 사람이 보는 화면 |
| --- | --- | --- |
| Codex · 번갈아 쓰기(`alternate`, 기본) | 질문마다 같은 대화를 SDK로 다시 열어 이어 쓰고 바로 놓는다 | Codex Desktop(필요할 때) |
| Codex · 동시 사용(`shared_server`) | 공유 App Server 하나에 사람(TUI)과 이어온이 함께 붙는다 | 공식 Codex TUI |
| Claude Code · 채널 | 실행 중인 Claude Code 세션에 이어온 채널로 질문을 넣고 `reply`로 답을 받는다 | Claude Code 터미널 |

구성은 세 부분이다.

- **이어온 서버**(`127.0.0.1:28760`): 웹 화면·API, 대화와 요청 상태 보관.
- **연결부**: 이 PC에서 서버로 먼저 접속해 질문을 가져가 엔진에 넣는다. 외부에 포트를 열지 않는다.
- **엔진**: Codex 대화, 공유 App Server(`28761`), Claude 채널(`28762`).

## 2. 처음 한 번 준비

- **리눅스 서버에 설치(서버 설치형·허브형):** 서버에서 `git clone` 뒤 `sh deploy/server/install.sh` 한 번 — 질문은 대부분 Enter, 나머지(관리자 비밀번호·Codex/Claude 로그인·메신저)는 웹 화면에서. 준비물·권장 사양·설치 뒤 할 일은 [처음 쓰는 사람용 따라 하기 8-1](BEGINNER_GUIDE.md). 서버 설치형은 PC 연결 화면이 숨겨지고, **설정 → 기기 → PC 연결 켜기**로 허브형이 됩니다(데이터 그대로).
- **작업 폴더(AI 직원별 폴더):** **설정 → 작업 폴더**에서 그 PC(허브는 PC·칸을 고름)의 폴더를 이름 붙여 등록하고, 직원마다 [폴더 정하기]로 개인 폴더 하나와 공유 폴더(읽기만 / 읽기·쓰기)를 붙인다. 저장할 때 "실제로 막히는 정도"를 보여 주고 승인을 받는다 — Codex는 작업 모드에서 파일을 고칠 때마다 승인 카드로 묻고(카드에 고칠 파일 경로, 작업 폴더 밖이면 "작업 폴더 밖" 표시), 사람이 허용해야만 써진다 — 허용하면 작업 폴더 밖도 써지므로 "작업 폴더 밖" 카드는 잘 보고 누른다. 읽기는 막지 못하고(정리만), 다른 엔진은 폴더를 안내만 한다. 임시 폴더 아래는 등록할 수 없다. 폴더를 붙이지 않은 직원은 지금과 똑같다. 메신저 `/status`에는 폴더 이름만 나온다. Claude(서버 대화·새 세션)는 붙인 폴더 밖 파일을 읽지도 고치지도 못하고(차단), 공유(읽기만) 폴더는 읽기만 된다(full 권한 새 세션은 명령 도구가 있어 정리만). 새 세션에는 공유 폴더만 붙인다(개인 폴더는 자동으로 만든 작업 폴더). 허브 새 세션은 작업 폴더 탭에서 "허브 자체"를 고른다.
- **Claude가 막힌 작업:** Claude 새 세션·서버 대화에서 권한 설정에 막힌 작업(예: 읽기만 폴더 고치기)은 실행되지 않고, 답 끝에 "[이어온] 권한 설정에서 막혀 실행되지 않은 작업"으로 무엇이 막혔는지 나온다. 대화는 멈추지 않는다.
- **예약 작업:** **설정 → 대화 → 예약 작업**에서 대화·언제(매일 시각/간격/한 번)·질문·하루 최대를 넣고 만들면, 그때 그 대화에 질문이 가고 답은 대화에 쌓인다. 만들 때·다시 켤 때 확인을 받는다(사람이 없을 때 AI가 호출됨). 질문만 보내고(작업 모드 대화는 건너뜀), 처리 중이거나 PC가 꺼져 있으면 그 회차는 건너뛴다(자동으로 다시 보내지 않음). 지난 예약 질문의 결과를 확인할 수 없으면 그 예약은 멈추고, 정리한 뒤 **다시 켜기**를 누르면 다시 보낸다. 답은 그 대화에 연결된 메신저 방(텔레그램·디스코드·슬랙·라인)에도 "[이름] 예약 질문(매일 09:00) 답:"으로 올라온다.
- **동시 질문 수:** PC·엔진 칸 하나가 한꺼번에 맡는 질문(기다림 + 처리 중)은 기본 3개. 넘으면 줄 세우지 않고 "그 PC·칸이 다른 질문을 여러 개 처리 중"으로 알려 주고 자동으로 다시 보내지 않는다(카드의 **다시 보내기**는 누를 때만). 바꾸기: **설정 → 대화 → 동시 질문 수**(0 = 한도 없음).

[따라 하기 1절](BEGINNER_GUIDE.md): 이어온 폴더에서 `pwsh scripts/install.ps1` 한 번. 부품 설치·설정과 내부 토큰 생성·로그온 자동 시작·바탕화면 바로 가기까지 한다. Edge가 있으면 바로 가기 **이어온**은 Edge 앱 창(주소창·탭 없는 자기 창)으로, 없으면 브라우저 탭으로 열린다. 설정·토큰은 `.local\`(git 제외)에 있고 화면에 나오지 않는다.

이 PC 화면을 처음 열면(연결한 대화가 없을 때) **처음 설정 3단계**가 뜬다: ① 준비 확인(이 PC의 Codex 로그인 여부) ② 대화 고르기(이 PC에서 최근에 쓴 Codex 대화 중 하나 — 유일한 필수 선택) ③ 준비됐어요(메신저·허브는 선택, **대화 열기**). 다시 열려면 주소 끝에 `/#setup`을 붙인다. 나머지 설정은 화면 왼쪽 아래 **설정**(⚙)에서 한다. **업무 대화 `01a0dadd-…`는 목록에 나오지 않고 연결할 수도 없다**(서버에서 빼고 거부).

## 3. 켜고 끄기

- 이어온은 **로그온하면 창 없이 자동으로 켜진다**(작업 스케줄러 `ieon-gateway`). 서버가 연결부와 메신저를 함께 띄우고, 하나가 끝나면 다시 띄운다.
- AI 호출(AI 응답)은 설치 때 켜져 있다(2026-11-18부터, 꺼 둔 채 설치하려면 `pwsh scripts/install.ps1 -AiOff`). 끄기는 대화 위쪽 **AI 응답** 스위치(같은 설정이 **설정 → 이 PC**의 "실제 실행 켜기"). 로그인한 웹 화면이면 어디서나(휴대폰·Tailscale 포함) 바꿀 수 있다. 꺼져 있으면 메신저·API 질문은 실행되지 않는다.
- Codex 대화는 보통 **＋ 대화 연결**에서 고르면 허용 목록 추가와 세션 등록이 한 번에 된다. 허용 목록을 직접 추가·빼기(연결 방식·작업 폴더 포함)는 **설정 → 이 PC**. 바꾸면 연결부가 새 설정으로 다시 시작한다.
- 완전히 끄기(자동 시작도 해제): `pwsh scripts/install.ps1 -Uninstall`(설정·기록은 남음).
- 다시 켜기·새 버전 적용: `pwsh scripts/install.ps1`(설정과 토큰은 그대로, 새 코드로 다시 시작).
- PC를 끄면 함께 꺼지고, 다음 로그온 때 자동으로 켜진다. 설치부터 지우기까지의 순서는 [따라 하기](BEGINNER_GUIDE.md) 10절.
- 로그: `.local\run\server.log`(질문·답변·토큰 원문은 남기지 않는다).

### 허브에 연결하기(허브형)

가장 쉬운 방법(PC 연결 링크):

1. 허브 화면 **설정 → 밖에서도 쓰기 → PC 연결 링크 → 링크 만들기**. 링크는 10분 동안 한 번만 쓸 수 있다.
2. 그 링크를 연결할 PC에서 연다. "이 PC를 허브에 연결할까요?"와 허브 주소가 나오면, **내가 만든 링크가 맞을 때만** **연결**을 누른다(이 PC 이름은 비우면 컴퓨터 이름). 코드 확인 없이 끝난다.

직접 하는 방법(6자리 코드):

1. 이 PC 화면 **설정 → 밖에서도 쓰기 → 허브에 연결**: 허브 주소(이 PC 이름은 선택) → **연결** → 6자리 코드.
2. 허브 화면 **설정 → 밖에서도 쓰기 → 연결 요청**: 같은 코드면 **승인**(같은 PC를 다시 연결하면 "기존 기기 대체").

연결되면 토큰은 허브에서 이 PC로 내부 전달되고, 이 PC 서버가 허브용 연결부를 띄운다. 재부팅 뒤에도 자동으로 다시 연결된다. **다시 연결**·**연결 끊기**·**허브 잊기**는 이 PC 화면 **설정 → 밖에서도 쓰기**에서 한다. 허브 화면의 대화 목록은 PC 이름별로 묶여 보인다.

- 허브 연결 중에는 이 PC 서버가 자기 작업을 내주지 않는다(같은 PC가 두 서버의 질문을 함께 실행하지 않게). 그래서 PC 화면에서는 질문을 받지 않고 "이 PC는 허브에 연결돼 있어요" 카드(**허브 화면 열기**)가 뜬다. 허브 화면이나 허브에 연결된 메신저 봇에서 보낸다.
- 실제 답을 받으려면 이 PC의 AI 응답(실제 실행)이 켜져 있어야 한다.
- 이 PC의 안전 설정(허용 목록·실제 실행·작업 폴더)은 허브에서 바꿀 수 없다.
- 허브 주소는 `https`만 받는다. 허브는 기기마다 1분 240번까지 받고 넘으면 429(연결부는 기다렸다 다시 묻고, 질문을 다시 보내지 않음).

### Claude 채널 세션

```powershell
pwsh scripts/ieon.ps1 claude
```

새 창에서 `claude --dangerously-load-development-channels server:ieon`이 시작된다.

- 구독 계정(Pro/Max)으로 로그인돼 있어야 한다. 처음이면 그 창에서 `/login`을 신산님이 직접 한다. 비구독 계정은 연결되지 않고, API 키 로그인은 유료 경로이므로 쓰지 않는다.
- 하단이 `manual mode`인지 확인한다. `auto mode`면 `shift+tab`으로 끈다.
- 이 창에는 질문을 직접 입력하지 않는다(입력해도 이어온으로 답이 가지 않는다).
- 끝낼 때 `/exit`. 세션이 꺼지면 채널도 꺼진다.

### Codex 동시 사용(TUI, 고급)

공유 App Server와 Codex TUI를 함께 띄우는 개발용 기능이라 아직 웹 화면이 없다. 보통은 "번갈아 쓰기"를 쓴다. 쓰려면 먼저 `pwsh scripts/install.ps1 -Uninstall`로 자동 시작을 내린 뒤(연결부가 둘이 되지 않게) 아래를 실행하고, 끝나면 `stop` 후 `pwsh scripts/install.ps1`로 되돌린다.

```powershell
pwsh scripts/ieon.ps1 start -Shared
pwsh scripts/ieon.ps1 tui
```

- 이 모드의 대화는 **Codex Desktop 앱에서 열지 않는다**(잠금 충돌).
- hook 확인 화면이 나오면 "Continue without trusting"을 고른다.

## 4. 웹 화면 쓰기

1. 바탕화면 **이어온**(또는 `http://127.0.0.1:28760`)을 연다. 이 PC에서 연 화면은 자동 로그인된다. 허브는 관리자 비밀번호로 로그인한다(처음에는 "관리자 만들기").
2. 왼쪽 목록에서 대화를 고른다. 줄마다 엔진·상태 한 줄이 있고, 처리할 일이 있으면 개수 배지가 붙는다. 목록 맨 위에 **＋ 대화 연결**, 왼쪽 아래에 **메신저**·**설정**(⚙)이 있다.
3. 아래 입력창에 질문을 쓰고 **보내기**(Enter, 줄바꿈은 Shift+Enter). 접수 → 실행 중 → 완료 순서로 표시된 뒤 답이 나온다.

대화 위쪽에는 대화 이름·엔진·상태, **AI 응답** 스위치(이 PC 화면만), **연결 설정**이 있다. **연결 설정**을 누르면 오른쪽에 엔진·잇는 방법·상태가 나오고, 새 세션이면 잠재우기·삭제, **고급**에 Codex 연결 방식과 대화 ID가 있다.

### 대화 연결하기(＋ 대화 연결)

이 PC 화면에서 **＋ 대화 연결**을 누르면 이 PC에서 최근에 쓴 Codex 대화 목록이 나온다(10초쯤 걸림, 업무 대화는 서버가 빼고 보여 준다). 하나를 누르면 허용 목록 추가(번갈아 쓰기)와 세션 등록이 한 번에 되고 그 대화가 열린다. 작업 폴더는 자동으로 정해진다. 목록에 없으면 **고급: 대화 ID 직접 넣기**. 허브 화면에서도 같다 — **＋ 대화 연결**을 누르면 허브가 내 PC(둘 이상이면 고름)에 목록을 물어 와 보여 주고, 고르면 그 PC의 허용 목록 추가와 세션 등록이 한 번에 된다(PC가 켜져 있어야 함). 허브 **설정 → 이 PC**에서 PC를 고르고 **그 PC의 Codex 대화 → 대화 목록 불러오기**로도 연결할 수 있다. Claude 채널 세션 등록도 **설정 → 대화**에서 한다.

### 상태 문구와 카드

| 상태 문구 | 뜻 | 할 일 |
| --- | --- | --- |
| 보낼 수 있음 | 엔진 준비됨 | 질문 가능 |
| 처리 중 | 이 대화의 질문이 실행 중 | 끝날 때까지 기다림 |
| 확인 필요 | 결과를 모르는 질문이 있어 잠김 | 아래 "확인 필요 정리" |
| 잠듦 · 질문하면 깨어나요 | 쉬고 있는 새 세션 | 그대로 질문 |
| PC 연결 끊김 | 연결부가 꺼져 있음 | 그 PC가 켜져 있는지, 허브형이면 PC 화면 **설정 → 밖에서도 쓰기**가 연결됨인지 |
| Claude 세션 꺼짐 | Claude 채널 세션이 꺼져 있음 | Claude 채널 세션 시작(위 "Claude 채널 세션") |
| 공유 서버 꺼짐 | 동시 사용 모드인데 공유 App Server가 꺼짐 | **연결 설정 → 고급**에서 번갈아 쓰기로 전환 |
| 허브에 연결됨 · 여기서는 못 보냄 | 이 PC가 허브에 연결돼 있음 | 허브 화면에서 보냄 |

문제가 있으면 대화 안에 **카드**가 이유와 버튼을 함께 보여 준다: 이 PC는 허브에 연결돼 있어요(**허브 화면 열기**), PC 연결이 끊겼어요, Claude 세션이 꺼져 있어요 / 공유 서버가 꺼져 있어요, 확인이 필요한 질문(**실행됐어요** / **실행되지 않았어요**), 보관된 세션이에요(**꺼내기**), AI 응답이 꺼져 있어요(**AI 응답 켜기**), 허브의 Codex 로그인이 필요해요(허브 화면, 설정으로 이동), 보내지 못한 질문.

**보내지 못한 질문**의 **다시 보내기** 버튼은 보내지 않은 것이 확실할 때만 나온다(Codex 앱에서 열림·공유 서버 사용 중·처리 중·동시 한도). 사용자가 누를 때만 보내고, 자동으로 다시 보내지 않는다. 결과를 모르는 질문은 다시 보내기 대상이 아니다.

### Codex 연결 모드 바꾸기

Codex 대화에서 **연결 설정 → 고급 → Codex 연결 방식**을 고른다.

- **번갈아 쓰기**: Desktop과 이어온 중 한쪽만 쓰거나 이어온 전용 대화일 때. 보낼 때 그 대화가 Desktop에서 열려 있으면 "Desktop에서 이 대화를 열고 있어 보내지 않았음"으로 거절된다. 앱은 켜져 있어도 되고 **그 대화만 닫으면** 된다. Desktop에는 대화를 다시 열 때 이어온 질문·답이 보인다.
- **동시 사용**: 사람(TUI)과 이어온이 앱 종료 없이 같은 대화를 쓴다. 이어온 질문·답이 TUI에 바로 보인다.
- 처리 중이거나 확인이 필요한 질문이 있으면 모드를 바꿀 수 없다.

### 휴대폰에서 쓰기(Tailscale)

- **권장: 휴대폰에서는 허브형을 쓴다.** 휴대폰 브라우저에서 허브 주소를 열고 **홈 화면에 추가**(Android Chrome은 "앱 설치"로 보일 수 있음, iPhone Safari는 공유 버튼에서)를 하면 앱처럼 아이콘이 생긴다. 좁은 화면에서는 목록 ↔ 대화가 전환되고 버튼이 크게(44px 이상) 나온다. 오프라인 저장은 하지 않는다. 허브는 허용한 곳에서만 열린다(허브 화면 **설정 → 허브 보안·Codex**의 접속 제한).
- 아래 PC 직접 공개는 고급 설정이라 아직 웹 화면이 없고 관리자가 설치 때 설정 파일에 넣는다: `extraHosts`(이 PC Tailscale 주소)·`extraAllowedClients`(휴대폰 Tailscale 주소)를 두면 그 주소에서도 열린다. Tailscale 주소(100.64.0.0/10)만 허용되며 0.0.0.0·집 와이파이 주소로는 열리지 않는다. 허용 목록 밖 기기는 403.
- 휴대폰에서 Tailscale을 켜고 `http://<이 PC Tailscale 주소>:28760`을 연다. 통신은 Tailscale이 암호화한다.
- 쓰지 않을 때는 두 항목을 지우거나 `stop`으로 끈다.

### 메신저에서 쓰기(텔레그램·디스코드·슬랙)

자세한 봇 만들기·추가·문제 해결은 [메신저 설정 설명서](MESSENGER_MANUAL.md)를 본다.

봇은 메신저마다 여러 개 둘 수 있다(**설정 → 메신저**). 대화방(텔레그램 그룹·주제, 디스코드 채널, 슬랙 채널)마다 세션 하나를 연결하거나, 봇과의 1:1 대화에서 `/use`로 대상 세션을 고른다. 모두 이 PC에서 메신저로 먼저 접속하므로 공개 주소·Tailscale이 필요 없다. 카카오톡은 공개 중계(PC 완결형) 또는 허브(허브형)를 거친다.

1. 화면 왼쪽 아래 **메신저** → 메신저 고르기(텔레그램·디스코드·슬랙·카카오톡). 꺼 둔 봇(허브로 옮긴 봇 등)은 고를 수 없다.
2. 짧은 안내를 따라 봇 토큰을 칸에 넣는다(텔레그램·디스코드 1칸, 슬랙 2칸, 이미 저장돼 있으면 바꿀 때만). 저장한 값은 다시 보이지 않는다. 카카오톡은 스킬 URL을 복사해 오픈빌더 스킬 URL에 붙인다.
3. 봇이 연결되면 6자리 숫자가 크게 나온다. 그 숫자를 봇에게 보내면 보낸 사람이 그 봇의 주인(허용 사용자)으로 등록된다("○○님이 주인으로 등록됐어요"). 숫자는 10분·1회용이고, 5번 틀리면 잠겨 새로 받아야 한다. 이미 허용된 사람이 보내면 봇이 "이미 허용된 분이라 따로 등록하지 않았어요"라고 답하고 화면은 완료로 바뀐다.
   - 다른 방법: 봇에게 아무 말이나 보낸 뒤 대화 화면의 "허용 대기" 띠나 **설정 → 메신저 → 허용 요청**에서 **허용**. 허용 목록 밖 사용자에게는 `/whoami` 외에 응답하지 않는다.
4. 명령어: `/sessions`, `/use <번호>`(이 대화방을 세션에 연결), `/status`, `/review done|not`(확인 필요 정리), `/stop`(이 대화방의 마지막 질문만 멈추기), `/help`. 그 밖의 글은 연결된 세션에 질문으로 간다. 슬랙에서는 `/` 대신 `!`(예: `!sessions`)를 쓴다.

메신저별 준비:

- 텔레그램: BotFather `/newbot`. 그룹에서 쓰려면 BotFather `/setprivacy` → Disable(또는 1:1 대화만 사용).
- 디스코드: Developer Portal → Bot → **Message Content Intent** 켜기, OAuth2 URL Generator(bot, Send Messages·Read Message History)로 내 서버에 초대.
- 슬랙: 앱 생성 시 AI 연결(Claude/OpenAI) 템플릿이 아니라 **From scratch**. Socket Mode 켜기(App-Level Token `connections:write` → xapp), Bot Token Scopes `chat:write`·`channels:history`·`groups:history`·`im:history`, Event Subscriptions의 bot events `message.channels`·`message.groups`·`message.im`, App Home의 Messages 탭 허용, 워크스페이스에 설치(xoxb) 후 채널에 앱 초대.

### 개발 프로그램에서 쓰기(HTTP API)

자세한 따라 하기·예제(PowerShell·Node·Python·curl)는 [개발 프로그램 연동 설명서](API_GUIDE.md)를 본다.

직접 만든 프로그램은 웹 화면·메신저 봇과 같은 HTTP API를 부른다. 엔진을 직접 부르지 않는다. 서버에 질문을 접수하면 연결부가 가져가 Codex 대화·Claude 채널 세션에 넣고, 프로그램은 결과를 조회한다.

- 주소: `http://127.0.0.1:28760`(Tailscale 허용 기기는 `http://<이 PC Tailscale 주소>:28760`).
- 인증: 모든 `/v1/` 요청에 `Authorization: Bearer <API 키>`. 키가 틀리거나 폐기됐으면 401.
- API 키는 **설정 → 내 프로그램 연결**에서 프로그램마다 발급한다(한 번만 보임). 그 프로그램이 볼 세션을 체크해 저장하고, 필요 없어지면 폐기. 설정 파일은 고치지 않는다.

| 요청 | 하는 일 | 응답 |
| --- | --- | --- |
| `GET /v1/conversations` | 세션 목록 | `conversationId`·`label`·`engine`·`deviceOnline`·`busy`·`engineReady`·`heldBy` |
| `POST /v1/conversations/<id>/requests` | 질문 접수 | 202 `{"requestId"}` |
| `GET /v1/requests/<requestId>` | 결과 조회 | `status`·`answer`·`errorCode`·`usage` |
| `POST /v1/requests/<requestId>/review` | 확인 필요 정리, 본문 `{"executed": true\|false}` | 정리된 `status` |
| `GET /v1/tasks?filter=active\|all` · `GET /v1/tasks/<requestId>` | 작업(질문 단위) 목록·하나(질문·승인 결과·답) | `tasks` · 작업 |
| `GET /v1/approvals` | 모든 대화의 기다리는 승인과 사람에게 넘긴 일(`handoff: true`) | `approvals` |
| `GET·PUT /v1/conversations/<id>/handoff` | "사람이 직접 할 일" 규칙(PUT은 웹 화면만), 본문 `{"kinds":["command"\|"file"\|"permissions"], "patterns":["git push"]}` | 규칙 |
| `POST /v1/requests/<requestId>/stop` | 그 질문만 멈추기 | 200 `cancelled`(시작 전) · 202 `stopping`(실행 중 → 확인 뒤 `cancelled`) · 409 `not_running`·`stop_unsupported` |
| `GET /v1/conversations/<id>/messages` | 그 세션의 이어온 질문·답 기록 | `messages` |
| `DELETE /v1/conversations/<id>/messages` | 기록 삭제 | 204 |
| `PUT /v1/conversations/<id>/settings` | Codex 연결 모드, 본문 `{"connectMode": "alternate"\|"shared_server"}` | `connectMode` |

질문 접수에는 `Idempotency-Key` 헤더가 필요하다(영문·숫자·`_`·`-` 8~64자, 질문마다 새 값). 같은 키를 다시 보내면 새로 실행하지 않는다. 네트워크 오류로 접수 결과를 모를 때는 **같은 키로** 다시 보낸다.

```powershell
$token = $env:IEON_API_KEY   # 웹에서 발급한 키를 내 프로그램 환경 변수에 둔다
$h = @{ Authorization = "Bearer $token" }
$base = 'http://127.0.0.1:28760'
Invoke-RestMethod "$base/v1/conversations" -Headers $h
$r = Invoke-RestMethod "$base/v1/conversations/c_claude_test/requests" -Method Post -ContentType 'application/json' `
  -Headers ($h + @{ 'Idempotency-Key' = "myapp-$([guid]::NewGuid())" }) -Body (@{ question = '안녕' } | ConvertTo-Json)
do { Start-Sleep 2; $s = Invoke-RestMethod "$base/v1/requests/$($r.requestId)" -Headers $h } while ($s.status -in 'queued', 'dispatching', 'running')
$s
```

결과 `status` 처리:

- `completed`: `answer`가 답이다.
- `failed`: `errorCode`를 보고 원인을 고친 뒤 새 키로 다시 보낼 수 있다.
- `unknown`·`approval_required`: **자동으로 다시 보내지 않는다.** 원래 세션에서 확인한 뒤 `review`로 정리한다("확인 필요 정리"와 같다). 정리 전까지 그 세션은 잠긴다.

접수 오류: 400 `bad_request`(키·질문 누락, 질문 길이 초과), 404 `not_found`(없거나 허용되지 않은 세션), 503 `device_unavailable`(연결부 꺼짐), `session_not_running`(Claude 세션 꺼짐), `shared_server_down`(공유 App Server 꺼짐), 409 `conversation_busy`(처리 중·확인 필요 잠금), `idempotency_conflict`(같은 키에 다른 질문).

실제 답을 받으려면 AI 응답(실제 실행)을 켜야 하고, Claude 세션은 채널 세션을 띄워 둔다. 기존 Codex 대화는 웹 **＋ 대화 연결**로 먼저 연결한다(허용 목록 추가·세션 등록이 한 번에 됨).

### 작업 모드(Codex, 승인 카드)

대화별로 켜는 "작업 모드"에서만 Codex가 파일 수정·명령 실행을 할 수 있고, 할 때마다 [허용]/[거부] 카드(웹)나 `/허용 n`·`/거부 n`(메신저, 주인만)으로 묻는다. 이번 한 번만, 정한 시간(기본 15분, **설정 → 허브 보안·기다리는 시간**에서 15분~24시간) 무응답·차례 끝은 거부, 쓰기는 작업 폴더 안·인터넷 없음, 승인 판단은 사람. 허용한 뒤의 실제 결과(실행 중 → 완료·실패·결과 불명)가 같은 카드와 메신저 대화방에 표시되고, 번호 n은 웹·메신저가 같다. 자세한 순서는 [BEGINNER_GUIDE 5-2](BEGINNER_GUIDE.md).

### 새 세션 만들기

이어온이 새 Codex·Claude 세션과 전용 작업 폴더를 만드는 기능(기본 꺼짐). 켜기·한도·잠들기·보관·기본 권한은 **설정 → 대화 → 새 세션**, 설계는 [NEW_SESSIONS](design/NEW_SESSIONS.md).

- 만들기: 화면 왼쪽 위 **＋ 새 세션**(기능이 켜져 있을 때만 보임 — 엔진·이름·권한을 고르고 만들기), 메신저 `/new codex|claude <이름>`, API `POST /v1/sessions`.
- 정리: 30분 유휴 잠듦(질문하면 깨어남) → 14일 미사용 보관(꺼내야 질문 가능) → 삭제는 이름 확인. 웹은 **연결 설정**의 잠재우기·삭제, 목록 아래 보관함과 "보관된 세션이에요" 카드의 **꺼내기**, 메신저 `/sleep`·`/archived`·`/restore`·`/close`·`/limits`.
- 기본 권한은 작업 폴더 안 읽기·쓰기. `full`(명령 실행·네트워크)은 **설정 → 대화 → 새 세션**의 "full 권한" 스위치를 켜야 고를 수 있다(켤 때 확인 창, 2026-11-18부터).
- **어디서(허브형, SV2):** 허브에 엔진 칸·PC가 있으면 만들기 창에 "어디서"가 보인다. **기본은 켜진 첫 엔진 칸**(2026-11-18부터 — 웹·앱·메신저 `/new` 모두, 고르지 않으면 그 칸). 엔진 칸(예: 서버 · test1 — 목록에 "명령·파일 작업까지")은 명령·파일 작업까지 하고(Codex 새 세션은 칸 컨테이너가 경계, 칸 밖·허브 데이터는 못 건드림), 허브 자신은 글로만 답한다. 엔진 칸이 없거나 모두 꺼져 있으면 허브 자신에 만든다.
- **서버 Claude 로그인(허브형, 한 번만):** 허브 화면 **설정 → 계정 → Claude 계정**에서 **로그인(구독)** → **승인 창 열기**에서 Claude 계정으로 승인 → 나온 코드를 복사해 이어온 칸에 붙여 넣기 → "로그인됨 · 구독". 또는 **API 키**(sk-ant-…)를 한 번 넣는다. 허브와 모든 엔진 칸이 이 로그인 하나를 같이 쓰고(칸마다 로그인하지 않음), 토큰·키는 화면에 다시 보이지 않는다. 설치 때 서버 이어온 폴더 환경 파일에 `ANTHROPIC_API_KEY=...`를 적어 두면 자동으로 들어간다. PC의 Claude는 기본으로 그 PC의 Claude Code 로그인을 쓰고, **설정 → 계정 → Claude 계정**에서 이어온 전용 계정을 여러 개 둘 수 있다(이름표 → 로그인: 승인 창에서 승인 후 코드 붙여 넣기, 또는 API 키 → **기본으로 쓸 Claude 계정**). 고른 계정은 Claude 새 세션과 새로 여는 Claude 채널 창(`ieon.ps1 claude`)에 쓰이고, 로그인 전이면 보내지 않는다. 대화 기록은 계정과 상관없이 그 PC의 것을 이어 쓴다. 허브에서도 PC를 골라 같은 화면으로 바꾼다.
- **서버 칸의 Claude 대화 고르기(허브형):** 서버에서 `ieun.sh engine claude <칸> [이름]`으로 직접 연 Claude 대화도 이어온에서 이어 쓸 수 있다. 허브 화면 **설정 → PC 설정**에서 그 칸(서버 · 이름)을 고르면 **서버 Claude 대화** 표에 최근 대화가 제목·폴더·시간으로 나온다 → **연결**을 누르면 바로 대화 목록에 생기고, 질문은 같은 대화로 이어진다. 서버에서 그 폴더의 Claude 화면을 열어 둔 동안에는 보내지 않고 "사용 중"으로 알려 준다(닫고 다시 보내기). 명령 실행은 열지 않고 파일 읽기·고치기까지만.

### 여러 봇·역할

기본 봇 하나는 **메신저** 창으로 충분하다. 봇을 더 두거나 이름·부르는 이름·역할·볼 수 있는 기존 세션·추가 허용 사용자·켜기·토큰을 바꾸려면 **설정 → 메신저**로 간다(메신저 창의 "고급" 링크도 여기로 온다). 토큰은 다시 보이지 않는다. 자세한 순서는 [메신저 설정 설명서](MESSENGER_MANUAL.md) 6.2.

### 여러 사람이 같이 쓰기(허브형, 2026-11-19)

허브를 가족·동료와 같이 쓰는 기능(기본 꺼짐). 가입한 사람은 **자기 PC의 자기 세션만** 쓰고, 그 사람 대화는 다른 가입자에게도 관리자(허브 주인)에게도 화면으로는 보이지 않는다. 가입자용 순서는 [가입자 따라 하기](MEMBER_GUIDE.md), 설계는 [MULTI_USER](design/MULTI_USER.md).

- **켜기:** 허브 화면 **설정 → 허브 보안·Codex → 여러 사람**의 "여러 사람 쓰기"(확인 창). 켜면 로그인 화면에 **가입 신청**이 생긴다. 끄면 새 신청만 막히고 승인된 사람은 그대로 쓴다.
- **허브 접속 제한:** 허브가 IP 목록으로 막혀 있으면 다른 사람은 허브에 닿지 못한다. 같이 쓰려면 같은 화면 위쪽 **보안(허브 접속 제한)**에서 열어야 한다(열어도 로그인은 그대로 필요).
- **승인:** 같은 화면 목록에서 신청한 사람의 **승인 / 거절**. 승인된 사람은 **끊기**(바로 로그아웃, 다시 로그인 불가)·**다시 켜기**·**임시 비밀번호**(메일 없는 비밀번호 찾기 — 한 번만 보이고 그 사람 로그인은 끊김)·**지우기**(그 사람의 이어온 대화 기록·방·예약·연결한 PC·앱 연결·메신저 연결을 모두 지움, 그 사람 PC의 원래 세션 기록은 남음).
- **관리자 로그인:** 지금처럼 이메일 칸을 비우고 비밀번호만. 관리자 비밀번호 바꾸기는 **설정 → 밖에서도 쓰기 → 내 비밀번호**(가입자도 같은 칸으로 자기 비밀번호를 바꿈).
- **가입자가 쓰는 것:** 자기 PC 연결(PC 연결 링크), 자기 PC에 새 세션, 작업 폴더, 예약, 앱 연결, 메신저 연결(공용 봇). 자기 PC에서 쓰던 Codex 대화 연결(**＋ 대화 연결**). **못 쓰는 것:** 허브 설정·보안·메신저 봇 설정·계정·세션 등록 표(직접 입력), 허브 엔진 칸, 다른 사람의 PC·대화.
- **공용 메신저 봇:** 가입자는 허브의 텔레그램·디스코드·슬랙·라인 봇을 같이 쓴다(카카오는 아직 안 됨). 가입자가 **설정 → 밖에서도 쓰기 → 메신저 연결**에서 받은 6자리 숫자를 봇에 보내면, 그 메신저 계정에서는 그 사람 대화만 보인다. 연결하지 않은 메신저 계정은 지금처럼(관리자가 허용한 사람 = 관리자 대화). 자세히는 [메신저 설정 설명서](MESSENGER_MANUAL.md) 6.6.
- **앱 받기:** 휴대폰 브라우저에 `<허브 주소>/app`(안드로이드 앱 바로 받기), 또는 **설정 → 내 프로그램 연결 → 앱 받기**(안드로이드·PC). 새 판을 올리면 앱 첫 화면에 "새 판이 있어요 — 받기"가 뜬다.
- **알아 둘 것:** 서버에서 DB 파일을 직접 열면 내용을 볼 수 있다(화면·API로는 못 봄). 다른 사람 PC를 실제로 연결하는 흐름과 공용 봇 연결은 아직 실제 계정으로 확인 전이다(시험 계정·대역 시험으로는 확인).

### 확인 필요 정리

결과를 모르는 질문은 같은 세션을 잠근다(같은 질문이 두 번 실행되는 것을 막기 위해서다). 이어온은 **절대 자동으로 다시 보내지 않는다.**

1. 원래 세션 화면(Desktop·TUI·Claude 터미널)에서 그 질문이 실행됐는지 본다.
2. 웹에서 그 대화를 고르면 "확인이 필요한 질문" 카드와 버튼 두 개가 나온다.
   - **실행됐어요**: 실행된 것으로 닫는다. 받지 못했거나 섞였을 수 있는 답은 저장하지 않는다.
   - **실행되지 않았어요**: 실행 안 된 것으로 닫는다. 필요하면 질문을 직접 다시 보낸다.
3. 정리하면 잠금이 풀린다.

## 6. 꼭 지킬 것

- 동시 사용 모드에서 이어온이 처리 중일 때 TUI에 입력하려면 **Enter가 아니라 Tab(대기열)**을 쓴다. Enter는 진행 중인 이어온 답에 합류해 답을 바꾼다(실측).
- 동시 사용 모드의 대화는 Desktop에서 열지 않는다.
- Claude 채널 지시에 "도구 금지"라고 쓰면 `reply`까지 막혀 답이 이어온으로 오지 않는다. 채널은 "reply 외 도구 금지"로 동작하게 만들어져 있다.
- 이어온에서 온 Codex 질문은 **읽기 전용·승인 없음·네트워크/웹 차단**으로 실행된다. 파일 변경·명령 실행이 필요하면 원래 세션에서 사람이 직접 한다.
- 실제 실행(`-Live`)·로그인·포트·설정 변경은 승인 범위에서만 한다. 토큰·인증 파일을 복사·출력·공유하지 않는다.
- 업무 대화 `01a0dadd-739f-74d2-93c5-9c405cc1019b`는 대상이 아니다.

## 7. 알려진 제한

- 접속은 이 PC, 허용한 Tailscale 기기, 허용한 메신저 사용자(카카오톡은 중계·허브를 거침), 허브 접속 제한을 통과한 곳만 된다. 그 밖의 공개 인터넷 접속은 없다.
- 동시 사용 모드의 사람 화면은 Desktop 창이 아니라 TUI다.
- Claude Code 2.1.314에서는 채널 `reply`가 권한 확인 없이 실행될 수 있다(원인 미확인, `reply`는 채널 답장만 가능).
- 새 세션: Claude 새 세션은 질문마다 `claude -p`로 실행한다(채널·터미널 창이 필요 없음). 사람이 같은 세션을 터미널에서 열어 둔 채 질문하면 결과 불명(`session_forked`)으로 멈춘다.
- 새 세션 `workspace` 권한은 파일 쓰기만 하고 명령 실행·인터넷은 막는다. `full`은 작업 폴더 안에서 명령을 실행할 수 있지만 명령으로 폴더 밖을 건드리는 것까지 운영체제 수준에서 막지는 않는다(Oracle 배포 전 재검토).
- 새 세션 보관 예고는 그 세션에 연결된 메신저 대화방으로 간다. 메신저 봇을 다시 켠 뒤 그 방에서 아직 아무 말도 없었으면 보내지 못한다.
- 텔레그램은 안내 문구 속 `/close`를 링크로 바꾼다. 링크를 누르면 확인 없이 같은 안내가 다시 나온다. 삭제는 `/close <이름> 확인`을 직접 입력해야 한다.
- 새 세션이 "잠듦"이어도 프로세스를 끈 것이 아니라 상태 표시다(질문이 없을 때는 원래 프로세스가 없다).
- Codex 실행마다 "unrecognized configuration setting(`computer_use.windows.always_allowed_app_ids`)" 경고가 하나 뜬다. 실행에는 영향이 없다.
- 규칙 점검 2차(2026-11-18): PC 설정(AI 응답·계정·허용 목록·모드·허브 연결)은 로그인한 웹 화면이면 어디서나 바꾼다. 새 세션의 full 권한 스위치·지울 때 이름 확인·작업 폴더도 지우기는 **설정 → 대화 → 새 세션**에서 바꾸고(덜 안전하게 바꿀 때 확인 창), 웹 로그인 유지 기간은 기본 30일(1~90일, 같은 "기다리는 시간" 칸). 세션·기기 지우기는 이름 입력 대신 확인 창 하나. 허브 주소는 http도 받는다(도메인 없는 서버 설치형 — 화면에 "암호화되지 않음" 경고).
- **알림(2026-11-18):** 웹 화면 왼쪽 아래 🔕 알림 → 브라우저 허용이면 **탭을 닫아도** "○○가 답했어요"가 크롬·엣지 알림으로 온다(이어온 화면을 보고 있으면 안 띄움, 누르면 그 대화). 휴대폰 앱은 Firebase 알림(APP_GUIDE 8-1). 질문·답 원문은 어느 알림에도 넣지 않는다.
- 결과 불명 정리는 사람 확인 방식이다. 원래 세션 기록과 자동 대조하는 기능은 없다. 단, 서버를 다시 켜는 동안 처리 중이던 질문은 PC(연결부)가 엔진의 실제 결과를 보내면 자동으로 정리된다(연결부가 약 5분 동안 다시 보냄. PC형에서 연결부도 함께 꺼진 경우는 그대로 결과 불명).
- Codex 질문 모드(작업 모드 아님): 기존 대화는 읽기 전용 샌드박스에서 파일 읽기·명령을 그대로 하고(쓰기·인터넷은 막힘), 새 세션은 작업 폴더 안에서 명령까지 한다. 샌드박스 밖 도구(MCP 등)는 그 자리에서 멈추고, 멈춘 것·막힌 것은 답 끝에 알린다(대화를 잠그지 않음). 공유 서버 방식에서 도구를 쓰려 하면 그 차례를 끊고 "끊기 전에 시작됐을 수 있음"을 알린다.
- 공유 App Server(`codex app-server --listen`)는 Codex의 실험 기능이며 버전 0.165.0 기준으로 확인했다.

## 8. 개발 작업 절차(참고)

작업 branch는 최신 `origin/main`에서 주체별 접두어로 만든다(Codex `codex/<목적>`, Claude Code `claude/<목적>`). commit·push 후 `pr-request/<branch 최신 sha>/<branch>` 태그(현재 main 가리킴)를 push하면 자동 PR로 병합된다. 병합 확인 → main에서 `node --test tests/pilot/*.test.mjs` → branch·작업 폴더 정리 후 다음 작업. 자세한 규칙은 [AGENTS.md](../AGENTS.md).

## 부록. 개발·문제 해결용 명령

보통은 쓰지 않는다. 설치(`install.ps1`)로 띄운 이어온과 함께 쓰지 말고, 쓰기 전에 `pwsh scripts/install.ps1 -Uninstall`로 자동 시작을 내린다.

```powershell
pwsh scripts/ieon.ps1 start [-Shared] [-Live]   # 서버·연결부를 직접 띄움(개발용)
pwsh scripts/ieon.ps1 status                    # 포트·실제 실행·시험 대화 잠금
pwsh scripts/ieon.ps1 check                     # 설치 점검(모델 호출 없음)
pwsh scripts/ieon.ps1 stop
```
